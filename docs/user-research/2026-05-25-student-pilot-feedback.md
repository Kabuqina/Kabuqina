## 3. 分样本反馈摘要

### 3.1 S1 — 安装与首聊体验

**原文要点：**

- 请求「帮我生成一段代码」后，很快得到 Python 分形渲染代码，并附带运行方式、不同命令的效果说明及调色板提示。
- 安装包双击即可安装，无需复杂设置，无捆绑软件，约十几分钟完成，对电脑小白友好。
- 打开后界面干净，无花哨元素，能一眼找到聊天框。

**可归纳标签：** `#安装体验` `#UI清晰度` `#代码生成` `#新手友好` `#可执行回复`

---

### 3.2 S2 — 课程任务场景深度测试

**测试场景与评价：**

| 场景 | 行为描述 | 学生评价 |
|------|----------|----------|
| 论文写作 | 优化表述、梳理逻辑、格式校验 | 大幅提升课程论文修改效率 |
| 文献阅读 | 上传 PDF，提取核心观点与研究方法 | 快速把握文献重点 |
| Python 课设 | 定位语法错误、给出优化建议 | 辅助理解算法逻辑 |

**整体结论（学生原意）：**

- 精准覆盖学生学习高频需求，功能集成度高、上手难度低，对日常学习与课程任务有明显效率提升。
- 体验过程稳定顺畅，对课程学习有较大帮助；是一款实用性强、适配学生场景的桌面 AI 助手。

**改进建议（书面反馈）：**

1. 复杂 PDF 中**公式识别精度**有待提升。
2. 界面交互的**快捷功能**可进一步完善。

**后续访谈补充（与 S2 口头沟通，优先级高于书面中的「快捷功能」泛化表述）：**

书面里的「快捷功能」在后续交流中进一步具体化为 **PPT 文件生成** 需求，而非泛指聊天区多几个按钮：

| 诉求 | 说明 |
|------|------|
| **专用 PPT 生成功能** | 希望不是「在对话里要一个大纲或 Markdown」，而是能**产出可打开的 `.pptx` 文件**的一整套流程 |
| **完整工作流** | 从输入（主题 / 大纲 / 文献要点 / 课设结论等）到排版、分页、导出，步骤连贯、可预期，少靠用户自己拼装 |
| **学生向 PPT 模板** | 内置或可选**对学生实用**的模板（如课程汇报、文献综述、课设答辩、小组展示等），风格清晰、不过分商务 |

**访谈结论（归纳）：** 当前通用对话 + 文件工具能辅助「写内容」，但**缺「直接交作业用的演示文稿」这一环**；模板 + 工作流是 perceived gap 的核心，而非单纯 UI 快捷键不足。

**可归纳标签：** `#论文润色` `#PDF文献` `#编程辅助` `#稳定性` `#公式识别` `#PPT工作流` `#学生模板`

## 4. 跨样本共性结论

### 4.1 已验证的产品优势

1. **低摩擦上手链**  
   安装简单、无捆绑 → 界面克制、聊天入口明显 → 首次对话即有「能直接用」的正反馈（S1 代码示例 + S2 三类课程场景均有效）。

2. **学生场景匹配度**  
   写作润色、文献理解、编程/debug 三类高频任务均被主动验证，且均获得正向效率评价；与 Kabuqina「PC 上的友好助手、少折腾」定位一致。

3. **回复质量感知**  
   S1 强调「附带运行说明与参数提示」；S2 强调「逻辑梳理、要点提取、错误定位」——用户价值不在「有回答」，而在**可跟进、可落地**。

4. **稳定性**  
   S2 明确提到体验「稳定顺畅」；在内测阶段可作为安装/onboarding/对话链路的正面信号（仍需更多样本与长跑数据支撑）。

### 4.2 待跟进或可优化方向

| 主题 | 来源 | 优先级建议 | 备注 |
|------|------|------------|------|
| **PPT 生成工作流 + 学生模板** | S2（后续访谈） | **高** | 明确为端到端 `.pptx` 产出 + 模板库；与 L1 QuickAction / Recipe 形态最接近；见 §5 |
| PDF / 公式识别 | S2（书面） | 中–高（视课程 PDF 占比） | 可能涉及 vision/file 工具链与模型能力边界；需区分「产品 UX」与「模型/OCR 上限」 |
| 界面快捷功能 | S2（书面，已部分澄清） | 中 → 收敛为 PPT 场景 | 书面表述较泛；访谈后宜按 **「演示文稿一键生成」** 理解，避免与 companion 通用快捷入口混为一谈 |
| 首次对话引导 | S1 隐含 | 低–中 | S1 自发尝试代码生成即成功；可考虑是否对更广泛样本加强示例 prompt / 快捷入口 |

### 4.3 S2 需求层次（书面 vs 访谈）

```text
书面：「快捷功能可完善」
        ↓ 后续访谈
具体：专用 PPT 文件生成（工作流）+ 学生实用模板
```

对产品含义：学生场景里 **「能写」≠「能交」**——论文润色、文献摘要已在对话链路成立；**课程汇报/答辩** 仍依赖 PowerPoint/WPS，用户希望 Kabuqina 补齐最后一步。

## 5. 与产品能力映射（内部参考）

便于研发/产品对照现有架构，**非学生可见内容**：

| 反馈点 | 可能涉及模块 |
|--------|----------------|
| 双击安装、无捆绑 | Tauri MSI、`docs/release-checklist.md` |
| 干净 UI、聊天框明显 | `web/src/` chat/onboarding |
| 代码生成 + 运行说明 | Hermes agent 默认 toolset（`file` 等）、模型回复风格 |
| PDF 上传与分析 | file/vision 工具、附件 UX、`docs/document-tools-plan.md` |
| 论文润色 / 格式 | 纯对话 + 可选 file；无专用「论文模式」——效率来自通用 agent |
| 公式识别不足 | PDF 解析 / vision 模型限制；可记录为已知 limitation |
| PPT 工作流 + 模板 | **当前无专用能力**；可能路径：`python-pptx` / Office COM（Windows）/ L2 Recipe；模板资产放 workspace 或安装包；需 product spec |
| 快捷功能（书面原话） | 访谈后主要收敛为 PPT 场景；其余 companion/workbench QuickActions 仍为一般性体验项 |

## 6. 建议的后续动作（可选）

- **试点设计：** 下轮可固定记录 Provider/模型、是否上传 PDF、任务类型，便于量化「公式识别」类 issue；对 PPT 需求可追问：典型页数、是否必须 `.pptx`、常用 WPS 还是 Microsoft Office。
- **已知限制说明：** 若面向课程推广，可在帮助/onboarding 中简短说明「扫描版/复杂公式 PDF 可能不准」。
- **PPT 功能预研（S2 驱动）：** 在动实现前建议先定最小工作流，例如：`输入主题/粘贴大纲` → `选学生模板（课设答辩 / 文献汇报 / 课程小结）` → `生成 .pptx 到 workspace` → `壳内打开或「在文件夹中显示」`。可评估是否作为 L1 QuickAction 或 L2 Recipe，以及是否允许 agent 调 `file` 工具写 pptx。
- **路线图输入：** 将「PDF 公式」「**PPT 工作流 + 学生模板**」写入 `docs/ROADMAP.md` 时引用本纪要；PPT 项单独成行，不与泛化「快捷交互」合并。
