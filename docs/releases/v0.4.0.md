# Kabuqina v0.4.0

Kabuqina v0.4.0 is a major learning-workspace release for Windows 10/11 x64.

## Important upgrade notice

Users of v0.2.0 or v0.3.0 must download and run the v0.4.0 installer manually
once. The updater signing key used by those versions is no longer recoverable,
so they cannot authenticate an automatic update to v0.4.0.

This manual install starts the replacement updater trust chain. v0.4.0 and
later releases use the new `latest-v2.json` channel. Existing workspaces,
settings, sessions, credentials, and Study data are designed to remain in
place during the in-place install.

## Highlights

- A first-class STUDY notebook with course spaces and dedicated Plan, Learn,
  Practice, and Evaluate flows.
- Reviewable learning drafts, lifecycle controls, source tracking, and local
  persistence that keep model-generated learning content under user control.
- Code and derivation practice with deterministic grading foundations,
  retries, weak-point tracking, and review workflows.
- Bounded long-running goals with desktop controls and safer workspace-scoped
  artifact handling.
- The desktop and owned agent core now use Kabuqina-native runtime names, with
  compatibility migrations for existing local data and Windows credentials.
- The legacy conversation loop has been retired; the graph runtime is now the
  single agent execution path.

## Install or upgrade

1. Download `Kabuqina_0.4.0_x64-setup.exe` from this release.
2. Close Kabuqina if it is running.
3. Run the installer. Existing v0.2.0/v0.3.0 users can install it over the
   current installation; uninstalling first is not required.
4. Start Kabuqina and confirm your workspace, settings, conversations, and
   Study data are present.

Kabuqina stores user data under
`%LOCALAPPDATA%\com.kabuqina.app\`. As with any major upgrade, keeping a backup
of important workspace files is recommended.

## Updater transition

- The retired `latest.json` channel remains frozen.
- v0.4.0 checks the new COS-first, GitHub-fallback `latest-v2.json` channel.
- The first end-to-end proof of the replacement automatic-update chain will be
  an update from v0.4.0 to a later signed version.

If the in-app updater cannot reach or verify an update, the installed version
continues to run.
