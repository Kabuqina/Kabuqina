## 1. 一句话模型

> **课程目录决定学习范围，知识核决定眼前这一件事；学习与练习共享同一个知识核游标，阅读器提供完整来源，继续书签投影当前可恢复现场。**

五页不是五个互不相干的内容容器，也不是必须顺序完成的向导。它们是同一本课程本的五种工作面：

```text
扉页：这门课按什么目标和约束来学
  ↓
计划：当前在哪一段范围内、接下来做什么
  ↓
学习：围绕一个知识核理解、重构、对照
  ⇄
练习：围绕同一个知识核运用、检查、修改
  ↓
评估：证据说明哪里需要调整，并返回具体来源
  └──────────────→ 计划 / 学习 / 练习
```

## 2. 核心领域对象与尺度

### 2.1 三种尺度必须分开

```text
课程目录（宏观）
  └─ 当前计划范围：章 / 节 / 学习单元，最多三级
       └─ 计划行动：理解、练习、回访，不属于第四级目录
            └─ 知识核序列（微观，不在计划页逐项铺开）
                 ├─ 学习模式
                 └─ 练习模式
```

| 概念 | 回答的问题 | 默认出现位置 | 不是什么 |
|---|---|---|---|
| 目录节点 | 这部分在真实材料的哪里？ | 计划页、阅读器目录 | 学习进度条 |
| 计划项 | 这一段接下来做什么？ | 当前目录节点展开区 | 第四级目录 |
| 知识核 | 眼前只需要弄懂哪一件事？ | 学习页、练习页 | 计划目录节点 |
| 练习题 | 如何验证当前知识核？ | 练习页 | 独立于知识核的随机题 |
| 继续书签 | 上次正在做什么、如何精确恢复？ | 笔记本页眉 | 用户固定收藏 |
| 阅读器 | 完整资料和上下文是什么？ | 右侧书堆打开的侧板 | 学习页主体 |

### 2.2 知识核是共享游标

每门课程在当前学习范围内有一个有序知识核序列。Study 只维护一个共享的
`activeKnowledgeCoreId`，不得为学习页和练习页分别维护两个不相关的游标。

```ts
type StudyPage = "flyleaf" | "plan" | "learn" | "practice" | "evaluate";

type StudyLocation = {
  courseId: string;
  page: StudyPage;
  outlineNodeId?: string;
  planItemId?: string;
  knowledgeCoreId?: string;
  exerciseId?: string;
};
```

`knowledgeCoreId` 是内部稳定标识。普通界面不显示“K1”“知识核 ID”等工程语言，而使用
“这一步要弄懂的”和具体内容标题。

### 2.3 学习和练习是同一对象的两种模式

```text
Learn(core=K2)    → 切到练习 → Practice(core=K2)
Practice(core=K2) → 回到学习 → Learn(core=K2)
```

切换页面只改变模式，不改变知识核。前后推进知识核只改变知识核，不改变当前模式：

| 当前操作 | 必须得到的结果 |
|---|---|
| 学习 K2 → 下一知识核 | 学习 K3 |
| 学习 K2 → 上一知识核 | 学习 K1 |
| 学习 K2 → 去练习 | 练习 K2 |
| 练习 K2 → 下一知识核 | 练习 K3 |
| 练习 K2 → 上一知识核 | 练习 K1 |
| 练习 K2 → 回学习 | 学习 K2 |

## 3. 全局不变量

以下规则跨五页成立，任何单页实现不得自行放宽：

1. **一页一个主任务。**默认只呈现 P0 当前任务和 P1 必要上下文。
2. **学习、练习一次只呈现一个知识核。**不得默认铺开知识核列表或资源列表。
3. **共享知识核游标。**学习和练习切换时知识核不变。
4. **阅读不等于学习证据。**打开材料、滚动、停留、看过目录都不产生掌握证据。
5. **系统拟定不等于生效。**计划、学习设定、知识库、资源包、辅导笔记等按既有信任合同审核；不得因渲染出来就视为课程真值。
6. **练习行为才产生可检验的证据。**计划完成是活动，不能单独证明掌握；评估只能引用有来源的证据。
7. **来源可追溯。**目录来自真实文件结构；知识核、练习和评估能回到来源。
8. **不展示覆盖率、连续天数、达标徽章或固定能力标签。**目录状态不能把“走过”伪装成“学会”。
9. **Study 不提供向 Studio 推送的出口。**Studio 取材由 Studio 发起。
10. **恢复优先于猜测。**目标失效时降级到正确课程和目录节点，不跳到另一个知识核或课程。
11. **同一事实只在一个主要位置表达。**五页标签已经表达页面身份，正文不再重复一个巨大的“学习/练习/评估”标题。
12. **内容可滚动。**笔记本正文承担垂直滚动，分页、关键动作和关闭阅读器入口在可达范围内；不得让内容从窗口下部不可达。
13. **五页 Prompt 不同。**“问小娜”共用入口和会话 UI，但必须按来源页使用不同上下文与协作边界，详见独立 Prompt 合同。

## 4. 五页标签与笔记本导航

### 4.1 标签层级

扉页、计划、学习、练习、评估是同一级的笔记本分页。标签本身承担页面标题功能：

- 标签使用足够明确的字号和选中状态；
- 正文第一标题应是当前对象，例如课程目标、当前目录节点、当前知识核、当前题目、最近评估结论；
- 不在标签下再次显示只写着“扉页”“计划”“学习”“练习”“评估”的大标题；
- 五页不是完成后解锁的向导，已存在的数据允许直接访问。

### 4.2 切页规则

- 从学习切到练习：保持知识核，恢复该知识核最近题目或进入推荐第一题；
- 从练习切到学习：保持知识核，恢复该知识核的学习草稿与对照状态；
- 从学习/练习切到扉页、计划或评估：保留知识核游标，以便返回；
- 练习有未检查修改时，切换到其他五页必须触发离页保护；
- 打开 Chat 或阅读器不属于离开当前工作面，必须保留当前位置与草稿；
- 切换课程前先保存当前课程的继续状态，再恢复目标课程自己的继续状态。

## 5. 计划页与三级目录

### 5.1 页面职责

计划页回答：**当前在哪一段真实材料中学习，接下来做什么？**

它由两部分组成：

1. 有来源的课程目录；
2. 当前目录节点就地展开的行动队列。

计划页不负责逐项展示知识核，也不负责呈现完整资料正文。
当前行动只在行动队列中原位标记“正在进行”；列表上方不再另放复述阶段名的
“下一行动”摘要卡。

没有计划时，`+ 学习计划` 先读取知识源文件：一份文件直接生成草稿，两份或以上先让用户
选择一份；一次计划生成只使用被选文件。草稿必须等正式计划真值确认后才能显示，采用期间不得
闪回草稿或无计划空态，采用成功后同一位置只展示正式计划。

### 5.2 目录最多三级

产品层只允许：

```text
第一级：章
第二级：节
第三级：小节 / 学习单元
```

课程本身和文件名是目录上下文，不算目录层级；挂在当前节点下的计划行动也不算第四级。

当原始文件目录超过三级时：

- 完整原始层级保留在阅读器；
- 计划页将更深后代压平到第三级列表，显示足以辨认的标题和来源路径；
- 不发明原文件不存在的父子关系；
- 不为追求三级而丢失来源 ID 或页码；
- 同一显示节点可以映射一段真实来源范围，但必须可核对。

### 5.3 目录来源与多材料

- 有可靠目录或标题层级时，骨架来自一份真实材料抽取出的结构，不由模型改写；
- 其他讲义、习题集、真题和参考资料通过可审核挂靠连接到骨架；
- 计划顺序可以不同于教材顺序，但不重排真实目录；
- 未对齐材料留在书堆中明确可见，不强行挂靠；
- 目录节点可以显示“在学、练过、有错题”等重构痕迹，但不显示已读、百分比或覆盖率。

**没有可靠目录时，Agent 做二次编目，但不能伪造原书目录：**

1. 导入结果先明确保存 `structureStatus = missing | weak`，不能把前 12 页或一段正文冒充目录；
2. Agent 读取封面/前言、疑似标题页，并在全书前中后均匀抽样；必要时按页继续展开；
3. Agent 只能根据可定位的标题、主题转折和页段提出最多三级的“建议学习结构”，每个节点都必须
   带原文件 `sourceRef + locator/pageRange` 和提名理由；不能产生没有页段证据的章节；
4. 建议在计划页标为“小娜整理的目录（待确认）”，允许用户改名、合并、拆分、调整顺序或拒绝；
5. 用户确认后写成 `origin = inferred_confirmed` 的学习目录。它可以驱动计划、知识核和练习，
   但阅读器仍显示原文件没有目录，不把学习目录称为“原书目录”；
6. 后续按页阅读发现新结构时，只产生带 base revision 的修订草稿，不静默修改已确认目录。

因此，“目录来自真实材料”指每个节点都有可核对的材料位置；不要求原文件必须自带目录页，
也不允许 Agent 仅凭常识生成一套看似合理但无法回到原文的课程大纲。

### 5.4 计划项不是知识核

计划项绑定一个目录范围和动作类型，例如：

```text
2.3 极限的运算法则
  · 理解未定式的含义
  · 完成本节基础练习 1–6
  · 回访本节错题
```

一个计划项可以覆盖多个知识核。启动计划项时：

1. 有该项未完成继续状态：恢复精确知识核；
2. 没有继续状态：进入该范围内第一个推荐知识核；
3. 计划项明确是练习/错题回访：进入练习模式；
4. 其他理解型行动：默认进入学习模式；
5. 不把知识核列表展开到计划页让用户手工挑微步骤。

### 5.5 完成与跳过

- `完成` 表示这项行动已做完，记录活动，但不能单独证明知识掌握；
- `跳过` 表示主动调整，不计为完成，也不是失败；
- 完成当前项后不得擅自启动下一项；
- 用户开始下一项时，继续书签才切换到新的计划范围；
- 没有 active plan 时显示诚实空态，不伪造默认计划。

## 6. 学习页：单个知识核的重构循环

### 6.1 页面职责

学习页回答：**对于眼前这一件事，我能否形成自己的理解？**

默认工作面只呈现一个知识核：

1. 一句最关键的内容；
2. 它来自哪里；
3. 一个促使学习者用自己的话表达的问题；
4. 学习者自己的草稿；
5. 按需出现的教材说法对照；
6. 上一知识核、下一知识核和“去练习”的动作。

### 6.2 主循环

```text
知识核
  → 我的想法
  → 和教材对一下
  → 只对照，不判分
  → 去同一知识核的练习中验证
```

行为规则：

- 输入区允许不完整表达，明确“不评分”；
- 小娜不得替换、润色或自动补全学习者的话；
- 用户可以先看教材说法，此时“我的想法”保持空白，不用劝说文案填充；
- 对照区并排显示教材说法和学习者说法，双方有同等视觉分量；
- 对照只提供差异提示或观察角度，不产生正确/错误判定；
- “去练习”必须带着当前 `knowledgeCoreId`；
- 上一/下一知识核保持在学习模式，并保存每个知识核自己的草稿和对照阶段。

### 6.3 学习页明确不放什么

默认工作面不铺开：

- 多知识点列表；
- 完整知识库；
- 资源包列表；
- 辅导笔记列表；
- 完整教材正文；
- 学习历史；
- 总体掌握度。

这些对象可以作为知识核和来源的底层输入。需要用户审核的草稿从草稿箱/进行中进入专门审核面；
审核完成后再影响课程内容，不在学习页旁边常驻一列待办。

### 6.4 无知识核与失效状态

- 当前目录范围尚无知识核：说明需要先整理该节，不自动跳到别节；
- 当前知识核被删除：回到同一目录节点的最近有效知识核；没有则回计划页当前节点；
- 来源暂不可用：知识核仍可显示，但明确来源暂不可打开；
- 保存失败：保留输入框内草稿并允许重试，不以空白覆盖。

## 7. 练习页：同一知识核的验证循环

### 7.1 页面职责

练习页回答：**我能否运用当前知识核，并根据反馈修正？**

默认只呈现：

- 当前知识核的必要上下文；
- 当前一道题；
- “答到这些就够了”的完成要求；
- 我的答案；
- 检查动作；
- 检查后的定位反馈和修改动作；
- 同知识核下的题目移动，以及知识核前后移动；
- “回学习”动作。

### 7.2 两个游标

练习可能在一个知识核下有多道题，因此允许两个不同尺度的内部游标：

```ts
type PracticeLocation = {
  knowledgeCoreId: string; // 与学习页共享
  exerciseId?: string;     // 练习页内部
};
```

- 上一题/下一题只改变 `exerciseId`，不改变知识核；
- 上一知识核/下一知识核改变 `knowledgeCoreId`，并恢复目标知识核最近题目或推荐第一题；
- 回学习时忽略题目层，保持 `knowledgeCoreId`；
- 再次回练习时恢复该知识核上次的 `exerciseId`、答案草稿和反馈状态。

### 7.3 题目来源、选择与激活

练习不默认等同于“小娜出题”。新进入一个知识核时，题目按以下顺序选择：

1. 当前知识核对应页段中的教材习题、习题集、讲义题或真题；
2. 基于同一知识核和可定位来源缩小、拆分或改编的题目；
3. 材料中没有合适题目时，由小娜根据当前知识核、来源摘录和完成要求生成补充题。

错题回访时顺序不同：当前知识核下上次做错、未完成或仍在修改的题目优先；没有可回访现场时，
再依次使用资料原题、资料改编题和小娜生成题。不得为了凑题跳到另一个知识核。

```ts
type ExerciseOrigin = "source" | "adapted" | "generated" | "mistake_revisit";

type KnowledgeCoreExercise = {
  exerciseId: string;
  knowledgeCoreId: string;
  origin: ExerciseOrigin;
  sourceRefs: SourceRef[];
  prompt: string;
  completionRequirement: string;
  rubric: string;
  status: "draft" | "active";
};
```

- `source` 必须能回到真实材料位置，并显示“资料原题”和材料/章节/页码；
- `adapted` 必须保留原题或来源页段引用，明确显示“根据资料改编”，不能冒充原题；
- `generated` 必须显示“小娜生成”，只允许在当前知识核范围内补位；
- `mistake_revisit` 指向同一题的既有作答现场，不复制出一份失去答案和反馈历史的新题；
- 资料原题只有在题干抽取可靠、知识核映射明确且检查要求可用时才能直接成为 `active`；
- OCR 不可靠、来源映射不确定、资料改编和小娜生成的题目先成为 `draft`，用户点击“采用并开始”
  后才激活；采用动作可以与首次开始作答合并，不另建管理后台；
- 小娜可以为资料题补充检查标准，但若依据不足必须降低检查结论强度，不能伪造标准答案或页码；
- 不把答案、解析或 rubric 泄漏到作答面；题目去重至少覆盖同一知识核下的来源位置和题干指纹。

### 7.4 作答、检查与反馈

- 答案草稿自动保存；保存不等于提交或正确；
- 练习正文按“题目（页面主标题）→ 我的答案”排列，不展示“完成标准”或其他考核式说明，也不再额外显示一条复述题意的大标题；
- `检查这一步` 是当前主动作；
- 检查后“小娜批注”每次只显示一种判断：`已经说明清楚`、`还差一步`、`接下来试试`；
  由检查结果选择当前最有用的一种，不把三段模板同时堆到页面上；
- 待修改状态下答案仍可编辑，`保存答案` 只保存当前草稿；保存后由用户再次点击 `检查这一步`，
  不把保存冒充为提交或正确；
- 答案区只显示 `我的答案`，不再另贴 `我的草稿` 等重复状态文案；保存状态由答案下方的状态行承担；
- 答案区不再另设“小娜陪我补这一步”按钮；需要求助时统一从书桌右侧的 `碰杯问小娜` 进入；
- 练习页的折叠入口叫 `提示`，展开后只显示一条最短线索；不显示题目摘要、解题说明、答案或 rubric；
- 修改答案后再次检查，形成同一题的迭代，不创建第二份互不关联的现场；
- 真实作答、检查、卡片复习等行为可以产生有来源的学习证据；
- 失败或超时状态保留用户输入，不把后端 detail 原样展示给学生。

### 7.5 Chat 与精确返回

从练习页问小娜时，课程 Chat 至少携带：

- Course；
- 目录节点；
- `knowledgeCoreId`；
- `exerciseId`；
- 当前答案版本；
- 已有反馈定位；
- 可用的来源引用。

从 Chat 返回必须恢复同一题、同一答案、同一反馈状态与合理焦点。Chat 给出的建议不得直接改写答案。

其余四页同样需要页面专用 Prompt、结构化上下文和精确返回，不得复用练习页的“当前题目”模板；
完整合同见 [Study 五页「问小娜」Prompt 合同](2026-07-29-v0.5.0-study-five-page-nana-prompt-contract.md)。

### 7.6 无练习状态

当前知识核没有练习时：

- 留在该知识核，不偷换到其他知识核；
- 说明“这一步还没有可用练习”；
- 主动作使用“准备练习”，按资料原题 → 资料改编 → 小娜生成的既定顺序查找或生产题目；
- 可靠资料原题可以按 7.3 的合同直接成为 active；映射不确定的原题、资料改编题和小娜生成题
  先成为待审核草稿；
- “问小娜”只作为解释来源不足、处理异常或主动重整的次动作，不代替“准备练习”入口；
- 可以提供返回学习的次动作；
- 草稿未激活前不能作答、检查或形成证据。

## 8. 扉页：课程级学习合同

### 8.1 页面职责

扉页回答：**这门课按什么目标、偏好、时间和约束来学？**

- 扉页内容归用户所有，用户可以直接填写和修改；
- 小娜可以根据用户明确提供的课程目标和对话上下文协助起草，但不是唯一入口，也不是内容所有者；
- 无论由用户直接填写、小娜起草，还是双方共同修改，内容都先进入同一份可编辑草稿；
- 用户明确“就按这个来”后，草稿才成为当前 active student state；
- 放弃草稿不改变已有 active 状态；
- 草稿与已确认内容使用同一组字段，避免误以为确认会改结构；
- 用户文案说“目标、偏好、时间/约束”，不显示内部 artifact 名称。

### 8.2 内容来源与编辑合同

扉页不是“小娜生成结果展示页”，而是**用户可编辑的课程级学习合同**。

| 场景 | 必须行为 |
|---|---|
| 第一次打开，尚无内容 | 直接显示空白可编辑字段，同时提供“请小娜帮我拟一版”的次级入口 |
| 用户自己填写 | 自动保存为草稿；用户确认后生效 |
| 小娜协助起草 | 生成一份可编辑草稿，明确标为“小娜拟的”；用户可逐字段修改后再确认 |
| 已有正式设定 | 默认显示“我确认过的”；用户点“修改”后，以当前正式设定为底稿开始新草稿 |
| 已有未确认编辑时再次请小娜起草 | 不得静默覆盖；先让用户选择保留当前内容或采用建议 |
| 用户放弃修改 | 丢弃本次草稿，继续使用原 active 状态 |

可见字段保持精简：

1. **目标：**这门课希望学会什么；
2. **偏好：**更适合怎样理解和练习；
3. **可投入时间与约束：**节奏、时间和明确限制。

课程名称是课程容器身份，默认只读，不与学习合同字段混写。打开扉页、导入资料或创建课程时，
小娜不得在没有用户动作的情况下自动生成并激活学习设定。

### 8.3 扉页不承担的内容

- 当前计划阶段；
- 下一调整；
- weak points；
- 评估结论；
- 最近活动；
- 当前知识核和练习进度。

这些信息属于计划、评估、进行中或学习/练习现场。

## 9. 评估页：有来源的诊断与回访

### 9.1 页面职责

评估页回答：**最近可靠证据说明了什么，下一步调整什么？**

默认呈现：

- 有边界的最近评估结论；
- 建议下一步；
- 需要回访的错题或知识核；
- 返回具体来源的动作。

### 9.2 证据和返回

- 每条评估结论必须能追溯到练习、复习或其他允许的 evidence ref；
- “再做一次”进入对应 `knowledgeCoreId + exerciseId`；
- “回学习”进入对应 `knowledgeCoreId`；
- 来源题目失效时降级到同一知识核；知识核失效时降级到同一目录节点；
- 评估建议可以成为下一次计划输入，但不能未经审核直接改写 active plan。

### 9.3 评估页明确不放什么

- Activity 时间线或完整历史日志；
- 无来源的总体评价；
- 固定能力、人格或学习风格标签；
- 覆盖率、连续天数、完成徽章；
- 与当前调整无关的全部证据明细。

## 10. 右侧书堆与材料阅读器

### 10.1 角色

学习页只呈现提炼后的一个知识核；完整资料由右侧书堆/书立打开阅读器。阅读器是辅助上下文层，
不是第六个 Study 页面，也不替代计划目录。

### 10.2 行为合同

- 点击书脊打开完整文件；
- 从目录、知识核或来源打开时，跳到对应章节/页码；
- 文件自己的完整目录始终可访问，目录折行，超过约三行时在目录区域内部滚动；
- 阅读器从右侧展开，笔记本仍在旁边可见和可操作；
- 窄窗仍保留“旁边”的关系，不改成独立全屏页面；
- 阅读器正文独立滚动，不让整个应用横向溢出；
- 阅读器是纯阅读面，不放“完成阅读”“记下来”“高亮库”“挂到某条”等结账动作；
- 打开、滚动、关闭阅读器不改变知识核、学习/练习模式、题目和继续书签；
- 可以单独记住每份文件的阅读位置，但该位置不取代课程继续状态；
- 删除知识源只在阅读器标题栏提供一个极简入口，书堆目录不重复提供“移出/删除”；
- 删除采用软删除：`resource_pack` 从 `active` 变为明确的 `deleted` 墓碑，电脑上的原文件不删除；
- 删除不级联。已经生成的计划、知识核、学习内容、练习、评估和活动记录全部保留，原有来源 ID 也保留；
  以后解析这条来源关系时返回 `deleted`，不得返回 `null` 或把历史来源清空；
- `deleted` 来源不再出现在知识源列表，也不能继续用于阅读或生成新的学习内容。

## 11. 继续书签：动态状态投影

### 11.1 定义

原型中的“书签”不是用户钉死在某页的固定收藏，而是：

> **每门课程当前可恢复学习现场的动态摘要和继续入口。**

它对用户是状态说明；对系统包含会随学习推进而更新的精确游标。

### 11.2 与计划目录的关系

书签必须能回到一个真实目录范围，并可以关联触发它的计划项：

```ts
type StudyContinueState = {
  courseId: string;
  outlineNodeId: string;
  planItemId?: string;
  page: "plan" | "learn" | "practice";
  knowledgeCoreId?: string;
  exerciseId?: string;
  answerDraftId?: string;
  feedbackState?: string;
  updatedAt: string;
};
```

- `outlineNodeId` 提供用户能理解的宏观位置；
- `planItemId` 说明由哪项行动进入，允许为空；
- `knowledgeCoreId/exerciseId` 用于精确恢复，不直接以内部编号展示。

### 11.3 可见形态

书签视觉内容保持极简：尚未开始具体学习时只显示书签图标和 `开始`，存在可恢复现场时只显示
书签图标和 `继续`。行动标题、阶段名、来源范围、模式和系统编号都不在书签表面重复展示；
精确目标保留在无障碍名称与内部游标中。

书签是笔记本页眉中的固定物理元素，不随数据状态增删。没有关联到计划项、知识核或题目时，
保留同样位置与尺寸的空白书签，不显示文字、图标或点击行为；有可靠关联后才在原位显示内容
并成为入口。不得用当前页面上碰巧出现的标题猜测或补造书签内容。

正式计划已经采用、但用户尚未进入知识核时，书签表面显示：

```text
[书签图标] 开始
```

这时点击书签回到对应计划项，不显示“继续”，也不伪造学习进度。开始具体行动后，同一位置
原位变为 `[书签图标] 继续`，不同时展示两张书签。

### 11.4 创建与更新

v0.5 每门课程最多一个自动继续书签，不提供“创建书签”“删除书签”或书签管理页。

建立入口：

1. 正式计划采用后，以首个 open item 建立“从这里开始”入口；
2. 在计划项点击“学习/练习”后，原位升级为可恢复现场；
3. 没有计划项时，用户第一次进入一个有效知识核；
4. 从评估/错题来源进入一个可恢复学习现场。

自动更新点：

- 前后切换知识核；
- 学习与练习切换；
- 练习切换题目；
- 答案草稿安全保存；
- 检查完成或修改状态变化；
- 从 Chat 精确返回；
- 用户显式开始另一个计划项。

不更新书签的动作：

- 打开/滚动/关闭阅读器；
- 打开设置；
- 查看计划或评估但未进入具体学习现场；
- 普通历史浏览；
- 系统后台生成尚未审核的草稿。

### 11.5 完成、失效与降级

- 完成计划项：保留最后现场，但不自动把书签移到下一项；
- 开始下一项：更新到下一项；
- 题目失效：降级到同一知识核的练习入口；
- 知识核失效：降级到同一目录节点；
- 目录节点失效：降级到正确课程计划页；
- 课程删除：移除该课程继续状态；
- 任何降级都不得跳到另一个课程，也不得丢弃仍有效的答案或证据。

如果未来要支持用户固定保存多个位置，该功能应另称“收藏/标记”，不得复用继续书签的状态语义。

## 13. 学习活动、证据与状态边界

| 行为 | 可记录活动 | 可作为掌握证据 | 是否移动继续状态 |
|---|---:|---:|---:|
| 打开目录/材料 | 可选、默认不展示 | 否 | 否 |
| 滚动或阅读材料 | 否 | 否 | 否 |
| 写“我的想法” | 保存工作草稿 | 不能单独作为掌握证据 | 是 |
| 与教材对照 | 可保存阶段 | 否 | 是 |
| 完成计划项 | 是 | 不能单独证明掌握 | 仅保持/结束当前项 |
| 跳过计划项 | 是 | 否 | 不自动跳下一项 |
| 提交并检查练习 | 是 | 是，有来源 | 是 |
| 修改后再次检查 | 是，同题迭代 | 是，有版本关系 | 是 |
| 复习卡片并给出回忆结果 | 是 | 是，按现有契约 | 可更新到对应知识核 |
| 查看评估 | 可选、默认不展示 | 否 | 否 |

评估只消费有来源、允许进入 Learning Index 的 bounded evidence。页面不得因为后端存在字段就全部渲染。

## 14. 加载、空态、错误与部分可用

五页都必须覆盖：首次 loading、refreshing、empty、error、target-invalid、retained content、
mutation pending 和部分可用。
各页的具体空态、主动作、处理中与失效优先级以
[Study 五页空置状态合同](2026-07-31-v0.5.0-study-five-page-empty-state-contract.md) 为准。

共同规则：

- 切课程或快速切知识核时，旧响应不得覆盖新位置；
- refresh 失败时保留仍可信的旧内容并标明可重试；
- mutation pending 只锁相关动作，不冻结整本笔记本；
- 后端能力缺席时显示诚实降级，不填 mock/demo 数据；
- 错误提示不显示内部对象名、owner、space id、artifact id 或后端 detail；
- 窄窗和 200% zoom 下主任务、主动作、分页与滚动区域仍可达；
- 未保存或未检查内容必须有安全反馈，不能为了极简而隐藏。

## 16. 前端实施切片建议

现有 integration plan 的 S3 只完成了共同书桌和五页容器。后续应按行为合同继续拆分：

| 切片 | 目标 | 关键验收 |
|---|---|---|
| S3A | 共用书桌、课程本和五页标签 | 已完成；只代表容器完成 |
| S3B | Study location / knowledge-core / continue-state 领域模型 | K-01–K-06、B-01–B-06 |
| S3C | 三级目录与计划行动 | P-01–P-06 |
| S3D | 单知识核学习重构循环 | L-01–L-05 |
| S3E | 同知识核练习、题目来源、题目游标、反馈和 Chat 返回 | R-01–R-10 |
| S3F | 用户可编辑的扉页学习合同与评估回访 | F-01–F-06、E-01–E-03 |
| S9-Study | 右侧材料阅读器与知识核定位 | M-01–M-03 |
| S3G | 跨页、跨课程、恢复、窄窗与错误态 QA | G-01–G-05 + 全部旅程 |

实施顺序不能再次以“页面已经有组件”为完成标准。每个切片必须提供：

1. 产品状态图；
2. 现有后端能力映射和缺口；
3. loading/empty/error、target-invalid、retained content 与异步动作状态；
4. 组件测试；
5. 跨页集成测试；
6. 720×520 与宽屏视觉验收；
7. 本文对应验收编号的完成记录。

## 17. 非目标与待后续能力

本轮不因为书签隐喻顺手加入：

- 多书签管理；
- 用户固定收藏位置；
- 高亮、划线和摘录库；
- 全课程知识地图；
- 覆盖率或掌握度仪表盘；
- 自动替用户生成“我的想法”；
- Study 向 Studio 推送内容。

若未来需要多位置固定保存，应独立定义“收藏/标记”对象；若未来实现知识地图，应从有来源的目录
和评估诊断生长，不能与当前目录、知识核游标或继续书签混成同一个对象。

## 18. 最终验收句

> **用户在任何时刻都能知道自己正在学习哪一个知识核、是在理解还是练习、如何查看完整来源、如何回到上次现场；计划保持宏观而不细碎，系统保持精确而不把内部游标暴露给用户。**
