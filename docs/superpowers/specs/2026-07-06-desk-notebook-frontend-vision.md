## 0. 设计法则：隐喻必须是结构性的

拟物化作为**装饰**已经死了（iOS 6 皮革）；作为**结构**活得很好（Notion
页面、Figma 画布、OneNote 笔记本）。区别：活下来的隐喻改变了"什么操作
是自然的"，死掉的只换了皮。

因此选择场景隐喻的唯一标准：**它的物理规则是否与四铁律同构**。且
**隐喻不许撒谎**——每个场景元素必须映射真实的持久状态（learning.db），
没有数据支撑的元素宁可不画。

## 1. 三个候选隐喻的判词

| 隐喻 | 物理规则 | 与铁律的关系 | 判词 |
|------|---------|-------------|------|
| 书 | 作者写、读者读、线性翻页 | 把学习者放回消费者位置，违反铁律二 | 不做主界面；作为课程材料/知识库/示范的**局部呈现形态** |
| 笔记本 | 学习者拥有；别人只能写页边小字；可积累、可回翻、允许乱 | 页边注=她的物理形态（不喧宾夺主被空间强制执行）；回翻=铁律四 | **主舞台** |
| 白板 | 共享、即时、双方都能拿笔；擦了就没 | 递笔=LG2 interrupt；但"擦了就没"违反铁律四 | 不是界面，是**从笔记本进入的一节课**；下课快照贴回笔记本 |

## 2. 综合：书桌场景

书桌是容器隐喻，收编全部候选：

```text
┌─────────────────────────── 书桌 ────────────────────────────┐
│  [桌角书堆]      ┌──── 摊开的笔记本（主舞台）────┐   [卡片盒] │
│  课程材料/       │ 分页: 设置|计划|学习|练习|评估 │   到期复习  │
│  知识库(READ)    │ 正文: 学习者的内容            │   队列      │
│                  │ 页边: 小娜的旁注/知识点        │            │
│                  └──────────────────────────────┘   [☕小娜]  │
│         （站起来 → 白板课：推导/画图/你来试，tutor loop）      │
└─────────────────────────────────────────────────────────────┘
```

- **一本笔记本 = 一门课**（learning_space）。换课就是换本子。
- **小娜是桌上那杯卡布奇娜。** 品牌资产（CompanionCup、产品名）早已
  埋好这个本体：她在桌上陪着，冒热气；你需要时她说话，不需要时她只是
  安静地在——"陪伴但不代替"的视觉表达。对话入口即是这只杯子。
- **错题本**是笔记本里的保留页：M4 的 weak_points 投影 + quiz.attempt
  证据链，自动维护的中国学生最熟悉的学习实践。文化锚点，优先做。

## 4. 护栏

1. **隐喻停在布局与交互层，渲染克制。** 纸质感可以；3D 翻页、做旧
   皮革、重度光影不要。现有 kq-glass 柔和视觉就是正确的底子。
2. **场景只管学习循环，chrome 还是 chrome。** 设置、模型配置、能力包、
   导出绝不藏进"抽屉"。REPORT 发射台不进场景——该快的时候快，
   发射台就该长得像发射台。
3. **聊天永远是逃生门。** 任何场景状态下都能直接和小娜说话；场景坏了
   不能把产品一起带走。
4. **可及性与小窗口。** 场景必须能降级为普通布局（窄窗、缩放、读屏）；
   隐喻是增强不是依赖。
5. **性能。** Tauri webview 内避免重 canvas；白板课模式再引入绘图层。

## 5. 分期：信息架构先行，场景皮肤后上

最贵的美术投资必须花在已被使用验证的结构上。

### v0.4.0 — 笔记本作为信息架构（不画桌子）

- STUDY 按 M6 生命周期重组为**分页标签**（设置/计划/学习/练习/评估），
  用现有视觉语言渲染；
- 错题本、卡片盒成为真实入口（吃 M4 数据）；
- 数学与代码的练习面（临摹/变式）挂在"练习"分页下；
- 页边注形态试点：kq-kp 知识点与小娜的短旁注在视觉上向"页边"靠拢。

验证问题：学习者是否按生命周期走？错题本回访率？——遥测已有基线（H5）。

### v0.5.0 — 书桌场景 + 白板课

- 铺开书桌场景（B3 三区的最终形态：书堆/笔记本/卡片盒/咖啡杯）；
- 白板课模式：从笔记本发起一节课，tutor loop 驱动（前提：soak 结束、
  G2 门开、LG1/LG2 契约定型、M4 数据就绪）；下课白板快照贴回笔记本；
- 咖啡杯吸收 CompanionWindow 的能力，成为场景内的小娜本体。

### 各期动工前

另出实施设计稿（组件拆分、路由、降级布局、美术规格）；本文只锁方向
与映射约束。

## 6. 明确不做

- 不做装饰性拟物（皮革、3D 书页、逼真木纹）。
- 不把 REPORT/chrome 塞进场景。
- 不为场景发明没有数据支撑的元素（§3 撒谎检查表）。
- 不在 v0.4.0 画场景皮肤——先验证信息架构。
- 不强制线性闯关：分页可自由跳转，场景是脚手架不是关卡。

## 7. 技术选型

**总原则：不换栈，不引擎化。** 现有 Tauri 2 + React 19 + Vite +
Tailwind 4 就是底盘；场景是"布景"不是"游戏"。确定性的部分（DOM、
CSS、已有栈）承重，昂贵的部分（新依赖）只在被验证的点上花——
good quality, nearly free 的前端版。

| 能力 | 选型 | 何时进依赖 | 理由 |
|------|------|-----------|------|
| 场景 / 纸质感 / 降级 | DOM + Tailwind + 克制的 CSS 3D + SVG `feTurbulence` 噪点 + container queries | 已有 | 文本渲染、无障碍、i18n、选中复制全部免费；**不下载位图纹理**（护栏① + MSI 体积红线） |
| 转场 / 微动效 | View Transitions API（WebView2 可用）+ `motion` | v0.4.0 | 翻页/分页/白板课进出用原生转场；元素级微动效用 motion（tree-shakable） |
| 分页 / 错题本 / 卡片盒 | 现有 React 栈 | v0.4.0（零新依赖） | 信息架构期不加皮肤 |
| 白板 | **Excalidraw**（MIT，React 嵌入，懒加载） | v0.5.0 | 手绘风匹配气质；JSON+PNG 序列化 = "下课快照贴回笔记本"免费；程序化元素 API 让小娜能画图。不选 tldraw（许可证水印/付费）、不自研（工作量黑洞） |
| 推导板 | DOM + KaTeX（已有） | v0.4.0 契约落地后 | **推导不进自由白板**——Excalidraw 不渲染 LaTeX；推导板是并列的结构化表面（一步一行、挖空补理由，承接练习契约的 `derivation` 题型） |
| 代码练习面 | **CodeMirror 6**（MIT，模块化） | v0.4.0 | 不选 Monaco（数 MB）；CM6 的 decoration API 正好做临摹的逐字符比对高亮 |
| 笔记本正文 | 现有 react-markdown + KaTeX | 已有 | 富文本编辑器是最重的依赖类型；只有"页边批注要求所见即所得"被验证后才考虑 Tiptap |
| 咖啡杯 | 品牌 SVG（CompanionCup）+ CSS/motion | v0.4.0 起渐进 | 热气 = 几条 path 循环形变；idle/说话/提醒三态。Rive（状态机角色动画）观望，v0.5 之后再评 |

**加载纪律：** 所有场景件按模式懒加载（ChatMarkdown 已有先例）——
Excalidraw / CodeMirror 各自成 chunk，只在进入白板课 / 练习面时载入；
日常聊天路径的包体积一字节不增。

**明确不用：** three.js / PixiJS / 游戏引擎（文本与无障碍是命）、
Monaco（体积）、tldraw（许可证）、位图纹理包（体积 + 俗）。

## 8. 场景物件裁决记录与决策程序

细节会源源不断出现。任何新物件按四步裁决，裁决结果补进 §3 映射表：

1. **找数据**（撒谎检查表）：什么持久状态支撑它？没有 → 不上桌。
2. **找人称**：谁写的？学习者写的 → 他的物件（第一人称）；练习/证据
   产生的 → 见证式记录（如错题本）；系统产生的 → chrome，不上桌。
3. **找原型**：真实书桌上有这个东西吗？没有物理原型 → 大概率是 chrome
   或页边注，不要发明新家具。
4. **过铁律**：它加深学习还是绕过学习？

### 已裁决的细节（2026-07-06）

**扉页（学习画像的最终形态）。** `student_state` 不做"档案/画像"物件
——档案是别人保管的关于你的记录（第三人称、监视语义），扉页是你写在
自己本子第一页的自我介绍（第一人称、自主语义）。开新本时她陪你填
（一次一问，铅笔写入=draft，你确认落墨=active）；之后退到背景，在她
因材施教引用它时浮现（"扉页上写着你偏好代码例子……"）。weak_points
刻意不在扉页上（M4 的数据分离）：**扉页写"我是谁、我想要什么"，
错题本记"证据显示什么"，永不合并成一份"关于这个学生的报告"。**
文案纪律：UI 持久层逐步用"扉页/我的学习设定"替代"画像/档案"；
对话入口保留"学习画像"作为用户听得懂的词。

**杂记本（自由笔记本）。** 学生不止有课程。四层 §8.1 本就定义 space =
"一门课程、一个长期主题**或一个项目式学习单元**"——自由本不需要新
概念，就是**常驻的默认 learning_space**：素色封面、始终在桌上；聊天中
无课程上下文的知识点捕获落进它（`_ensure_space` 的默认空间正是它）；
内容日后可显式转移进课程本（§8.1 的空间间复制）。

**铅笔/落墨 = draft/active（系统级视觉母语）。** 从扉页推广到全部草稿
审核：AI 草稿一律呈现为"铅笔字迹的夹页"，激活=落墨并粘进本子，
拒绝=抽走活页。M6 的统一草稿箱 = 各分页处夹着的活页合集。

**设置入口：没有这个物件。** 护栏②的直接应用——系统设置（模型、
密钥、能力包、gateway）永远走 chrome，不藏进任何抽屉；学习类设定
分散到所属物件上（本课偏好在扉页，到期提醒开关在卡片盒上，白板课
选项在白板边），不存在一个"设置台灯/抽屉"。找不到设置的场景是
失败的场景。

**卡片盒随本走。** 卡片数据按 space 隔离，因此盒中内容跟随当前打开的
笔记本；跨本聚合的"今日全部到期"视图留待后续（数据支持，UI 后置），
不为它发明第二个盒子。

**书堆随本走。** 桌角书堆呈现当前笔记本（课程）的材料与知识库；
换本换书。
