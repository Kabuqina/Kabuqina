# v0.3.0 "Slim & Focus" Plan

Date: 2026-06-19

## Theme

v0.2.0 is released. v0.3.0 has one theme: **reduce bundle size and converge the
product to the `mainland_cn` student profile**, without touching the agent hot
path or the package rename.

This plan merges two prior specs that turned out to be the same effort seen from
two angles:

- `.qoder/specs/Core重构架构设计_task-eee.md` — the **mechanics**: compatibility
  facades, leaf-first extraction, "delete last", test guards.
- `docs/superpowers/specs/2026-06-19-mainland-profile-code-pruning-design.md` —
  the **product policy**: `mainland_cn` vs `sea` surface, global cuts, hide vs
  delete.

Pruning is, in effect, the product-policy-aware version of the refactor's
Phase 7 deletion. This plan is the single source of truth for what v0.3.0 ships;
the two docs above are referenced for step-level detail and remain authoritative
for their respective lists.

## Scope

In scope:

1. Profile policy layer (`product_profile_policy.py` + consumers + tests).
2. Hide-set wiring (Web + Rust gateway eligibility) so the `mainland_cn` surface
   is correct without deleting anything entangled.
3. Physical deletion of independent global cuts (the bulk of the size win).
4. Bundle pruning (drop rules + stale-dependency exclusion).
5. Minimal refactor guardrails (compat tests + facade) pulled in first.

Deferred (explicitly **not** in v0.3.0):

- **Provider global deletion → v0.3.x.** The global-cut providers are entangled
  in `hermes_core/agent/auxiliary_client.py` (~3,833 lines) with retained
  providers (`kimi`, `zai`, `minimax`, `alibaba`, `stepfun`). Do refactor
  Phase 3 (extract providers into a `providers/` package) first, then delete at
  file level. In v0.3.0 these providers are only hidden via profile policy.
- **Core rename + user-data migration → v0.4.0.** Refactor Phases 8-9
  (`kabuqina_core` rename, `KABUQINA_*` env beyond the profile var, home-dir
  migration) are orthogonal to size and focus.

## Phases

Ordering principle: **policy and guardrails before deletion; physical deletion
only for set A; bundle pruning last.** Contested or entangled items are hidden
(set B) now and have their deletion deferred — same discipline as the provider
deferral.

### Phase A — Guardrails

Pull the cheap safety nets from refactor Phase 0-1 before deleting anything.

- Compat import test (`run_agent` still exports `AIAgent`; legacy core modules
  import) — refactor Phase 0 Step 2.
- `kabuqina_core` facade (lazy) — refactor Phase 1.
- Introduce the profile env var: `KABUQINA_PRODUCT_PROFILE` primary,
  `HERMESDESK_PRODUCT_PROFILE` fallback, unknown/missing → `mainland_cn`.

Verify: `hermes_core` compat tests pass; `cargo check`.

### Phase B — Profile policy layer

- Create `python/src/product_profile_policy.py` exposing profile-aware lists
  (providers, gateways, auto-start platforms, default/hidden toolsets, global
  cuts, network hosts, skill categories, bundle/deletion targets).
- Consume it in `capability_policy.py`, `tool_policy.py`, `network_policy.py`,
  `gateway_policy.py`, `desk_server/capabilities.py` — replace ad-hoc region
  checks.
- Rust injects `KABUQINA_PRODUCT_PROFILE` into the Python child
  (`python_supervisor.rs`) and uses the same contract for gateway eligibility
  (`gateway_supervisor.rs`, `secrets.rs`).
- Tests per the pruning design "Testing" section.

Verify: Python policy tests; Rust gateway-eligibility tests; runtime smoke
(`scripts/dev.ps1`) — chat + one tool call still work.

### Phase C — Hide-set wiring (Web + Rust)

- Web: remove `dingtalk` and `email` from
  `web/src/lib/gatewayPlatformSettingsRegistry.ts` and
  `web/src/advanced/settings/SettingsGateway.tsx`; render policy payloads rather
  than hard-coded region lists. (`providers.ts` and onboarding `optionData.ts`
  are already mainland-only.)
- Rust: `.env` keys for hidden gateways must not make the gateway eligible for
  auto-start under `mainland_cn`.

Verify: frontend tests (onboarding/settings only show mainland gateways); Rust
eligibility ignores telegram/discord/dingtalk/email/slack/signal keys.

### Phase D — Physical deletion of set A

For each candidate: inventory references first, quarantine (drop from
build/bundle inclusion, keep in worktree), run full verification, then delete
source. Mirrors refactor Phase 7.

- Build a removal inventory (`rg` across `hermes_core python tauri web scripts`,
  excluding `target`/`node_modules`/`dist`) proving zero live production
  references for each set-A item.
- Delete in small commits grouped by kind (gateways, tools, upstream dirs,
  plugins, skills).
- Remove deleted gateways from `PLATFORMS` and the platform registry; delete the
  matching `tauri/src/*_env.rs` only after confirming no Rust caller remains.

Verify after each group: Python desktop tests, `hermes_core` gateway/cron tests,
`npm run build`, `cargo check`.

### Phase E — Bundle pruning + smoke

- Add set-C drop rules to `python/build_bundle.ps1` (DingTalk SDKs from
  site-packages; `discord_tool.py`).
- Rebuild the bundle; run bundle smoke tests from the pruning design (retained
  desktop server imports; retained tools import; global-cut tools absent;
  `openai` SDK still importable for compatible providers).

Verify: bundle builds; size reduced; smoke imports pass.

## Verification matrix

Per phase, run the narrowest relevant tests plus the compat tests. Before
closing v0.3.0:

```powershell
cd python; python -m unittest discover -s tests -p "test_*.py" -v; cd ..
cd hermes_core; python -m pytest tests -q; cd ..
cd web; npm run build; cd ..
cd tauri; cargo check; cd ..
.\scripts\dev.ps1   # runtime smoke
```

Runtime-copy caveat (pruning design `Audit Findings`): deleting source does not
update `python/dist/runtime/...` or `tauri/target/debug/runtime/...` until a
re-sync/rebuild. The "absent from runtime" checks must run against a freshly
built bundle, not a stale copy.

## Non-goals (v0.3.0)

- No `kabuqina_core` physical rename or `KABUQINA_*` env migration beyond the
  profile var.
- No user-data home migration.
- No deletion of items in set B (hidden, source retained for `sea`).
