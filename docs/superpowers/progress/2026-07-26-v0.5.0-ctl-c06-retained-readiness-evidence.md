  - `sea`: Telegram, WhatsApp, Email
- DingTalk is a real desktop dependency rather than an optional-import false
  green. Core, desktop requirements and the lock select
  `dingtalk-stream==0.24.3` plus
  `alibabacloud-dingtalk>=2.2.42,<3`; the retained runtime verifier requires
  their modules and DingTalk dist-info. Official 0.24.3 metadata has
  `websockets>=11.0.2` and no obsolete `<13` cap, so the existing locked
  `websockets==15.0.1` is compatible. The adapter reports connected only after
  the SDK exposes a live WebSocket, not merely after scheduling `start()`.

  product. The build input pins the official Node.js 24.18.0 Windows x64
  archive and SHA-256, stages only `node.exe`, `LICENSE` and `VERSION`, and
  verifies the executable. Runtime inventory hashes the executable/license;
  npm remains build-time-only. The locked bridge install and `npm ls`
  validation use the same pinned archive's `npm.cmd`, and the reusable cache
  key/marker includes the Node version so native packages cannot be reused
  across incompatible Node ABIs.
- WhatsApp adapter, identity reader and bridge agree on
  `KABUQINA_HOME/platforms/whatsapp/session` and
  `KABUQINA_HOME/cache/{images,documents,audio}`. The Python resolver retains
  the one-release `whatsapp/session` read fallback without copying, deleting or
  migrating owner data; cleanup remains C07.
- QQ voice conversion no longer wraps arbitrary compressed bytes as raw PCM.
  It uses QQ ASR, a real SILK/ffmpeg conversion, or the visible
  `[Voice] [语音识别失败]` degraded result. The gateway child resolves bundled
  `stt-bin/ffmpeg.exe` before an optional developer system fallback.
- The C0 environment audit now derives accesses, declarations and computed
  templates in one Python AST pass per tracked file. A behavioral regression
  prevents the three ledgers from silently returning to repeated full-tree
  parsing.
