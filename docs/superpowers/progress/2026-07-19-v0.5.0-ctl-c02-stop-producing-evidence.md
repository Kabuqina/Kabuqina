## Conclusion

The C01 manifest is now enforced at every C02 producer boundary. The exact
visible/autostart sets are:

| profile | external gateways | desktop |
|---|---|---|
| `mainland_cn` | `weixin`, `qqbot`, `dingtalk` | retained |

Unknown explicit profiles fail closed. Removed credentials alone cannot make
Rust report gateway eligibility, create migration/profile state, start a child,
or expand Python network trust. Feishu/WeCom config and QR producer commands
reject before file cleanup/write or worker launch. Web settings/onboarding use
the trusted Rust profile DTO; removed deep links render an explicit tombstone.

Every real gateway child now receives both the canonical and compatibility
product-profile variables plus its single platform identity. Before spawn,
Tauri reconstructs `config.yaml` with exactly that platform and preserves only
host-wide sections such as LLM and credential-pool settings. As defense in
depth, `gateway.config` applies the same profile/platform contract after YAML,
environment overrides, and plugin discovery have merged, then discards every
adapter except the selected one. Therefore stale host config cannot start a
removed or second retained adapter or open its network connection.

All Tauri gateway producers validate before mutation or network/worker launch:
the generic env-patch command maps each upsert namespace to one retained
platform, while Telegram, DingTalk, Email/password, Email OAuth, Weixin QR,
QQ/WeChat QR, Feishu QR, and WeCom config/QR entry points enforce the active
profile. Read/status, explicit credential removal, and QR cancellation remain
available so legacy state can still be observed and cleaned up.

New cron and `send_message` targets outside the active profile fail with the
versioned `unsupported_delivery` error before gateway config, adapter, or
network loading. Existing removed job target text is preserved for
list/edit/delete; execution returns `unsupported_delivery` and does not silently
route to local/Desktop/a home channel.
