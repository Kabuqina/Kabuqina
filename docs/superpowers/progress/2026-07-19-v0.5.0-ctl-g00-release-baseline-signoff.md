## v0.5 分叉与 v0.4 hotfix 回补规则

- v0.5 的唯一 ancestry/fork anchor 是 **`v0.4.0^{}` = `f6229d96`**；后续 consumer
  branch 可基于其 `main` descendants，但基线比较、升级来源和回滚都引用该 tag，不引用旧
  `main@a27ac48d` 规划点或当前移动的 `main`。
- 若现在需要维护 v0.4，从 `f6229d96` 新切 `release/0.4`；不得把 v0.5 `main` merge/rebase
  回该分支，也不得移动 `v0.4.0` tag 或替换既有同名资产。
- 安全、数据、迁移、updater 类 hotfix 优先在 `release/0.4` 形成小提交并发布新 `v0.4.x`
  tag/制品，再用 `git cherry-pick -x <hotfix>` 回补 `main`；若修复先落在 `main`，须经 v0.4
  兼容 review 后 `cherry-pick -x` 回 `release/0.4`。冲突时做等价小提交并在 release 记录中
  写明双向 commit mapping，禁止整支合并。

JIT plan/owner/reviewer gate 拉取；v0.5 发布仍由 `CTL-G01/Q-3 → Q-4` 单独裁决。
