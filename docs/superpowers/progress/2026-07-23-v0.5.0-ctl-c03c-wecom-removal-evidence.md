Python, Rust and Web source. The two adapters, callback crypto, QR worker,
Rust commands/child state, Web route/settings/onboarding producers,
direct-send and active CLI/toolset/config branches, WeCom-only tests and
active messaging documentation were removed.

can create platform state. Removed WeCom toolset names remain denied. The
compatibility enum values and persisted credentials, profile/QR state,
sessions, jobs, channel-directory records and home targets remain readable,

loads an adapter, expands network trust or reroutes delivery.

crypto code, imports no `wecom_crypto`, and its complete focused test file
passes after the WeCom sources are deleted. Shared `cryptography`, `aiohttp`,
`httpx` and `qrcode` dependencies remain because retained Weixin, QQ Bot,
DingTalk or common runtime paths consume them. The C0 dependency ledger now
removes only WeCom edges.

Runtime pruning rejects the retired root worker and all three retired Core
modules. Source sync removes those paths from an existing runtime before
verification. No completed branch-local bundle is counted as evidence; the
operator-owned Gate moves to the merged `main` milestone.
