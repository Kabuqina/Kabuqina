## Current conclusion

The owned Feishu/Lark leaf is physically absent from Core, desktop Python,
Rust and Web. The adapter, comment automation, document/drive tools, QR
worker, Rust commands/child state, Web route/settings/onboarding producers,
Feishu-only tests and active messaging documentation route were removed.
Shared registries, direct send, CLI/toolset configuration and current product
copy no longer select or advertise the adapter.

The first Gate review found three implementation blockers. The fresh bundle
copy of the deleted QR worker is now gone. `lark-oapi` is removed from desktop
requirements, the Core extra, the `all` extra and the mechanically regenerated
lock. Runtime pruning rejects the worker, three adapter/comment modules, two
tool modules, `lark_oapi` and its dist-info. Source sync also removes those
artifacts from an existing developer runtime before running the verifier.
Legacy `feishu_doc` and `feishu_drive` toolset names are in the removed set, so
hand-edited or pre-C03b configs cannot re-enable them.

Compatibility remains non-destructive. `Platform.FEISHU`, removed-target
delivery denial, stale config/env filtering and old persisted target text stay
only where required to read, list, edit, delete or fail closed. No
`FEISHU_*` credential, profile, QR/comment file, session, job, channel
directory or home target is deleted or rerouted; CTL-C07 owns that cleanup.
