## 3. 冻结合同证据

### 3.1 Deterministic grader truth

每个新 materialized active question 保存 `PracticeGraderProvenanceV1`，绑定 artifact version、item、
grader kind、canonical hidden-rubric hash 与 `practice-grader-v1` policy。公开 questions 剥离完整
hint/rubric 和所有 answer/reference/test truth；submit 只返回 hash/provenance，不返回 hidden truth。

choice、boolean、short answer、code sandbox/transcribe 与 derivation 共用同一 outcome taxonomy。runner
timeout 与 unavailable 不伪装成 learner incorrect；unsupported 或缺失 required truth 为 ungradable。
旧 quiz 没有新字段时仍可 lazy materialize provenance 并继续 grading。code runner 仍是 current-user
subprocess，存在 filesystem/network/process/memory residual risk；B04 没有宣称强隔离 sandbox。

### 3.2 Activated hint identity、上限与最小化 evidence

`PracticeHintRequestV1` exact schema 绑定 artifact/item/idempotency/level；owner/space 只由 host 注入。
stable activity id 与 canonical fingerprint 共同保证 exact replay、payload conflict 和 concurrent winner。
`LearningStore.insert_bounded_activity_once()` 复用现有 activity PK、write coordination、owner delete 与
export/import；计数检查和 insert 在同一事务内，因而第九个 distinct request fail closed。

service 只读取 active item 已冻结的一个请求层级，不从 answer/reference/test code 动态拼 hint。
activity detail 保存 level、fingerprint、ordinal、content hash 和 zero-provider summary，不保存 hint 内容。
缺 level、draft/rejected/archived artifact、owner/space/item mismatch 均不可消费。

### 3.3 Level ⑤ pending/draft boundary

explanation rubric 在 activation 固定 exact criteria 与 hash。learner request 有 codepoint/canonical byte
caps，文本作为数据字段交给 injected evaluator；typed result 的 exact schema 拒绝 pass/correct/score/
mastery/branch 和伪造 provenance。服务先 durable record bounded explanation request，再至多调用一次
evaluator；replay 不重发。None、exception、timeout 或 invalid result 返回 pending/no draft；合法结果只
经既有 OutputWriter 创建 `evaluation` draft，仍需用户 activate/reject。

B04 没有 production network client，也不调用 ordinary `call_llm()` 或旧 semantic reviewer。P-2
接线前必须另建 write-ahead reservation、physical-attempt hard cap、crash/recovery 与 no-fallback 合同。
