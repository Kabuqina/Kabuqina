## 3. B-track review finding closure: v0.4 active Quiz provenance

The combined review found that a quiz already activated by v0.4 remained
materialized without `artifact_version` or `grader_provenance`. Re-running
`activate_quiz()` skipped that item, while the B06 Tutor adapter correctly
returned `source_untrusted`. Commit `054e23aa` closes that upgrade break without
weakening Tutor's deterministic source boundary:

- activation reconstructs the exact normalized v0.4 item from the still-active
  artifact and adds provenance only when every legacy truth field matches;
- content drift, a missing stable `createdAt`, or a partially present provenance
  pair is never repaired or guessed and remains unavailable to Tutor;
- persistence uses one owner/space-coordinated compare-and-update transaction,
  so a second process changing the item between read and write causes a stable
  retry failure rather than blessing stale truth;
- the compatibility regression starts from the actual v0.4 materialized shape,
  re-activates it with `materialized=0`, and proves `resolve_check()` now returns
  a deterministic Tutor check. Separate tests prove truth drift, partial state,
  and CAS mismatch remain fail closed.

## 4. Security and recovery evidence

- Deterministic Tutor checks consume only activated, hash-pinned Practice
  source and grader truth. Missing/drifted truth blocks; the LLM cannot pass,
  fail, score or choose a branch.
- Tutor provider calls remain single physical attempts with SDK retry/fallback
  disabled and a durable reservation before the call. Retention and L-4 add no
  unreserved provider calls.
- Whiteboard rejects unknown fields/types, floats, JS/SVG/HTML/plugin/external
  content and unsafe KaTeX commands. All quotas and mutations execute under
  the common owner/space operation fence.
- S-3 accepts only bounded v1 `put_element`/`delete_element` batches. Preview
  writes nothing; apply rechecks Tutor revision, working CAS, command hash and
  scene hash under one cross-process fence. Exact replay is stable and payload
  drift conflicts.
- Snapshot/attach/recover/cancel use the same Tutor activity id. A Tutor
  snapshot pins its checkpoint revision in provenance. A test claims a learner
  answer, rejects an executable command, and proves the entire Tutor checkpoint
  and answer remain unchanged while the API returns sanitized readable Tutor
  output/check state.
- Owner export/import validates whiteboard identities, lineage, evidence and
  aggregate quota before commit. The actual near-8-MiB owner bundle round-trip
  and next-unit zero-write rejection are covered by S-2 tests.
