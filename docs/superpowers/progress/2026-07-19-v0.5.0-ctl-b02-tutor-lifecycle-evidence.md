## 3. Crash, race, and restart evidence

- spawned coordinator owner crash 留下 durable fence/journal，由新 coordinator 实例接管；
- production `learning_recovery` entrypoint 从真实 subprocess 覆盖 delete 四 phase、full import
  四 phase、runtime restore 三 phase；desktop startup 在 port handshake 前执行，并每 30 秒重试；
- spawned live writer 持有 OS liveness lock 时第二 entrypoint 只跳过、不 finish/rollback；writer
  退出后下一次 scan 接管。失败只记录 stable reason，fence/journal 原样保留；
- spawned Gateway production constructor 与独立 desk-style LearningStore writer 同时命中 owner fence，
  两者均返回 `LearningOperationInProgressError / learning_operation_in_progress`；
- delete restart matrix 覆盖 `fenced → learning_deleted → runtime_deleted → compacted` 四个 crash phase；
- full import restart rollback matrix 覆盖
  `fenced → validated_empty → learning_imported → runtime_imported` 四个 crash phase；
- stable outbox 覆盖 learning projection 已提交、ack 前 crash 的 replay，不复制 terminal event；
  owner/space delete barrier 还证明 pending-read 到 insert/ack 的 owner-wide guard 不允许 delete 后复活；
- prepare hash drift、manifest mismatch、oversize 与 runtime merge fingerprint conflict 均为 zero-delete/zero-partial-write。
- runtime merge 组合配额覆盖 owner 12、space 6、checkpoint aggregate、terminal 1,000、
  attempt 24、pending outbox 44、exact duplicate 与半批超限 rollback。
- terminal outbox import 覆盖 forged event id/type/payload/budget/time、nonterminal reference 全部
  zero-write；pending replay 与 delivered 后再次 restore 始终复用同一 projection identity，只保留
  一条 `tutor.terminal` history。
