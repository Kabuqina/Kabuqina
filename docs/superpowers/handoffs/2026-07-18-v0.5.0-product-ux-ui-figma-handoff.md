## 0. 新 task 的 30 秒启动摘要

Kabuqina v0.5.0 的产品承诺是：**Study 是长期主线与学习真值，小娜 Chat 是贯穿式交互层，Create/Report 是有界成果工作流。** 一级目的地只有 **学习 / 对话**；“制作”是上下文动作，“成果”是可找回对象，Activity/Recent 属于 product chrome。

用户第一眼看到的必须是 owner 已确认的书桌：**左桌角书堆、中央打开的课程笔记本、右侧卡片盒、右下小娜杯**。书签与卡片盒到期徽标优先回答“上次学到哪、今天复习什么”。不得重新发散 A/B/C 书桌概念或移动这四件物件；全产品只增加一只从笔记本前缘/下层露出的次级“制作 / 成果”工作夹。

下一 task 先验证这一条流程：

```text
小娜杯 idle
  → contextual Chat sidecar
  → 同一会话展开为完整 Chat
  → 返回原 Study 课程、页面/题目与焦点
```

两段式 Chat 是**当前推荐方向，不是已经通过测试的最终结论**。E3 必须同时保留“杯子直接打开完整课程 Chat + 明确返回”的对照方案。若 sidecar 不能复用真实的 session/context/transcript/composer/focus 合同，v0.5 应采用直接完整 Chat，禁止做一套不持久的“迷你 Chat”。

完成标志不是“画出好看的杯子”，而是原型足以判断：

- 用户能否在不丢 Study 上下文的情况下向小娜提问；
- sidecar 与完整 Chat 是否明显是同一段对话；
- transcript、composer draft、pending turn 与 return target 是否无损延续；
- wide、medium、narrow/200% zoom、键盘与 reduced-motion 路径是否语义等价；
- 直接完整 Chat 是否比 sidecar 更诚实或更易用。

## 5. 小娜杯与 Chat 交互合同

### 5.1 推荐的两段式形态

1. **Idle：** 右下只有一只杯子；SVG/装饰本身 `aria-hidden`，外层使用原生 button，旁边始终有可读文字 `问小娜`。
2. **Wide contextual sidecar：** 点击后右侧出现约 360–420px 可读 Chat。header 使用文字 `与小娜对话`，显示 context chip（例如 `高数 · 极限 · 题 3`）、展开与关闭动作；不再复制第二只头像杯。
3. **Expanded full Chat：** 同一 Chat surface 扩展为深度活动，适合长回答、代码、附件与历史；书桌退成边缘背景/return anchor。
4. **Medium fallback：** 空间不足时用真正的 full-height modal drawer。
5. **Narrow/200% fallback：** 用完整 route/full-height Chat 和显式 return，不把核心动作藏起来。

杯子应继续是小娜唯一的视觉化身。当前优先测试“杯子留在 panel 下方/桌边作为空间锚”与“共享元素收进 header”两种微方案，但任何时刻都只能出现一个小娜杯。不得让杯子变成人、巨型聊天气泡、卷轴、咖啡渍对话框或另一套角色 UI。正式对话主体使用普通、可读、可滚动的 Chat UI。

### 5.2 同一个 Chat 的状态不变量

sidecar、完整 Chat、杯子入口和 Study 页边入口必须消费同一份状态：

```text
session_id
SessionExperienceContext {
  mode: general | study
  space_id?
  focus_kind?
  focus_id?
  intent?
  origin_surface
  return_target?
  revision
}
transcript
composer_draft
in_flight_turn / pending / blocked / error
scroll_anchor / unread position
```

必须遵守：

- 从 Study 点 `问小娜` 时，先创建/选择 session，再固定 `space_id + focus + return_target`；
- 后续切换桌面 current course 不得静默改绑这段 session；rebind/unbind 是显式动作；
- ordinary session 没有 context 时按 general 处理，不自动继承当前课程；
- 展开、收起、重开只改变 presentation，不创建第二段 transcript，不丢 composer draft；
- 关闭只折叠视图，不取消 agent；停止生成必须是显式 `停止` 动作；
- return target 失效时回课程安全概览，并解释原位置不可恢复；
- 精确 reuse key、跨窗口冲突策略与持久化边界若尚未由 E2/E4 冻结，原型标 `OPEN`，不能自行伪造最终规则。

### 5.3 Focus、键盘与 streaming

- 杯子外层原生 button 需要可见焦点、`aria-expanded`、`aria-controls` 和可读名称；杯图/蒸汽为装饰。
- wide sidecar 是 **non-modal**：不使用 `aria-modal`、focus trap 或背景 `inert`；正常打开后焦点进入 composer，错误/blocked 时进入明确的恢复状态。
- 只有真正的 medium modal drawer 才使用 dialog 语义、focus trap、背景 inert、初始焦点与关闭后精确恢复。
- 关闭恢复到准确 invoker；从 full Chat 返回恢复到原 activity/heading，而不是笼统回页面顶端。
- Escape 只关闭最内层 view；IME composing 时不响应；Escape 不停止生成。
- streaming 不做逐 token `aria-live`；用户向上阅读时不自动拉到底部，显示 `跳到最新消息`。
- reduced motion 下关闭蒸汽、共享元素位移与 smooth scrolling；蒸汽、颜色和动画从不承担唯一状态。
- 消息列表不用无效的 `role="user"` / `role="assistant"`；speaker 通过可读标签、结构与文案表达。

| `P2` | 杯子到 Chat 的共享元素、蒸汽、180–240ms 转场、纸张质感和最终品牌美术 |

### 13.6 仍需验证，不应在 plan 中写成事实

- sidecar 是否比 direct full Chat 更容易理解、是否真的减少打断；当前只有原型观察，没有参与者证据。
- 真实后端生成期间收起、展开和返回后，pending turn 是否继续且不会产生第二个 session。
- 用户向上阅读时的 scroll anchor、unread 数量与“跳到最新消息”能否跨呈现保持。
- 目标 Windows WebView 的原生 Tab 顺序、系统 IME composing、屏幕阅读器、真实系统 200% 与 reduced-motion；本轮只完成焦点目标、focus trap、Escape 和等价 200% fixture。
- 普通 Chat 与 course Chat 是否仅凭文字、context chip 和 return 就足够清晰。
- 当前代码证据中动态 ARIA role、无条件 smooth scroll 与裸 `/chat` navigation 的修复范围和排期。

### 13.7 给总体 plan session 的一句话

> v0.5.0 应先保证“同一课程会话 + direct full Chat + 精确返回”这条低风险脊柱，再把 wide sidecar 作为共享状态已被证明后的渐进增强；最终美术与动效不应阻塞这条脊柱。
