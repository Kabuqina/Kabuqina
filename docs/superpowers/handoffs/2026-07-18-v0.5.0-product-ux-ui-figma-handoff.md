## 0. 新 task 的 30 秒启动摘要

Kabuqina v0.5.0 的产品承诺是：**Study 是长期主线与学习真值，小娜 Chat 是贯穿式交互层，Create/Report 是有界成果工作流。** 一级目的地只有 **学习 / 对话**；“制作”是上下文动作，“成果”是可找回对象，Activity/Recent 属于 product chrome。

用户第一眼看到的必须是 owner 已确认的书桌：**左侧知识库（可保留桌角书堆的家具造型）、中央打开的课程笔记本、右侧卡片盒、右下小娜杯**。书签与卡片盒到期徽标优先回答“上次学到哪、今天复习什么”。不得重新发散 A/B/C 书桌概念或移动这四件物件；“书堆”只能描述造型，不能覆盖“知识库”父概念。全产品只增加一只从笔记本前缘/下层露出的次级“制作 / 成果”工作夹。

下一 task 先验证这一条流程：

```text
小娜杯 idle
  → contextual Chat sidecar
  → 同一会话展开为完整 Chat
  → 返回原 Study 课程、页面/题目与焦点
```

两段式 Chat 是**当前推荐方向，不是已经通过测试的最终结论**。E3 必须同时保留“杯子直接打开完整课程 Chat + 明确返回”的对照方案。若 sidecar 不能复用真实的 session/context/transcript/composer/focus 合同，v0.5 应采用直接完整 Chat，禁止做一套不持久的“迷你 Chat”。

完成标志不是“画出好看的杯子”，而是原型足以判断：

- 用户能否在不丢 Study 上下文的情况下向小娜提问；
- sidecar 与完整 Chat 是否明显是同一段对话；
- transcript、composer draft、pending turn 与 return target 是否无损延续；
- wide、medium、narrow/200% zoom、键盘与 reduced-motion 路径是否语义等价；
- 直接完整 Chat 是否比 sidecar 更诚实或更易用。

### 4.2 响应式翻译

- **Wide：** 完整书桌；sidecar 打开后覆盖或压缩右域，不增加第四列，中央 Study 内容仍可辨认且可操作。
- **Medium：** 只有在同时容得下 ≥360px Chat 和可用 Study 主栏时保留 non-modal sidecar；否则使用 full-height modal drawer。
- **Narrow / 200%：** 单 route/full-height Chat，提供明确“返回学习/返回原处”；场景转为语义等价 flat document flow。
- **Flat DOM 顺序：** current context → next/recovery → due → Activity → Study content → 知识库（当前引用默认展开、其他分类一步可达）→ Create/results → Chat。
- 品牌插画、纸纹、光斑、蒸汽与动效失败时，DOM/CSS/SVG 的中性骨架仍可用；不得退回旧 Workbench。

## 5. 小娜杯与 Chat 交互合同

### 5.1 推荐的两段式形态

1. **Idle：** 右下只有一只杯子；SVG/装饰本身 `aria-hidden`，外层使用原生 button，旁边始终有可读文字 `问小娜`。
2. **Wide contextual sidecar：** 点击后右侧出现约 360–420px 可读 Chat。header 使用文字 `与小娜对话`，显示 context chip（例如 `高数 · 极限 · 题 3`）、展开与关闭动作；不再复制第二只头像杯。
3. **Expanded full Chat：** 同一 Chat surface 扩展为深度活动，适合长回答、代码、附件与历史；书桌退成边缘背景/return anchor。
4. **Medium fallback：** 空间不足时用真正的 full-height modal drawer。
5. **Narrow/200% fallback：** 用完整 route/full-height Chat 和显式 return，不把核心动作藏起来。

杯子应继续是小娜唯一的视觉化身。当前优先测试“杯子留在 panel 下方/桌边作为空间锚”与“共享元素收进 header”两种微方案，但任何时刻都只能出现一个小娜杯。不得让杯子变成人、巨型聊天气泡、卷轴、咖啡渍对话框或另一套角色 UI。正式对话主体使用普通、可读、可滚动的 Chat UI。

### 5.2 同一个 Chat 的状态不变量

sidecar、完整 Chat、杯子入口和 Study 页边入口必须消费同一份状态：

```text
session_id
SessionExperienceContext {
  mode: general | study
  space_id?
  focus_kind?
  focus_id?
  intent?
  origin_surface
  return_target?
  revision
}
transcript
composer_draft
in_flight_turn / pending / blocked / error
scroll_anchor / unread position
```

必须遵守：

- 从 Study 点 `问小娜` 时，先创建/选择 session，再固定 `space_id + focus + return_target`；
- 后续切换桌面 current course 不得静默改绑这段 session；rebind/unbind 是显式动作；
- ordinary session 没有 context 时按 general 处理，不自动继承当前课程；
- 展开、收起、重开只改变 presentation，不创建第二段 transcript，不丢 composer draft；
- 关闭只折叠视图，不取消 agent；停止生成必须是显式 `停止` 动作；
- return target 失效时回课程安全概览，并解释原位置不可恢复；
- 精确 reuse key、跨窗口冲突策略与持久化边界若尚未由 E2/E4 冻结，原型标 `OPEN`，不能自行伪造最终规则。

### 5.3 Focus、键盘与 streaming

- 杯子外层原生 button 需要可见焦点、`aria-expanded`、`aria-controls` 和可读名称；杯图/蒸汽为装饰。
- wide sidecar 是 **non-modal**：不使用 `aria-modal`、focus trap 或背景 `inert`；正常打开后焦点进入 composer，错误/blocked 时进入明确的恢复状态。
- 只有真正的 medium modal drawer 才使用 dialog 语义、focus trap、背景 inert、初始焦点与关闭后精确恢复。
- 关闭恢复到准确 invoker；从 full Chat 返回恢复到原 activity/heading，而不是笼统回页面顶端。
- Escape 只关闭最内层 view；IME composing 时不响应；Escape 不停止生成。
- streaming 不做逐 token `aria-live`；用户向上阅读时不自动拉到底部，显示 `跳到最新消息`。
- reduced motion 下关闭蒸汽、共享元素位移与 smooth scrolling；蒸汽、颜色和动画从不承担唯一状态。
- 消息列表不用无效的 `role="user"` / `role="assistant"`；speaker 通过可读标签、结构与文案表达。

### 13.3 Narrow / 200% 设计结论

Narrow 服务于 Windows 主窗口 `720px` 最小宽度、200% zoom/reflow 与极窄安全降级，不是移动端设计。废止旧的八段固定正文顺序；新的稳定顺序是：

```text
course context → current task surface → due summary → supporting entry points
```

- `Activity / Recent` 始终属于 shell，不进入正文 section；
- `Chat` 是一级导航和当前活动动作，不放在页面末尾；
- 知识库作为父入口存在，“当前引用”默认展开，课程知识/资料/辅导笔记与制作/成果保持一步可达；
- 当前题目、答案、检查动作、dirty/pending/error/feedback/result 与“问小娜”保持在同一活动面；
- DOM、Tab 与读屏顺序不因优先级动态重排；优先级只改变主 CTA：`action-required > dirty/interrupted recovery > due-now > ordinary next`；
- recovery 与 due 并存时 recovery 为主、due 同屏为次；活动进行中 due 不自动打断。

### 13.9 P1 · focus、语义锚点、读屏与 Chat 入口修复

本节处理 P0 后实测发现的四项 P1，不改变视觉方向或 presentation 裁决，只收紧原型行为合同。

#### 动作完成后的焦点交接

- `Stop` 被激活后会同步把焦点交给同位置重新出现的“发送问题”，不会让被隐藏按钮继续持有焦点，也不会在动作结束后落到 `BODY`。
- “跳到最新”会在隐藏自身前同步聚焦可编程聚焦的 transcript region；消息区保留明确 label，键盘用户可从最新消息继续阅读。
- 同类状态替换一并收紧：从“发送问题”进入生成时，若触发者是发送按钮则焦点转到 `Stop`；生成自然完成且 `Stop` 仍持焦点时，焦点转回“发送问题”。从 textarea 使用 `Ctrl+Enter` 时不强夺输入焦点。

#### 滚动连续性使用语义锚点

绝对 `scrollTop` 不再作为连续性真值：

| 区域 | 保存合同 | 恢复方式 |
|---|---|---|
| Chat transcript | `messageId + offsetWithin` | 找回同一 message node，再按元素内偏移修正容器滚动；消息高度、sidecar/full 宽度与字体缩放改变后仍锚定同一段内容 |
| Study | `page + focusId + offsetWithin` | 找回同一 lifecycle page 的真实 activity/focus anchor，再恢复其 viewport 内相对位置与键盘焦点 |

`scrollTop` 仅作为浏览器执行滚动的结果，不再被保存为跨呈现恢复合同。geometry readout 同时显示当前 Study/Message semantic anchor，便于 W03/W04/W07 对照。

#### 流式回答的读屏策略

- transcript 从 `role="log"` 改为普通 `role="region"`，并显式 `aria-live="off"`；每 `620ms` 更新的流式正文不会作为 live region 反复播报。
- composer 下方状态文字继续可见，但不承担 live 播报。
- 新增位于 Chat visibility 之外的独立、atomic polite announcer，只播报生成开始、完成、停止、新消息与“已跳到最新”等生命周期事件；隐藏 Chat 时仍可播报“回答完成，有新消息”。
- fault alert、表单错误和显式 return notice 继续使用各自既有语义，不与逐段流式正文混用。

#### Wide Chat 入口可发现性

- `#kq-cup` 已从长内容的 `.study-stage` 坐标系移到 `.product-viewport` 内的产品 shell 层；wide/medium 下保持 `right: 26px; bottom: 24px` 的稳定画布内悬浮，不再定位到长正文底部。
- full/narrow Chat route 会显式隐藏该入口；sidecar 候选打开时保持原 `aria-expanded` 合同。Narrow 仍使用原有 static、全宽的一步可达入口，不引入移动端导航。
- geometry readout 新增 `Chat entry visible {width}×{height}px`，目标 Windows 复验时应看到完整按钮面积，而不是约 `8px / 31px` 的残片。

#### 本轮可执行验收

| Frame / 动作 | 验收点 |
|---|---|
| `W04 → Stop` | 动作返回后 `document.activeElement === #kq-send` |
| `W04 → 跳到最新` | 按钮隐藏后 `document.activeElement === #kq-transcript` |
| `W04 sidecar → full` | 改变消息宽度/高度后，message anchor 的 ID 与元素内偏移保持不变 |
| `W01 → sidecar → full → Study` | 改变 Study 布局后恢复同一 `page/focusId/offsetWithin` 与焦点 |

| 任一 streaming frame | transcript 非 live region；独立 announcer 只在 lifecycle boundary 更新 |

本节仍只落在决策 HTML 与 handoff。应用内浏览器的 `file://` 限制未解除，因此“完整按钮面积”和真实读屏行为仍需目标 Windows 环境复验；当前 DOM 交互检查覆盖焦点、语义锚点恢复与 live-region 结构，不等同于 NVDA/系统缩放认证。
