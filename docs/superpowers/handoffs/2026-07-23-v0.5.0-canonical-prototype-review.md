## 2. 已验证的优点（无需修改）

1. **实验室层与产品画布分离**：`decision-status` / `scope-ledger`（L2333–2364）明确声明 `CANONICAL FLOW PROPOSAL · NOT FINAL` 与 scope-out 项，符合流程文档 §9 的分离要求。
2. **焦点与播报合同落实**：`setCanonicalPhase(phase, { focusId, announcement })`（L4034–4055）统一处理焦点恢复（`preventScroll`）与 polite 播报；K0 期间答案只读、按钮原地变「正在检查…」（L4110, L4134–4136），符合 §4.2 规则。
3. **三段式反馈落纸页**：「已经说明清楚 / 还差一步 / 接下来试试」（L2442–2456）与 §4.2 结构一致；反馈不覆盖答案、不自动改写。

## 3. 候选冻结必须携带的三条附条件备注

> 以下三条不阻塞进入候选冻结，但必须写进冻结记录并在最终行为冻结前关闭相应证据缺口，
> 避免实现阶段误读原型。

### 备注 A：原型的 phase 枚举不是实现模型

流程文档 §2 明确「状态不是一个巨型 enum」，界面由 `deskDensity / studyActivity / nanaPresence / chatPresentation / sessionContinuity` 五个正交维度组合。但 canonical 实现是一个扁平 `canonicalPhase` 枚举 + `hidden` 切换（L4057–4083）。

**后果：**
- 文档给出的关键组合例——「学生正在修改答案，同时小娜有未读回答」（`dirty + unread + chat closed`）——**在原型中无法呈现**；
- 实现者有照抄原型结构的风险。

**要求修改：** 在原型 lab bar 的 `scope-ledger` 中新增一条说明：「canonical 的 phase 枚举仅为演示驱动；实现必须按流程文档 §2 的正交维度建模，不得复制本原型的状态结构。」同时在该条目中点名 `dirty + unread` 组合尚未被任何 frame 演示。

### 备注 B：K0 与 error 路径的验收边界必须显式

- C-K0 不在 frame 下拉框中（L2270–2279），只能点击触发、650ms 定时器自动跳走（L4664–4675），评审者无法静态定格审视；而流程文档 §3 为 K0 定义了独立合同（pending/cancel/timeout/error、不跳页顶、不用 toast）。
- canonical 流程内**没有任何 error/timeout 分支**；fault frame 仅存在于旧 W04/W05 系列。P0 宣称「完整 course Chat」，但其不变量（same session/pending）在失败场景下未被 canonical 自身演示。

**要求修改：**
1. 在 `scope-ledger` 注明：「canonical 的 K0/error/timeout 路径本轮不重演，沿用 W04/W05 系列 frame 验收」；
2. 在 frame 下拉框中增加 `C-K0` 静态 frame，使检查中状态可定格截图；
3. 最终冻结证据必须同时引用 canonical 的 K0 截图与 legacy 的 error/timeout 回归结果，不能把后者描述为 canonical 已独立演示。

### 备注 C：行为冻结后拆分 canonical 与 legacy，拆分后重新验收

单文件 4,988 行中约 70% 是与被评审新流程无关的 legacy `kq-` 代码，两棵完整 DOM 树靠 `hidden` 互斥。回归保留旧 frame 的决策合理，但文件形态已开始稀释 canonical 的信号。

**要求修改：** 浏览器证据关闭后由 owner 确认行为冻结，再将 canonical 壳拆为独立文件
（建议 `2026-07-23-v0.5.0-desk-canonical.html`），原文件改名归档为 legacy 回归矩阵。
拆分是文件结构变化，不自动继承冻结结论；拆分后的 canonical 文件必须重跑主路径、窄屏、
焦点与 exact return 冒烟，证据通过后才进入原型制品冻结。
