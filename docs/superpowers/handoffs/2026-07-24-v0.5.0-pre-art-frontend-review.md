## 1. 这次真正交付什么

### 1.1 书桌 ↔ Chat

- 咖啡杯和页内求助先显示可审核提问卡，再进入真实 `/chat`，不会静默发送。
- versioned `StudyChatHandoff` 携带课程、步骤、题目、原答案、反馈、来源、用户问题、
  return target、focus anchor 和 revision。
- 同一课程/步骤复用确定性 Chat session；课程 context bar 与普通对话明确区分，可显式解绑。
- “返回这一步”准确恢复原题、答案、反馈与焦点；失效 target 安全回课程 overview。
- 首次发送前关闭或重启应用，课程上下文与可见 prompt 仍恢复；真实 session 建立后改由
  session binding 恢复。

### 1.2 制作 / 成果工作夹

- “制作”只允许显式选择当前课程真实材料与目标，然后生成可审核的 Create handoff。
- 不默认携带整个课程，不自动写 mastery、计划完成度或 active artifact。
- “成果”只认 typed deliverable truth；当前后端没有该 truth 时显示可信空态，不从 Chat
  文本或 Windows 路径猜测成果。

### 1.3 Activity / Recent

- Study 列表读取真实 activities，打开时可独立刷新、失败和重试。
- Chat 列表只展示有当前 course binding 的真实 sessions；普通/最近对话不会被静默归入课程。
- Study 与 Chat 的 loading/error/empty 相互独立。

### 1.4 其余 pre-art 状态

- 真实 due-card queue 可揭示答案并以按钮或 1–4/Space 键评分；失败保留当前卡。
- 课程、页面、材料、卡片、Activity、Settings、“开新本”和 Chat 入口继续复用现有路由/
  dirty-leave guard。
- 既有五题型与 overview/focused/dirty/checking/needs_revision/completed、刷新恢复、失败重试
  合同保留。
- 720px/360px 下 utilities、Activity、工作夹和对话入口不隐藏；最终美术只需替换现有
  DOM/CSS/asset slots。

## 4. Reviewer 重点

1. handoff 校验是否 fail closed；unsafe return path、过期或失效 step 是否安全降级。
2. pending handoff、session binding 与 explicit unbind 是否可能把普通 Chat 静默绑入课程。
3. dirty-leave 取消时是否保持原页；确认后是否持久化必要的恢复 handoff。
4. exact return 是否恢复原答案/反馈/焦点，而不是只跳回 practice 首页。
5. 工作夹是否始终要求显式来源；成果是否存在文本/路径推断或第二份 truth。
6. Activity 是否只展示有可验证 course binding 的 Chat session。
7. card review 失败、键盘评分和重复触发是否可能丢卡或重复写 evidence。
8. narrow DOM 顺序、键盘焦点、live region 和 reduced-motion 是否仍可用。
9. production bundle 是否继续排除 `/__dev/desk` 和固定 fixture answer。
10. diff 是否严格排除 C 轨 manifest 与 backend/schema 扩权。
