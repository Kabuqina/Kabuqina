## Outcome

Physically remove the owned Feishu/Lark product surface across Core, desktop
Python, Rust shell and Web: adapters, comment automation, document/drive tools,
QR worker and child state, settings/onboarding routes, active documentation,
imports, registries, `lark-oapi`, and fresh-runtime artifacts.

The leaf is non-destructive. Existing `FEISHU_*` credentials, profile folders,
QR result/progress files, comment state, sessions, jobs and home targets remain
on disk. Compatibility tokens may remain only where they make old state
readable, explicitly removable, or fail as C02 `unsupported_delivery`; they
must not load an adapter, spawn a child, write new platform state, connect to
Feishu/Lark hosts, or reroute delivery.

## Commit slices

1. **Plan + retained-boundary preflight:** freeze this JIT plan; replace Feishu
   as a generic reconnect/stream/session/display test double with retained or
   neutral platforms. Keep Feishu-specific batching/comment behavior with the
   leaf to be deleted.
2. **Core leaf deletion:** delete Core adapters/comment/tools and Feishu-only
   tests/docs. No dependency or desktop shell changes in this commit.
3. **Desktop leaf deletion:** delete Python QR worker, Rust commands/child slot,
   Web page/component/routes/onboarding/settings producers.
4. **Shared-spine cleanup:** remove imports, registries, direct-send/toolsets,
   CLI and active navigation/copy while retaining C02 compatibility tokens.
5. **Dependency/runtime closeout:** after B02 integration, remove `lark-oapi`,
   regenerate the lock, and update bundle/sync/pruning verification. The
   release operator owns the fresh runtime build and attaches its result before
   re-review.

Each slice receives a separate diff review. Mechanical deletion, shared-spine
changes and dependency/lock regeneration are not squashed together.
