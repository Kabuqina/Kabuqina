## 0. 三条约束

1. **设置不承载学习。** 它调外观、凭据、数据与资源，不出现任何影响掌握度或学习证据的东西。
2. **同一事实只有一个主表达位置。** 外观那条只做**台灯的镜像**，不是第二个独立主题控件
   （否则违反 §7.3 重复测试）。
3. **内部对象名不出现在学生可见层。** `migration_key`、`space_id`、profile 名一律降到
   高级模式之后。

**#2 外观主题（改）。** 保留三档（跟随系统/浅色/深色），但文案与行为改为**台灯的镜像**：
桌上那盏灯是主表达位置，设置里这条只是同一状态的另一个入口。参见
[物件词汇表](2026-07-25-v0.5.0-materiality-vocabulary.md)：台灯不得"沦为设置项里的开关"。

**#4 材料与隐私（新）—— 本轮最缺的一条。**

v0.5.0 的默认路径是学生导入**自己的教材**。docling 在本机跑，但抽知识点、出题、讲解必须把
**教材正文**发给云端 provider。学生手上那本书有版权、有他自己的批注。产品欠他一句话：
哪些内容离开这台机器、发给谁。

- 形态：**披露为主**，不是一堆开关。能关的只有"本来就是可选项"的东西；把不可选的做成
  假开关更不诚实。

**实现时核过代码，修正了本条初稿的一处过度断言（2026-07-27）：**初稿写的是"讲解/出题/抽卡
会把相关材料片段发给 provider"。实际不是——`TutorProviderRequestV1.input_refs` 是
`{kind, id}` 形态的**条目引用**（见 `learning_data_service` 对 `ref.kind === "artifact"`
的校验），连同 `goal` 一起发出，**材料正文不在其中**。真正会外发材料内容的是**对话附件**：
`DeskAttachmentPayload` 带 `data` 字段，就是文件内容本身。

因此披露按"核得实"的四条写，宁少说不多说：

| 内容 | 去向 | 依据 |
|---|---|---|
| 材料解析（版面/表格/公式） | 本机 | docling 本地推理 |
| 讲解与纠错请求 | 只发学习目标与条目**编号** | `input_refs` 是 `{kind,id}` |
| 学习记录（答案/练习/掌握度） | 本机 learning 库 | 不上传 |
| **对话附件** | **发给当前 provider** | `DeskAttachmentPayload.data` |

并点名当前生效的 provider 与模型（取 `cmd_llm_config_preview`）；未配置时明确说
"配置之前不会有任何内容发出"。
- 现有的「学习功能改进计数」那条的措辞标准（默认关闭 / 不记录题目答案 / 不上传）
  **就是本条的范本**——但它只管遥测，不管教材正文，两者不能互相顶替。
- 后端：需要一份"出口清单"——即当前生效的 provider/模型，以及哪些活动会外发材料内容。

**#5 学习数据（搬）。** 导出 / 导入 / 删除全部现在挂在 **Study 顶栏一个常驻按钮**
（[StudyAdvancedMenu.tsx](../../../web/src/study/StudyAdvancedMenu.tsx)，由
[StudyTopBar.tsx:35](../../../web/src/study/StudyTopBar.tsx#L35) 无 gating 渲染）。
学生学习时顶栏永远挂着"学习数据"——§7.2 删除测试不过：删掉它学生照样能学。

- 搬进设置：**导出备份**、**导入**、**删除全部**（保留现有确认短语机制）。
- **迁移状态 / 迁移失败导出降到高级模式**（见 2.3）——`migration_key` 不该铺在学生面前。
- Study 顶栏那个按钮**删除**，不留折叠入口。
- 后端：命令已存在（`cmd_study_data_export` / `cmd_study_data_import` /
  `cmd_study_migration_failures_export`，见 [tauri/src/study.rs](../../../tauri/src/study.rs)），
  只换调用位置。

**#7 复习节奏（新）—— 本表唯一需要动学习算法邻域的一条。**

[flashcards.py](../../../hermes_core/learning/flashcards.py) 是 SM-2 变体，有
`MAX_INTERVAL_DAYS` 但**没有每日上限**。学生迟早会遇到"今天堆了 200 张"。

- 形态：每日新卡上限 + 每日复习上限，两个数字，给保守默认值。
- **后端契约（2026-07-28 已实现）：**默认分别为 20 / 100，范围为 `0..100` /
  `0..1000`，通过 `cmdStudyPreferencesGet/Put` 读写。限制按课程和用户本地自然日计算；
  `cmdStudyFlashcards(spaceId, true)` 返回受限队列及 `queue` 统计，刷新不重置已用额度。
- **红线：这是保护，不是成就。** 不显示连续天数、不显示完成率、不做 streak——
  一旦变成打卡指标，就把"走遍"伪装成"学会"，与目录那条红线同源。
- 优先级：本表**最后做**。它是新功能，前六条都不依赖它。

### 2.2 模型

**#2 token 用量（新）。**

- **只报 token 数，不折算金额。** owner 定：具体金额不是我们能准确知道的（provider 定价、
  折扣、缓存命中都不在我们手里）。报一个假精度的钱数比不报更糟。
- 数据**已经落库**，不需要新埋点：`tutor_provider_attempts`
  （[tutor_runtime_store.py:214](../../../hermes_core/learning/tutor_runtime_store.py#L214)）
  已有 `actual_input_tokens`、`actual_output_tokens`，且同表带
  `owner_id`、`space_id`、`model_id`、`provider_id`、`status`、`completed_at`——
  按课程 / 模型 / 时段聚合是一条 `GROUP BY`。
- 现成可抄的写法：`_attempt_fold`
  （[同文件:1566](../../../hermes_core/learning/tutor_runtime_store.py#L1566)）已经在 SUM
  `reserved_*`，照它加 `actual_*` 的聚合即可。
- 需要新写的只有三段：store 上的聚合方法 → desk API 端点 → tauri command → UI。
- 展示口径：**本周 / 本月 + 按课程分组**，只用低强调数字，不做趋势图（§7.4 行动测试：
  学生看了能做的动作是"少问几次"或"换个便宜模型"，一张折线图不增加这个决策）。

### 2.3 高级

**2026-07-27 修订：不再分权限层。**owner 决定取消 power-user 两档，能力默认全开
（理由见 DECISIONS.md「Power mode is the only mode」）。因此本节的「高级」是
**信息组织**，不是权限门：把排查用、低频、术语重的东西收在一个 tab 里，而不是
"这些你没资格用"。

受影响的两条：**#2 工作区**不再分层，路径、打开文件夹、改位置全部常驻；
**「高级用户」开关**整节删除（连同顶栏那个开关与 onboarding 首屏的 advanced 勾选）。
`SettingsLearningMigrations` 仍放在高级 tab——理由是 `migration_key` 术语重、
只在排查升级时才看，不是因为权限。

| # | 节 | 状态 | 后端支持 |
|---|---|---|---|
| 1 | **导入精读档位默认值** | **新** | 已有：偏好读写 + Study 材料读取策略 |
| 2 | 工作区路径 | 改 | 无 |
| 3 | 加载包下载管理 | 已有 | 无 |
| 4 | **迁移状态 / 迁移失败导出** | **搬** | 命令已有 |
| 5 | 共享偏好（裸文本） | 已有 | 无 |
| 6 | 高级模式开关自身 | 已有 | 无 |

**#1 导入精读档位（新）。** docling 的 `auto`（快，pypdf）与 `precise`/`math`（CPU 推理）
差一个数量级——学生导一本 300 页教材会以为卡死。这个选择现在埋在工具参数里，
学生看不见也控制不了。设置里给默认档位，导入时可临时改。
参见记忆：docling read modes & perf。

**后端契约（2026-07-28 已实现）：**`cmdStudyPreferencesGet/Put` 读写
`importReadMode: auto | precise | math`，默认 `auto`。`cmdStudyMaterialRead` 只为可信的
Study 导入路径应用该默认值/上限；一次性 `overrideLimit: true` 可在学生确认性能提示后越过。
普通 Chat 的文档工具不受影响。返回值同时给出 preferred/requested/effective mode 和
`limited`，前端能明确展示实际采用的档位。

**#2 工作区路径（改）。** 原现状是整节仅 `powerUser` 可见。v0.5.0 学生要导入自己的教材，
"我的教材和笔记在哪个文件夹"对普通学生也成立了。**已实现：整节常驻，不再分层**
（2026-07-27 取消权限分档后，原先"路径只读提升、改路径留高级"的分层方案作废）。

## 3. 明确不做

1. **「小娜引导强度 / 允许直接给答案」开关。** 这会把产品红线做成可关掉的偏好项。
   学生确实有"我现在就想知道答案"的时刻，那的处理是 answer-then-teach 的**行为**，
   不是设置里的开关。一旦可关，agent 退化成替学生做题的工具。
2. **金额折算。** 见 2.2 #2。
3. **第二个独立主题控件。** 见 §0.2。
4. **本机控制台入口。** `/config`、`/env`、`/sessions` 是运维面，不是学生面；
   相关 i18n 已是死键，见 §4。
5. **任何 streak / 完成率 / 覆盖率。** 见 2.1 #7。

## 5. 验收

- **五秒测试：**打开设置，5 秒内能说出"这页能改什么"；
- **删除测试：**每个常驻节都过一遍"删掉它学生还能完成当前任务吗"——
  Study 顶栏那个「学习数据」按钮正是靠这条判死的；
- **行动测试：**token 用量那节必须对应一个学生能执行的动作，否则降级为纯数字一行；
- 明暗两套下每节都成立；720×520 最小窗口不出现横向溢出；
- 键盘可达与读屏语义等价（架构 Must 项）。
