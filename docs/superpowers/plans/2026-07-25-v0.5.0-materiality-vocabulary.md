> **日期：** 2026-07-25
> **状态：** `OWNER DIRECTION CONFIRMED · PRODUCT PRINCIPLE`
> **适用范围：** Kabuqina v0.5.0 的 Study、Studio、Chat、Activity 与后续前端重构、美术设计。
> **上游架构：** `2026-07-25-v0.5.0-study-studio-product-architecture.md`
> **界面预算：** `2026-07-25-v0.5.0-interface-information-principles.md`
> **物件原型来源：** `docs/superpowers/prototypes/2026-07-07-notebook-ia.html`（Study 物件词汇的最初出处）

## 0. 为什么必须写下来

**物化引导设计，不是美术阶段的抛光。**（owner，2026-07-25）此前几版原型"一直差点意思"，原因正是把物化推迟到了后面的美术阶段；没有物性引导，界面就退化成栏、卡片和状态条的排列。

但物性有一个特点：**它在代码里是不可见的。**复写件在实现中只是一圈虚线边框，工作夹只是一个圆角方向。看原型的人分辨不出这是"复写纸"还是"某种强调样式"，于是重构时它会被当作可随意替换的装饰删掉或改掉。

所以本文档为每一件物件记录三件事：**它是什么材质 / 它承担什么语义 / 拿掉它用户会误解什么**。第三列是判断标准——**凡是拿掉后用户不会误解任何事的物性，都是装饰，应当删除。**

## 1. 根隐喻：同一张书桌

Kabuqina 的全部界面发生在一张暖色的书桌上。Study 与 Studio 不是两个应用，是同一张桌子上的两种工作：一种把东西读进自己，一种把东西整理出去。因此两域共用纸张、桌面、紫色铅笔与全部设计令牌，**不允许引入第二套域色**。

桌上唯一的光源是**台灯**。开灯即夜晚：暖光从台灯所在的右上角落在桌面上，纸色转深。台灯是深浅模式的首选开关，设置里的开关是它的镜像。

## 2. 四条生成性区别

以下四条区别生成了其余所有物性。设计新物件时先回答这四条，再谈样式。

| # | 区别 | Study | Studio | 它表达什么 |
|---|---|---|---|---|
| 1 | **装订方式** | 装订成册，页序固定 | 散页，可重排 | 内化是累积（知识一页页攒起来）；表达是排序（决定什么先说） |
| 2 | **容器** | 本 | 夹 | 书是已经成形的；夹子装的是还没定序的东西 |
| 3 | **标签方向** | 顶边横向（书立） | 侧边纵向 | 本立着露顶边，夹插着露侧边——形状本身说明这是两类东西 |
| 4 | **原件所在** | 原件 | 复印件 | 跨域取材只取副本，学习真值永远留在本子里 |

第 1 条是根：**同一种纸，装订方式不同。**材质相同表示"都是你的思考"，装订不同表示两种工作的性质不同。

## 3. Study 的物件

| 物件 | 材质 / 形态 | 承担的语义 | 拿掉会误解什么 | 原型中的呈现 |
|---|---|---|---|---|
| 书桌 | 暖色渐变桌面 | 一切发生的场所 | 界面沦为无场所的应用窗口 | `.app-frame` 桌面渐变 |
| 课程本 | 象牙纸，装订成册 | 一门课的全部上下文在同一本里 | 课程沦为一个筛选条件 | `.notebook` |
| 书立标签 | 顶边横向，当前那本与纸面同色并压住边框 1px | 课程名长在本子上；换课＝换一本本子 | 课程身份与内容脱节，需要另设标题重复说明 | `.bookend` / `.nb-pill` |
| 书脊小色块 | 标签左侧竖条，当前为紫、其余半透明 | 哪一本正被打开 | 只能靠文字粗细区分，弱 | `.spine` |
| 杂记本 | **牛皮纸**，离开课程组、单独在最右 | 这一本不是课程；此处什么都不要求你（留白） | 会被当成"第某门课"，或变成待办收件箱 | `.nb-pill--scratch` / `.notebook--scratch` |
| 铅笔草稿 | 虚线边、铅笔色、淡紫底 | 系统拟的，尚未生效 | 用户误以为已经生效 | `.study-sheet--pencil` |
| 落墨 | 实线、棕色左边线、纸面加白 | 已由用户确认、已生效 | 草稿与真值不可分辨 | `.study-sheet--ink` |
| 书签 | 从本子上缘探出的暖色纸片 | 上次学到哪，一点即回 | 恢复位置变成一条普通链接 | `.bookmark-card` |
| 书堆 | 立在右栏的一排**书脊**（中文竖排），可抽出、可加一本 | 参考资料立着＝需要时抽一本；**不是可浏览的知识库空间** | 材料退回成一张可浏览的清单，重新引诱堆砌输入 | `.book-stack` / `.book-spine` |
| 书堆上的目录 | 贴在书堆下的一行，可翻开，每条带出处 | Learning Index 可核对可修正，但不占入口（与 Studio 的 Material Index 同待遇） | 系统抽取的知识点不可审，或被做成一个去处 | `.stack-index` |
| 摊开的材料 | 贴右边缘的侧开面板，工作面留在左侧照常可用 | 看材料**不必离开正在做的事**；书只作局部呈现，不做主界面 | 看一眼材料就得放弃当前工作，或被弹窗盖住无法对照 | `.material-panel` |
| 卡片盒 | 右侧一叠卡片 | 到期复习不打断当前练习 | 复习变成打断式提醒 | `.review-card` |
| 复习作答 | **两个等重按钮**（想起来了 / 没想起来）＋ 一个低强调"太简单" | 只问学习者能可靠回答的那一个问题；**等重是为了不诱导不诚实的自评** | 把一个做成主动作，用户会顺着按，调度器拿到垃圾数据 | `.recall-grid` / `.too-easy` |
| 页边批注 | 虚线框、小娜杯图标、贴在正文旁 | 建议，不改写你的答案 | 用户以为系统改了自己的答案 | `.margin-note` |
| 小娜杯 | 右下角咖啡杯 | 随时在，但不占主视觉 | 助手变成常驻面板，抢走注意力 | `.cup-anchor` |
| 台灯 | 右上角灯，开时发暖光 | 白天/夜晚 | 深浅模式沦为设置项里的开关 | `.lamp-toggle` |
| **学习者的笔迹** | **楷体** | 这一段是你自己写的，不是系统写的 | 用户与系统的文字混为一体 | `.answer-field textarea`、`.own-words`、`.scratch-pad` |

**楷体这一条特别重要。**产品里凡是学习者自己写下的字都用楷体，系统的字用无衬线。这是"她不替你写"在视觉上的直接兑现，学习页的对照区（我自己的说法 / 教材的说法）全靠它一眼分辨。

## 4. Studio 的物件（2026-07-25 新增）

| 物件 | 材质 / 形态 | 承担的语义 | 拿掉会误解什么 | 原型中的呈现 |
|---|---|---|---|---|
| 工作夹 | 牛皮纸夹，装散页 | 项目容器；里面的东西还没定序 | 会被当成另一本课程本 | `.studio-workspace` + `.folder-tab` |
| 纵向标签 | 左边缘竖排，圆角朝左，当前那个与夹内纸同色并压住边缘 1px | 夹插在架里露侧边——和本子的横向标签是两类东西 | 与 Study 的书立混淆，两域看起来是同一种容器 | `.folder-tabs` / `.folder-tab` |
| Brief 便条 | 别在夹子最前面、始终露着 | 讲给谁、要他们明白什么；所有排序判断都回到它 | 表达目标沦为一个可折叠字段，排序失去依据 | `.brief-slip` |
| 观点卡 | 一张卡＝**我要说的一件事**，依据挂在它下面 | 排的是自己的表达逻辑，不是素材 | 退化成素材排序器，离"自动生成"只剩一步 | `.point-card` |
| 卡片顺序 | 带序号，可上下挪 | **顺序本身就是结构**，不另设"结构"对象 | 需要额外发明一个大纲/结构面板 | `.point-order` / `.point-move` |
| 素材堆 | 右栏一叠，可上传 | Read 层：这个夹子手头有什么 | 素材来源不明，或与 Study 真值混淆 | `.material-pile` |
| **复印件** | **虚线边 + "原件在高等数学"回链** | 从 Study 取来的是副本；**原件还在本子里，Studio 改不动它**；且这是"截至取用那一刻"的一份 | 用户以为 Studio 会改动课程内容；只读语义要靠文字解释 | `.material-slip--copy` |
| 堆上的目录 | 贴在素材堆上的一行，可翻开 | Material Index 层：这堆里有什么，可核对可修正 | 索引被当成一个要去的地方，或完全不可见不可审 | `.pile-index` / `.pile-index-list` |
| 铅笔观点卡 | 虚线 + 铅笔色 + 空心序号，配落墨/改写/抽走 | 小娜拟的，**落墨才算数**；逐张参与，不是整份放行 | 生成内容与已确认内容混为一谈，用户失去逐条把关的机会 | `.point-card--pencil` |
| 成件 | 底栏的一个**动作**，不是一个地方；**还有铅笔卡时锁定** | Writer 层：顺序定了才装订；**形式到这一步才选** | 用户以为要先选 PPT/文档；或把没过目的大纲直接装订出去 | `.bind-bar` |

**复印件是本次最重要的一条物化。**架构文档的 `SourceSnapshot` 只读语义原本要靠一张"写入边界"说明卡来解释（P3 文案）。改成复印件之后，语义由材质承担：**你拿走的是复印件，原件还在本子里**——说明卡因此被删除。

用词经过一次校正：不是**复写件**（垫复写纸、与原件同时产生），而是**复印件**（原件早已存在，事后另取一份）。这不是措辞讲究——`SourceSnapshot` 带 revision，表达的正是"截至取用那一刻的一份，原件后来改了这份就旧了"，只有复印件承载得了这层意思。

**四层框架的落法。**`DECISIONS.md` 的四层映射（`Read → Material Index → Deliverable Planner → File Writer`）是 Studio 的骨架，但**不得渲染成四个等权标签页**。Study 同样有这四层（Learning Index / Learning Planner / Output Writer），却从不暴露它们——它露出的是扉页/计划/学习/练习/评估。把后端管线当成用户信息架构，正是界面原则第 8 章禁止的做法。四层的权重是：素材是地方，索引是标签，Planner 是唯一主工作面，Writer 是动作。

## 5. 材质与色彩的分配

| 材质 | 用于 | 令牌 |
|---|---|---|
| 象牙纸 | 课程本内页、对话纸、主要纸面 | `--paper` / `--paper-strong` / `--paper-soft` |
| 牛皮纸 | 杂记本、工作夹 | `--manila` / `--manila-line` |
| 暖木桌面 | 书桌底 | `--desk` / `--desk-hi` / `--desk-lo` |
| 紫（唯一强调色） | 当前项、主动作、小娜 | `--purple` 家族 |
| 暖灯光 | 夜晚台灯 | `--desk-glow` / `--lamp-glow` |
| 楷体 | 学习者亲手写的字 | `"KaiTi", "STKaiti"` |

**全部颜色必须经由设计令牌**，明暗两套各一份；两个主题里都不允许新增硬编码色值。

## 5.5 已定方向、尚未实现的物件

以下两件已由 owner 确认方向，实现前先回本节对齐。

**书堆（课程资料 / 知识库，Study）——已于 2026-07-26 实现。**出处是最初的场景表
（`2026-07-06-desk-notebook-frontend-vision.md:90`「桌角书堆＝当前课程 READ 材料/知识库」）。
注意它与**书立**是两件不同的东西：书立立的是**其余课程本**（换本＝换课程空间，同文件 :96），
即当前已实现的顶边标签；书堆立的是**参考资料**。

- 形态：立在桌角的一排书/资料，需要时抽一本；**不是一个可浏览的知识库空间**。
- 语义：**参考书立着（不常翻），笔记本摊开着（天天写）**——姿态差别本身就说明"材料是按需
  调用的参考，不是铺开的主线"。
- 明确不做：把知识库做成一个可浏览的空间。它是最诱人的"输入错觉"制造机——条目变多的感觉
  极像学习，而重构量为零；且通不过删除测试（去掉它，学习页照样按需调出材料）。
- 系统抽取的知识点（Learning Index）与 Studio 的 Material Index 同层，因此**同样待遇**：
  贴在书堆上的目录，可翻开核对与修正，不占入口。
- 与"课程地图"（这门课讲了什么、我哪块弱）区分开：那是知识点及其状态，不是材料集合，
  将来若做应从评估页长出来，不是从书堆长出来。

**铅笔观点卡（Planner 审阅，Studio）——已于 2026-07-26 实现。**0.4.0 已有的 planner 交互是
`hermes_core/tools/user_interaction_tool.py` 的 `review_outline`：把大纲作为一整块 Markdown
弹给用户，三个选择「通过 / 补充要求 / 自行编辑」。它是**一次性的全有或全无**，大纲不可分条操作。

- 升级方向：小娜拟的观点卡以**铅笔卡**出现（虚线、铅笔色），用户**逐张**落墨 / 改写 / 抽走 /
  挪动；**只有落了墨的卡片进入顺序**。
- 语义：「内容是小娜制作，但项目是用户参与的」由此有了具体形状；且与 Study 的铅笔/落墨
  是同一条法则，不发明新语言。
- 约束：铅笔卡未清空前不得"成件"——不能装订一份还没确认的大纲。
- Brief 需要可编辑，并提供"和小娜一起理清"的入口（对应 review_outline 的"补充要求"）。
- Planner 是通用的，不只服务 PPT；卡片与顺序不得出现任何格式专属词汇。

## 5.5.1 材料阅读器：一个壳，两个动作

材料面板在两域共用同一个壳（贴右边缘、工作面可见、一个动作关掉，与小娜聊天框同族），
但**里面唯一的动作各不相同**——这决定了它不会变成一个"可以住下来"的阅读器：

| | Study | Studio |
|---|---|---|
| 打开的是 | 从书堆抽出的**参考书** | 手里的**复印件**（材质跟着复印件：去饱和） |
| 唯一动作 | **用自己的话记下来** → 落到学习页的重构循环 | **作为某条的出处** → 挂到观点卡下面 |
| 次级动作 | 无 | 去看原件（跳回 Study 原位置） |

**Study 侧刻意不做高亮/划线/摘录库。**高亮是典型的"感觉很努力而学习收益为零"的行为，
正是机制修订要防的东西。对一段材料唯一能做的事是把它转成自己的话。

**复印件的点击行为：**点开的是**副本本身**；"去看原件"是面板里的次级动作。反例是早期实现
——点一下复印件直接跳回 Study，等于"你要看材料？那你别做项目了"。

**窄屏：**书堆整条被隐藏，底部"参考"是唯一入口，因此它先打开一个**书架**让人挑，再进具体
一本。窄屏没有"旁边"可言，面板占满，但仍是可关掉的一层，不是新页面。

## 5.6 文案规约

从 2026-07-26 的 Study 文案审查（`docs/superpowers/reviews/2026-07-26-study-copy-clarity-review.md`）
固化下来的三条，适用于两个域：

1. **内部隐喻不上界面。**铅笔/落墨、复印件、书堆这些物性由**材质**承担，界面文字必须说人话
   （「就按这个来」而不是「落墨生效」，「小娜拟的 / 我确认过的」而不是「铅笔草稿 / 已落墨」）。
   物性是给设计者的词汇，不是给用户的术语。
2. **工程语言不上界面。**"安全节点""未提交修改""生命周期分页"这类词只属于文档和代码。
   安全确认只回答一个问题——**走了会不会丢东西**——不在那一刻教用户产品的状态模型。
3. **来源行统一为 `来源 · 时间`**，来源在前、时间在后，任一项缺失即省略。反例：「昨天 · 来自
   对话」「最近保存 今天 13:42」。格式不统一，用户就建立不起"小字＝来源"的稳定预期。

另有一条命名习惯：**标签说"你在这儿能干什么"，不说"这是什么容器"**（「今天要复习」优于
「本课卡片盒」）；并且不加当前上下文已经给出的前缀（用户已经在这本课程本里，"本课"是废字）。

## 6. 禁止的物化

1. **不做无限画布。**创作面是有界的，观点卡形成**一条序列**，不是自由二维坐标。
2. **不做幻灯片排序器。**那是 PPT 优先，与"Studio 不等于 PPT"直接冲突。
3. **不做装饰性拟物。**任何材质、纹理、阴影、翻页效果都必须通过第 0 节的第三列检验：拿掉它，用户会误解什么？答不上来就删。
4. **不引入第二套域色。**Studio 与 Study 共用紫色家族（迭代 1 曾试过绿色，已否决）。
5. **不用红色未读徽标制造愧疚。**计数用低强调数字；杂记本连计数都不做。

## 7. 对实现的约束

- 每个物件在代码中必须有可识别、可搜索的类名，且类名要说物件而不是位置（`.material-slip--copy` 而不是 `.right-card-2`）；
- 物性关系必须在明暗两套下都成立。已验证的两条基准：**当前书立标签的背景 === 课程本纸色**；**当前夹标签的背景 === 夹内纸色**。任何一处不等，融合即断裂；
- 标签与纸面的 `-1px` 重叠是"连成一体"的实现手段，容器的列/行间距不得把它们分开；
- 新增任何物件，先在本文档登记它的三列，再写样式。

## 8. 未决事项

1. **牛皮纸撞色。**杂记本与工作夹目前共用 `--manila`。两者不会同屏出现（一个在 Study 书桌、一个在 Studio），暂靠"本 vs 夹"的形状区分，但同一材质承担两种含义长期是隐患。待定：给工作夹换一种纸，或接受形状区分。
2. ~~虚线边撞义。~~ **已解决（2026-07-25）：虚线一律归铅笔家族（"尚未生效"），复印件不得使用虚线。**
   复印件改为**偏灰（`saturate(0.55)`）＋ 底下垫一层的硬投影**——它是另一张纸，不是一份未生效的草稿。
   这条冲突必须在 Studio 引入铅笔观点卡之前解决，因为那时两者会同屏。
3. **观点卡的粒度。**当前定义是"一个观点"，素材作为依据挂在下面。若需允许纯素材的收集态（还没提炼出观点就先摆着），则需两类卡片，复杂度上一个台阶。
4. **与架构文档 §7 Deferred 的冲突。**§7 列明"自由画布、时间线、页面编辑器或自动排版范式"暂不决定，而观点卡序列已构成一种明确的创作范式。它由四层框架与物化原则推出、而非任意选择，但 §7 需相应更新。
