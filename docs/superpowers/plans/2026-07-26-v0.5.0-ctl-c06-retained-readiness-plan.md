# CTL-C06 retained platform readiness JIT plan

**Control:** CTL-C06 / retained mainland + SEA readiness
**Base:** `366e337c` (`main`, 2026-07-26)
**Owner:** Codex, authorized by the product owner on 2026-07-26
**Worktree:** `.worktrees/c-track-c06-retained-readiness`
**Branch:** `codex/v050-c06-retained-readiness`

## Objective

Turn the frozen six-platform set into an honest desktop runtime contract:

- `mainland_cn`: Weixin, QQ Bot, DingTalk
- `sea`: Telegram, WhatsApp, Email

C06 closes deterministic local readiness and produces a real-credential smoke
matrix for the owner. It does not delete or reinterpret legacy credentials,
profiles, sessions, jobs, channel-directory records, or home targets; those
upgrade/data semantics remain CTL-C07. Installer provenance, advisory review,
and final release approval remain CTL-G01/Q.

## Demonstrated gaps at start

1. Desktop requirements intentionally omit DingTalk. The current official
   `dingtalk-stream==0.24.3` metadata requires `websockets>=11.0.2` without the
   obsolete `<13` cap, and imports against the locked `websockets==15.0.1`;
   C06 must pin, bundle, and verify that resolved transport instead of
   preserving the stale conflict claim.
2. C05 bundles the locked WhatsApp bridge packages but the adapter still
   launches a system `node`. The signed runtime therefore does not own the
   executable needed by the retained SEA adapter.
3. New WhatsApp sessions are written to `platforms/whatsapp/session`, while the
   identity reader still searches `whatsapp/session`; bridge media caches also
   fall back through `HOME/.hermes`. New profile sessions and identity aliases
   can therefore diverge.
4. QQ voice conversion tries to wrap arbitrary failed audio bytes as raw PCM.
   That can create a syntactically valid but false WAV/transcript instead of an
   explicit degraded-audio result. The gateway child also lacks a deterministic
   path to the already bundled ffmpeg executable.

## Forbidden scope

- no removed-platform restoration or dynamic platform registration
- no destructive legacy credential/session/job/home cleanup or silent migration
- no A/B/Study or unrelated product UI work
- no new cloud account, credential, message, or external recipient operation
  without explicit owner action
- no per-adapter leaf Gate or repeated bundle loop
- Codex does not run the Python bundle; the owner may run one C06 integrated
  bundle after source review if reviewer evidence requires it

## Implementation sequence

1. Pin and declare the modern-compatible DingTalk SDK set; extend runtime
   sentinels/import checks and add compatibility regressions.
2. Bundle a pinned Windows x64 Node LTS executable from the official Node
   archive with SHA-256 verification; make WhatsApp prefer the bundled
   executable and fail clearly if none is available.
3. Unify WhatsApp session/identity/cache resolution under the active
   `KABUQINA_HOME`, retaining read-only legacy-path compatibility for C07.
4. Remove QQ's false raw-PCM conversion, resolve bundled ffmpeg explicitly,
   and prove unavailable SILK decoding yields the visible degraded result.
5. Run focused six-adapter contracts serially, bridge tests, Python runtime
   verifier tests, C0 no-refresh audit, and source hygiene. Produce one C06
   evidence/review stack plus an owner-only real-account smoke matrix.

## Rollback and compatibility

Rollback is the C06 commit series only. Existing legacy WhatsApp session files
remain readable in place; no session data is copied or removed. Explicit
`bridge_script`, `session_path`, and development system-Node overrides remain
available. QQ built-in ASR and QQ-provided WAV continue to work when optional
SILK decoding is absent; only the fabricated raw-PCM fallback is removed.

## Exit evidence

- DingTalk SDK and Alibaba card dependencies are present in desktop inputs and
  import with the modern locked `websockets` runtime
- verified runtime contract requires the pinned Node executable, DingTalk
  modules, and all six retained adapters
- WhatsApp uses one active-profile session path for bridge auth and identity
  mapping, and one active-profile cache root for downloaded media
- QQ audio conversion either uses QQ ASR/WAV, a real decoder, or reports an
  explicit recognition failure; it never fabricates PCM
- focused Core/Python/Node tests, no-refresh C0 audit, and `git diff --check`
  pass serially
- real-account smoke status is recorded per platform without converting
  missing owner credentials into a false green result
