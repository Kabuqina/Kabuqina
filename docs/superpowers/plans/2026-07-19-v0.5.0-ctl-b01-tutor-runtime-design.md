## 0. 决策摘要

1. Tutor 是用户显式启动的、可恢复的 **structured learning activity**；普通 Chat
   不做意图识别，不获得 checkpoint，也不改变现有 Agent turn 合同。
2. Tutor 使用独立的 `TutorGraphEngine` 和 `TutorGraphStateV1`，放在
   `hermes_core/agent/graph_engine/` 的新文件中；它复用现有 provider routing，
   但不嵌进 `TurnState`、不调用第二个 `AIAgent.run_conversation()`、不改变
   `build_agent_graph()` 的无 checkpointer 合同。
3. 持久化由 core 的 `LearningCheckpointStore` port 控制；v0.5 使用独立
   `tutor_runtime.db`（schema v1），不升级 v0.4 会打开的 `learning.db`。现有
   `learning_activities` 继续是不可恢复的追加事件；Tutor terminal event 通过 runtime DB
   outbox 幂等投影，不能反过来成为 checkpoint 真值。
4. 身份键固定为 host 注入的
   `(owner_id, space_id, activity_kind, activity_id)`；chat session、gateway chat、
   browser tab、模型参数都不能提供或覆盖这些字段。
5. 生命周期增加可恢复的 `interrupted`：
   `created → running → waiting_for_learner → running`，`running` 可因进程中断进入
   `interrupted`，再由显式 recovery 回到 `running`；终态只有
   `completed | blocked | cancelled`。
6. learner check 与 tool approval 使用不同 type、ID namespace、store、API、UI 和
   timeout。learner answer 永不授予工具副作用权限。
7. 模型调用只走 `TutorProviderPort.execute_once()`：SDK retry=0、v0.5 provider fallback=0；
   每个物理 attempt 在调用前写入 durable reservation，crash 后 reservation 仍算消耗。
   node、attempt、token、wall-clock 和总活动检查次数超限原子落为 `blocked`。
8. v0.5 的 structured Tutor 入口只在 desktop host 开放。Gateway conversation 保持
   unbound；后续若开放 gateway Tutor，必须另做投递、身份、并发和隐私评审。
9. L-2 不判断自由文本“答对/答错”：它只验证一次 learner response 已提交，然后以
   `participation_only` 完成，不写 mastery。只有绑定受信 rubric 的 deterministic grader
   才能在 L-3 返回 correct/incorrect 并驱动 advance/remediate。
10. 产品不支持从 v0.5 带 Tutor 数据原地降级到 v0.4。官方 installer/updater 必须阻止；
    降级前须用 v0.5 prepare-downgrade 导出并清除独立 runtime DB。已手工降级者须重装
    v0.5 清理，或在完全退出应用后删除三个精确 runtime DB 文件。

## 1. 当前代码事实与差距

### 1.1 可复用事实

- `hermes_core/agent/graph_engine/engine.py` 的通用 Agent graph 每个 user turn 调用一次，
  编译时无 checkpointer；`TurnState` 是普通 Agent loop 的兼容合同。
- `hermes_core/providers/chat_completions.py` 已集中 provider/model/auth/API-mode 解析；Tutor
  可以复用解析与 transport adapter，但不能复用包含内部 retry/fallback 的 `call_llm()`。
- `learning.db` 已使用 WAL、`BEGIN IMMEDIATE`、busy retry、`secure_delete=ON`，并由
  `LearningExecutionContext` 强制注入 owner/space。
- `python/src/learning_owner.py` 已建立 desktop owner；desk Study route 不接收请求中的
  `owner_id`。
- `tauri/src/study.rs` 已是 Study loopback command 的唯一 Rust bridge，具有 path-id
  校验和结构化错误映射。

### 1.2 不能直接复用的部分

- `learning_activities` 只有 `activity_type/detail_json/created_at`，是历史事件，不含
  revision、状态或 pending interrupt；把它原地改成 run 表会破坏现有 quiz/review 读者。
- `learning_schema_version` 当前为 v1，且 v0.4 不会拒绝未知高版本、owner delete 只枚举五张
  v1 表；因此不能把 Tutor 表加进 `learning.db` 后声称 downgrade fail closed。
- 通用 Agent graph 的 interrupt 是停止正在执行的 agent/tool，不是等待学习者回答的
  durable learner check。
- 当前 `/api/desk/study/activities` 是历史事件摘要接口，不能静默改成 resumable run API。

## 2. 分层与代码归属

```text
Web Study surface
  -> Tauri study commands                 tauri/src/study.rs
    -> loopback activity-run routes       python/src/desk_server/routes/study_activity_routes.py
      -> desktop owner/context injection  python/src/learning_owner.py
        -> TutorActivityService           hermes_core/learning/tutor_activity.py
          -> TutorGraphEngine             hermes_core/agent/graph_engine/tutor_*.py
          -> LearningCheckpointStore      hermes_core/learning/checkpoint_store.py
             -> tutor_runtime.db adapter  hermes_core/learning/tutor_runtime_store.py
          -> TutorProviderPort            resolved single provider / single physical attempt
```

边界规则：

- Core 拥有 graph、状态机、CAS、预算、错误 taxonomy 与 activity 语义。
- Python desk 只负责 host owner、loopback request/response、单进程 execution registry 和
  readiness；不复制 graph 或 scheduler。
- Rust 只做认证后的 loopback bridge 与 path/body 大小校验。
- Web 只渲染 snapshot/interrupt 并提交显式动作；不在 localStorage 保存 checkpoint。
- `learning.db` 继续由 `LearningStore` 管既有 Study 真值；`tutor_runtime.db` 只管
  resumable run/checkpoint/provider reservations/outbox。跨库操作由 desktop composite
  service 编排，不能假装 SQLite 跨文件原子提交。
- v0.5 L-2 是 toolless Tutor graph。未来节点需要工具时只能走现有 tool registry 与
  approval backend；不能由 learner answer 绕开审批。

## 3. 身份、版本和公开 wire

### 3.1 ID 与大小规则

- `space_id/activity_id/interrupt_id/idempotency_key`：1–128 字符，只允许
  `[A-Za-z0-9._:-]`；activity/interrupt 默认由 host 生成随机 opaque id。
- JSON request 上限 32 KiB；`goal` 上限 4,000 Unicode code points；单个 learner
  answer 上限 8,000；`input_refs` 最多 16 个。
- 所有 schema 都显式携带整数 `schema_version=1`；未知版本 fail closed。
- public wire 不接受 `owner_id`。Core `LearningActivityRequestV1` 在 host 校验 space 后
  注入 owner；模型永远看不到可写 identity 字段。

Core/DB 唯一 key type 固定为：

```text
LearningActivityKeyV1 {
  owner_id: host-injected string
  space_id: opaque id
  activity_kind: "tutor" | "review" | "practice"
  activity_id: opaque id
}
```

repository、checkpoint、attempt、interrupt binding 与 public path adapter 都消费这个 type；
不存在接受三元 key 或裸 `activity_id` 的 overload。

### 3.2 Start

`POST /api/desk/study/activity-runs`

```text
LearningActivityStartV1 {
  schema_version: 1
  space_id: opaque id
  activity_kind: "tutor"                  # review/practice 保留，L-2 返回 not_ready
  idempotency_key: opaque id
  goal: string
  input_refs: [
    { kind: "artifact" | "item" | "source",
      id: opaque id,
      version?: integer,
      sha256?: lowercase hex }
  ]
}
```

Host 对验证/NFC 规范化后的 start body（排除 `idempotency_key`，包含 schema、space、kind、
goal 与保持原序的 refs）执行 RFC 8785 canonical JSON，再保存
`request_fingerprint = sha256(canonical_utf8)`。idempotency namespace 固定为
`(owner_id, space_id, activity_kind, idempotency_key)`：

- 同 namespace + 同 fingerprint：返回既有 snapshot，不创建第二个 activity；
- 同 namespace + 不同 fingerprint：409 `study_activity_conflict`，reason 固定
  `idempotency_payload_mismatch`，零模型调用；
- 不同 `activity_kind` 是不同 namespace，但所有 DB key、repository key 与 route 都必须显式
  携带 kind，不允许靠 activity id 猜 kind。

引用由 host 在进入 graph 前解析/授权；checkpoint 只保存 pinned ref metadata 和 bounded
excerpt，不保存 raw source document。

### 3.3 Resume / recover

`POST /api/desk/study/activity-runs/{activity_kind}/{activity_id}/resume`

```text
LearningActivityResumeV1 =
  | {
      schema_version: 1
      space_id: opaque id
      expected_revision: integer >= 0
      mode: "answer"
      interrupt_id: opaque id
      answer:
        | { type: "free_text", text: string }
        | { type: "choice", selected: [opaque option id] }
        | { type: "step", text: string }
    }
  | {
      schema_version: 1
      space_id: opaque id
      expected_revision: integer >= 0
      mode: "recover"
    }
```

- `answer` 只接受 `waiting_for_learner`；必须同时匹配 owner、space、activity、interrupt
  和 revision。
- `recover` 只接受 `interrupted`；不得附带新 learner answer。
- duplicate/stale/cross-owner/cross-space 请求在 graph 前失败；不产生模型调用。

### 3.4 Cancel、get 与 list

- `POST /api/desk/study/activity-runs/{activity_kind}/{activity_id}/cancel`：body 为
  `{schema_version, space_id, expected_revision}`。CAS 胜者决定 cancel/answer race；失败方
  收到 conflict 并刷新 snapshot。
- `GET /api/desk/study/activity-runs/{activity_kind}/{activity_id}?space_id=...`：只返回同
  owner/space/kind 的 snapshot；跨 scope 与不存在统一为 404。
- `GET /api/desk/study/activity-runs?space_id=...&activity_kind=...&status=...&limit=...`：
  kind 必填、bounded list，不返回 checkpoint content。

对应 Tauri commands 冻结为：

`cmd_study_activity_start/get/list/resume/cancel`。

### 3.5 Snapshot 与 learner interrupt

```text
LearningActivitySnapshotV1 {
  schema_version: 1
  activity_id: opaque id
  space_id: opaque id
  activity_kind: "tutor" | "review" | "practice"
  status: "created" | "running" | "waiting_for_learner" | "interrupted"
        | "completed" | "blocked" | "cancelled"
  revision: integer
  label: string
  latest_output?: { kind: "explanation" | "feedback", markdown: string }
  interrupt?: PublicLearningInterruptV1
  terminal?: {
    outcome: "completed" | "blocked" | "cancelled"
    completion_basis?: "participation_only" | "deterministic_correct"
    reason_code?: enum
  }
  created_at: ISO-8601
  updated_at: ISO-8601
}
```

Internal `LearningInterruptV1` 保留 requirements 要求的 owner/space binding：

```text
LearningInterruptV1 {
  schema_version: 1
  interrupt_id: opaque id                 # namespace: lint_...
  kind: "learner_check"
  owner_id: host-injected owner
  space_id: opaque id
  activity_kind: "tutor" | "review" | "practice"
  activity_id: opaque id
  checkpoint_revision: integer
  prompt: {
    markdown: string
    options?: [{ id: opaque id, label: string }]
  }
  expected_input: "free_text" | "choice" | "step"
  created_at: ISO-8601
}
```

Public projection删除 `owner_id`，其他 binding 保留。Tool approval IDs 继续使用其现有
namespace/store；任何 API 都不能拿 learner interrupt id 调 approval endpoint，反之亦然。

## 4. 状态机与并发语义

```text
start: created(r0) -> running(r1)
running -> waiting_for_learner(r+1) -> running(r+1)
running -> interrupted(r+1) -> running(r+1)       # explicit recover only
created|running|waiting_for_learner|interrupted -> cancelled(r+1)
running -> completed|blocked(r+1)
```

`completed/blocked/cancelled` 为终态；只能通过新的 Start request 创建新 activity，不能
resume 原 id。

### 4.1 CAS 规则

- 每次状态/graph checkpoint 修改都在同一个 `BEGIN IMMEDIATE` transaction 中更新
  activity run 与 checkpoint，条件为 `revision = expected_revision`。
- 成功 transition 将 revision 精确加一；run revision 与 checkpoint revision 永远相等。
- answer claim 先把 answer 写入 checkpoint、清掉 pending interrupt、置 `running`，再调用
  模型。进程若随后崩溃，answer 已被消费一次，recover 从该 state 继续，不要求学习者重答。
- worker 完成节点时仍用 claim 后 revision CAS。若 cancel 已先提交，worker save 失败且
  不得复活 activity。
- client timeout 不能推断请求失败；客户端必须 GET snapshot，再决定重放。Start 依靠
  idempotency key；resume 依靠 revision/interrupt 做安全重放。

### 4.2 Crash / restart

- desk child 持有内存 execution registry：
  `(space_id, activity_kind, activity_id) -> execution_id/cancel handle`。
- persisted `running` 但 registry 无相同 execution 的记录被惰性 reconciliation 为
  `interrupted`；只由验证过 desktop owner 的 desk service 执行，不扫描/修改 gateway owner。
- reconciliation 不调用模型、不投递消息、不自动 resume。用户点击“继续”后提交
  `mode=recover`。
- disconnect 发生在 `waiting_for_learner` 时保持原 checkpoint 与 revision，不变更状态。

### 4.3 Product ActivitySummary 映射

- `waiting_for_learner -> awaiting_user`
- `interrupted -> interrupted`
- `created/running -> running`
- `blocked/completed/cancelled` 同名

`ActivitySummary` 是 `tutor_activity_runs` 的 bounded read model，`source_kind` 固定
`learning_activity`、`source_id={activity_kind}:{activity_id}`；它不复制 checkpoint 或
learner content。

## 5. Graph 合同

### 5.1 独立状态

新增 `TutorGraphStateV1`，不扩展普通 Agent `TurnState`：

```text
TutorGraphStateV1 {
  schema_version: 1
  graph_schema_version: 1
  policy_version: "tutor-v1"
  owner_id / space_id / activity_id / activity_kind
  phase: "start" | "explain" | "handoff" | "acknowledge" | "terminal"
  goal: bounded string
  input_refs: bounded pinned refs
  turns: bounded [{role: "tutor"|"learner", kind, content}]
  learner_evidence: bounded structured values
  pending_interrupt?: LearningInterruptV1
  branch?: {decision, policy_version, reason_code}
  budget: TutorBudgetStateV1
  latest_output?: bounded markdown
  terminal?: structured outcome
}
```

禁止保存 client、callback、DB handle、API key、tool credential、raw source bytes、gateway id、
browser tab id、完整 provider response、chain-of-thought 或自由 exception。序列化前递归
JSON-safe 校验、禁止字段扫描、单字段 cap 和总 checkpoint 256 KiB cap；超限进入
`blocked(checkpoint_too_large)`。

### 5.2 L-2 最小图

```text
START -> validate_context -> explain_bounded_unit -> handoff_to_learner
handoff_to_learner -> learner_check interrupt -> END(segment)

resume(answer) -> validate_answer_binding -> acknowledge_submission -> complete
```

- `handoff_to_learner` 是结构边；explain 不能直接自由续写到另一个概念。
- L-2 只发一个 `evaluation_mode=acknowledgement` 的 learner check。answer 通过 type/size/
  non-empty deterministic validation 后记录 `submitted`，终态是
  `completed(completion_basis=participation_only)`；UI 只能说“已提交/本节已结束”，不得说
  “答对/已掌握”，也不写 evaluation/mastery/weak-point。
- L-2 没有 `evaluate -> remediate` 边、没有自由文本 grader、没有模型 feedback call。
  correct/incorrect 与 remediate 从 L-3 才开放，避免实现者为任意 Tutor goal 猜 rubric。
- graph 每次只运行一个 bounded segment。持久化由 service 在 segment 前后显式执行，
  不使用 LangGraph 内部 pickle/checkpoint schema。
- L-2 不暴露 tools。未来工具节点只接收受信 `TutorServices` port，并复用既有 approval。

### 5.3 Deterministic evaluation truth（L-3 consumer contract）

所有 learner check 都携带 host 冻结的 `TutorCheckSpecV1`：

```text
TutorCheckSpecV1 {
  schema_version: 1
  check_id: opaque id
  expected_input: "free_text" | "choice" | "step"
  evaluation_mode: "acknowledgement" | "deterministic"
  rubric_ref?: {
    source_kind: "activated_quiz_item" | "trusted_builtin_rubric"
    source_id: opaque id
    source_version: integer
    source_sha256: lowercase hex
  }
  normalization_policy: versioned enum
  correct_action?: "complete" | "advance"
  next_unit_ref?: { source_id: opaque id, source_version: integer, source_sha256: hex }
}
```

- L-2 强制 `acknowledgement`，并禁止 rubric/correct_action/next_unit_ref；忽略/拒绝模型输出的
  rubric/expected answer。
- `deterministic` 只允许引用当前 owner/space 下的 activated quiz item，或代码中受审计的
  builtin rubric；AI draft、Tutor explanation、模型生成 expected answer、learner 自报均不是
  可信 rubric，且必须有 host-supplied `correct_action`。rubric missing/stale/hash mismatch 进入
  `blocked(source_missing)`，不得回退 LLM 判分。
- grader input 是 `(owner/space/kind/activity/check/revision, normalized_answer,
  pinned_rubric)`；identity 由 host 注入。grader 是 pure function，无模型、网络、工具或写入。

```text
DeterministicEvaluationResultV1 {
  schema_version: 1
  evaluation_id: opaque id
  activity_id / activity_kind / check_id / checkpoint_revision
  mode: "acknowledgement" | "deterministic"
  outcome: "submitted" | "correct" | "incorrect" | "invalid"
  grader_id: string
  grader_version: string
  rubric_ref?: exact pinned ref
  answer_fingerprint: sha256(canonical normalized answer)
  evidence_codes: bounded enum[]
  evaluated_at: ISO-8601
}
```

结果保存 provenance/fingerprint/code，不在 run summary、日志或 telemetry 复制 learner answer。
`correct_action/next_unit_ref` 由 host 从 activated plan/builtin rubric 构造；模型不能填写。
`correct_action=advance` 必须同时有可验证 pinned `next_unit_ref`，否则 check spec 无效。

branch policy 固定为 `tutor-branch-v1`：

- `submitted -> complete(participation_only)`；
- `correct + correct_action=complete -> complete(deterministic_correct)`；
- `correct + correct_action=advance -> advance(next_unit_ref)`；
- `incorrect + remediation_count=0 -> remediate_once`；
- `incorrect + remediation_count>=1 -> blocked(remediation_exhausted)`；
- `invalid -> 原 check、revision+1 重新等待且零模型调用`；
- rubric/next-unit missing、stale、hash mismatch -> `blocked(source_missing)`。

L-3 可消费 correct/incorrect；L-2 只能产生 submitted/invalid。

### 5.4 Model generation 与 prompt injection

`TutorProviderPort` 只生成 bounded explanation/check prompt。它复用现有 provider/auth/
transport 解析，但禁止调用带内部 retry/fallback 的 `call_llm()`；逐 attempt 合同见 §7.1。
模型只输出 versioned JSON/typed result；adapter 负责 schema/size 验证，模型自由文本不能决定：

- owner/space/activity/revision；
- learner check 是否匹配；
- pass/fail 或 advance/remediate 最终分支；
- tool approval；
- checkpoint schema、budget 或 terminal transition。

learner answer、source excerpt、whiteboard text和模型结果全部按不可信内容处理。Prompt
明确以 data delimiters 包裹，但真正安全边界是 deterministic validation/CAS，而不是提示词。

## 6. 独立 Tutor runtime persistence v1

### 6.1 为什么必须是独立数据库

v0.4 的 `learning.db` reader 只 seed `learning_schema_version=1`，没有“发现未知高版本即拒绝”
逻辑；`delete_owner_data()` 也只枚举 v1 的 spaces/artifacts/items/activities/migrations。把 Tutor
表直接加进该文件会造成两个不可接受事实：旧 runtime 仍会写同一 DB，且“删除全部学习数据”
会遗漏 checkpoint。因此冻结：

- `learning.db` schema 和 v0.4 五表合同不因 L-1 改动；
- 新文件固定为 `%LOCALAPPDATA%\com.kabuqina.app\kabuqina-home\tutor_runtime.db`，
  使用独立 `tutor_runtime_schema_version=1`、WAL、busy retry、ACL 和 secure-delete；
- v0.5 Tutor runtime 对未知高于 1 的 runtime schema fail closed；这个保证只属于新 reader，
  不再声称 v0.4 会拒绝 `learning.db` v2。

### 6.2 表与一致 identity

### 6.4 Delete、降级禁令与恢复流程

- v0.5 `CompositeLearningDataService` 是 owner/space delete 的唯一入口。它先在 runtime DB 写
  deletion fence（后续 Tutor start/resume fail closed），再删除/compact `learning.db` scope，
  再删除/compact runtime rows，最后清 fence；crash 后重启继续，未完成时不报告成功。
- active/interrupted/waiting checkpoint 在 v0.5 不做时间 TTL；由显式 cancel、composite
  space delete、composite owner delete 处理。archive space 不等于 delete。
- **不支持带 Tutor 数据原地降级到 v0.4。** 仓库当前 `tauri.conf.json` 已声明
  `allowDowngrades=false`，L-1/Q-3 必须用真实 v0.5 candidate + 官方 v0.4 artifact 证明 NSIS/
  updater 均拒绝低版本；配置事实本身不算通过。
- 支持的降级流程是 v0.5 “准备降级”：导出并回读校验 `StudyOwnerBundleV2` → 用户确认 →
  close runtime handles → secure-delete/删除 `tutor_runtime.db`、`-wal`、`-shm` → 保留 schema v1
  `learning.db` → 卸载 v0.5 后安装 v0.4。备份供将来回到 v0.5 后导入。
- 已手工覆盖安装 v0.4 而未 prepare 的恢复：停止应用；首选重装 v0.5，执行 composite
  export/delete；若隐私目标只是清除且无需恢复，则在确认进程退出后精确删除上述三个
  `tutor_runtime.db*` 文件。不得宣称 v0.4 的“删除全部”覆盖 Tutor 数据。

真实旧版本矩阵必须使用 `CTL-G00` 冻结的官方 v0.4 artifact hashes 与
`v0.4.0^{}`/`f6229d96` runtime；自行从当前 source 改版本号构建不算旧版本证据：

1. 先由 v0.5 创建 pending/running/terminal Tutor fixtures，记录 runtime DB/hash/mtime；
2. v0.4 启动、Study 读写、export、owner delete 后，证明它不打开/修改 runtime DB；owner
   delete 留下 runtime DB 是**预期 red characterization**，用于钉住降级禁令；
3. 官方 installer/updater downgrade 被阻止；
4. v0.5 composite delete 同时清两库，且 WAL/SHM 无私密残留；
5. prepare-downgrade 后 v0.4 可正常读取保留的 learning.db；重装 v0.5 后 v2 backup 可回读。

### 6.5 Export/import 总量合同

新 `StudyOwnerBundleV2` 是单个 canonical JSON object：`learning_v1` 保留现有五 sections，
`tutor_runtime` 含 runs/checkpoints/attempt metadata；import 强制写入当前 owner，导入的
`running` 改为 `interrupted`、清 execution id，terminal run 不含 checkpoint。

Import 继续要求该 owner 在两库都为空。它先完整 parse/validate/canonical-hash，随后写
`tutor_import_journal` 与 owner operation fence；按 phase 写 `learning.db`、runtime DB，全部
成功后才清 journal/fence 并使数据可见。crash/restart 发现未完成 journal 时，按 owner 清理两库
本次插入并重新 compact，返回可重试失败；因为 import 前 owner 必须为空，不会误删既有数据。
因此 schema/size/hash 错误是零写入，进程崩溃也不会留下可见的半导入 owner。

所有层使用同一 UTF-8 serialized-byte 口径：

| 项 | 硬上限 |
|---|---:|
| `learning_v1` 子对象 | 16 MiB（保留现有 core limit） |
| 单 checkpoint | 256 KiB |
| owner nonterminal checkpoints | 12 个、合计 3 MiB；每 space 最多 6 个 |
| terminal run summaries | 每 owner 最近 1,000 条、每条 ≤1.5 KiB |
| pending outbox | 正常 ≤32 条；payload ≤512 B；existing runs terminal 时最多短暂增至 44 条 |
| `tutor_runtime` 子对象 | 6 MiB |
| manifest/structural overhead | 1 MiB |
| 整个 `StudyOwnerBundleV2` | 24 MiB |

- 第 13 个 owner resumable activity 或单 space 第 7 个返回
  `study_activity_conflict(activity_quota_exceeded)`；不通过删 checkpoint 腾 quota。
- terminal 超过 1,000 条时，仅在 outbox 已 delivered 后删除最旧 run summary；既有
  `learning_activities` terminal event 仍保存历史。该 retention 在 UI/backup 文档公开。
- provider attempt rows 在 terminal/outbox commit 后折叠成 run 的 numeric budget summary 并
  删除；delivered outbox 立即删除。undelivered outbox 达 32 时暂停新 start（已有 run 仍可
  terminal），使 runtime subsection 在最坏的 12 个 existing run 全部 terminal 后仍受 6 MiB cap。
- L-1 把 Rust file metadata/read cap 从当前 10 MiB 调到 24 MiB；loopback Content-Length、
  desk parser、core canonical re-serialization 都用 24 MiB。任一子 cap 或总 cap 超限时在任何
  DB write 前拒绝；不允许 Rust 接受、core 再以不同数字拒绝。
- export 生成后必须用同一 validator 回读并核对 section counts + SHA-256 才报告成功。
- 测试至少覆盖：12 个接近 aggregate 3 MiB checkpoint cap + 1,000 terminal summaries 的
  export→delete→import round-trip；24 MiB 边界前成功/后失败；v1 10–16 MiB fixture 经新 Rust
  bridge 可导入；payload/count/单 record 任一超限均零部分写入。

## 7. 预算、停止与失败

### 7.1 Tutor provider port 与 write-ahead budget

| 预算 | 每次 start/resume | 单 activity 总上限 |
|---|---:|---:|
| graph nodes | start 6 / resume 4 | 10 |
| physical provider attempts | start 2 / resume 0 | 2 |
| provider fallback candidates | 0 | 0 |
| reserved input tokens | 16,384/attempt | 32,768 |
| reserved output tokens | 2,048/attempt | 4,096 |
| wall clock | 90 s | 不跨用户等待累计 |
| learner checks | — | 1 |

`TutorProviderPort` 冻结为以下 plan / reservation / execution / settlement 接口，不能包一层
现有 `call_llm()`：

```text
resolve_plan(main_runtime) -> TutorProviderPlanV1
  # 只做本地 config/credential resolution；得到一个固定 candidate，无网络调用

reserve_attempt(activity_key, expected_revision, segment_id,
                candidate, input_token_reserve, output_token_reserve)
  -> AttemptReservation + new_checkpoint_revision

execute_once(reservation, typed_request, timeout_s <= 45)
  -> TutorProviderResult

settle_attempt(activity_key, attempt_id, result_code, numeric_usage,
               expected_revision) -> new_checkpoint_revision
```

- `TutorProviderPlanV1` 在 activity create 时固定并保存 hash，只含 provider/model/api_mode/
  endpoint identity，不含 key。`provider=auto` 只能在 create 时本地解析为一个 candidate；
  recover 不重新 auto-detect，不切 provider/model。
- `execute_once` 使用专用 single-attempt client factory：OpenAI/Anthropic SDK
  `max_retries=0`，transport 不循环，credential pool/fallback 禁用。v0.5 fallback candidate 数为
  **0**；以后开放必须改 schema/policy/test，不能配置暗开。
- 每次物理调用前，`reserve_attempt` 在 runtime DB 同一 CAS transaction 中：检查 segment/
  activity remaining → 增加 checkpoint reserved counters → 插入 `status=reserved` attempt row →
  commit；只有 commit 成功才允许发 HTTP。
- retry 不是 port 内部行为。orchestrator 只可在明确 retriable reason 后再调用一次
  `reserve_attempt`；第二次同样消耗 activity 上限。SDK/transport 若被测试发现产生第二个 HTTP
  request，Gate 直接失败。
- crash 留下的 `reserved` 在 recovery 时改 `unknown`，**永久按已消耗计算，不退款**；这样
  crash-before-call 虽保守损失一次额度，但 crash-after-call 永远不能绕过总预算。
- input reservation 使用已注册 model tokenizer；未知 tokenizer 采用
  `reserved_input_tokens = UTF-8 byte length` 的保守上界。output 在 request 的 `max_tokens`
  写入前全额预留。实际 usage 只用于观测，不返还 reserved budget。
- start 的首次 attempt 失败且第二次也失败，或任何 reservation 不足，原子进入
  `blocked(provider_attempt_exhausted|budget_exhausted)`。Resume acknowledgement 不调用模型。
- usage event/attempt row 只含 provider/model id、token/call/latency 数值、outcome/reason code，
  不含 goal、answer、prompt、output、source ref、endpoint secret 或 whiteboard text。

### 7.2 Terminal reason codes

`completed` 无 reason；`cancelled` 使用 `user_cancelled`；`blocked` 只允许：

`provider_unavailable | provider_timeout | provider_attempt_exhausted | invalid_model_output |
budget_exhausted | source_missing | remediation_exhausted | checkpoint_too_large |
policy_rejected | internal_error`。

message 在 API/Web 层由 code 映射；数据库和日志不保存原始 exception/response body。

### 7.3 HTTP error taxonomy

| HTTP | code | 语义 |
|---:|---|---|
| 400 | `study_activity_invalid_request` | schema/size/id/action 无效 |
| 404 | `study_activity_not_found` | 不存在或不属于当前 owner/space |
| 409 | `study_activity_conflict` | stale revision、interrupt mismatch、非法 transition、idempotency payload mismatch、quota |
| 503 | `study_activity_not_ready` | capability/provider/runtime 未就绪且尚未创建 run |
| 500 | `study_activity_internal_error` | 已 redacted 的非预期 host 错误 |

进入 graph 后的 provider/budget 失败优先返回持久化的 `blocked` snapshot，而不是只抛 HTTP
错误，确保 restart 后仍有诚实结果。

## 8. Threat model

| 威胁 | 强制控制 | 必测失败 |
|---|---|---|
| owner/space/kind 注入 | public body 无 owner；host context 注入；DB/API 全部使用四元 identity | cross-owner/space/kind 返回 404 且零模型调用 |
| idempotency payload swap | canonical request fingerprint 与 scoped key 一起持久化 | 同 key/异 payload 409 且零模型调用 |
| stale/duplicate answer | exact interrupt + revision CAS；claim 前验证 | duplicate、旧 tab、重放只一方推进 |
| cancel race | cancel/answer/worker commit 同一 revision CAS | 任一确定胜出，terminal 不复活 |
| crash mid-resume | answer write-ahead + running checkpoint + explicit recover | restart 不丢 answer、不重复消费 |
| learner/tool interrupt 混淆 | 不同 type/namespace/store/API/UI；learner answer不含 approval | cross-use 全拒绝、零副作用 |
| prompt injection | untrusted data delimiters + typed output + deterministic branch/identity | 内容伪造 owner/pass/tool call 无效 |
| checkpoint 泄密 | allowlist schema、禁止字段递归扫描、size cap、terminal clear | secret/raw source/gateway id 序列化失败 |
| enumeration | scoped composite key；跨 scope 与 missing 同 404 | timing/response shape 不泄露存在性 |
| provider retry/fallback 绕预算 | single-attempt client、write-ahead reservation、fallback=0、unknown 不退款 | crash/SDK retry/fallback 不能超过 2 次物理请求 |
| resource exhaustion | request/checkpoint/owner quota、24 MiB bundle、hard budgets | oversized body/state/bundle 在写入或调用前拒绝 |
| log/telemetry 泄漏 | code/id/numeric usage only；exception redaction | caplog 不含 answer/source/prompt |
| delete orphan | composite deletion fence + 两库 cleanup；未完成不报成功 | DB/WAL 无可读残留、crash 可继续 |
| schema downgrade | 独立 runtime DB + 官方 downgrade block + prepare/recovery；不声称 v0.4 fail closed | 真实 v0.4 red characterization + installer/recovery matrix |

## 9. Capability 与降级

- 新 capability id：`student-tutor-runtime`。L-1 只有 persistence/API 时仍为
