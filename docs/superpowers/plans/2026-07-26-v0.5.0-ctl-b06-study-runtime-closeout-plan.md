### Phase D · L-4 kq-kp v2 post-node — backend node DONE; surface rollout WAITING

- Post-node accepts only bounded visible assistant output after raw-block stripping.
- Deterministic rule extractor is the zero-call baseline; optional cheap model path requires its own reservation.

Implemented backend boundary: `kq-kp-post-v2` is a dependency-light, zero-call post-node that strips complete and

Markdown definitions/headings, ignores code fences, never trusts the legacy JSON payload, and performs no capture,
branch, provider or store action. Usage telemetry now reuses the same raw-block sanitizer, including truncated final
blocks.

Production rollout remains waiting rather than being overstated: current Web chips consume the legacy block and the
ordinary `LegacyRunResult` cannot gain an ad-hoc metadata key. Until the structured Desktop/Gateway/export/TTS
consumer contract has parity, desktop response text is not stripped and H1 remains enabled. This rollout may touch
the Web/A hot surface only after its owning handoff; it will be a separate final commit before H1 retirement.

### Phase E · S-2 whiteboard runtime — DONE

- Implement the S-0 exact `whiteboard_snapshot` contract, item CAS, idempotency, quotas, lineage and immutable saves.
- Use existing learning DB + common writer/owner operation fence; no new database or browser persistence.
- Add trusted desktop source APIs for working save/load, snapshot/restore/attach/export/delete; no Web editor yet.
- DOM/SVG+KaTeX is the declared consumer; no dependency/package/bundle change.
- Export/import/delete/near-cap/concurrency/crash tests prove the frozen 16/24 MiB composition remains coherent.

Implemented without a schema-v2 table: the exact six-type scene contract and mutable working state use the existing
`learning_items` table; immutable deterministic-review snapshots use `learning_artifacts`. Generic item/artifact/
activity writers reject the reserved whiteboard kinds, so quota, CAS and attachment policy cannot be bypassed.
Working saves hold the common cross-process coordinator plus one `BEGIN IMMEDIATE`, enforce revision CAS and keep the
most recent 64 exact idempotency fingerprints; an evicted replay can only stale-conflict, never commit again.

Snapshot lineage, parent revision, max-eight count, 240/256 KiB scene/envelope limits and 3/4/8 MiB activity/space/
owner quotas are checked inside the write transaction. Restore advances working CAS; attach is the only activation
path; delete requires an exact descendant/active-attachment preview, leaves validated hash/id evidence and performs
the existing WAL/VACUUM cleanup under the same fence. Owner bundle import validates working identity, lineage,
attachment/delete evidence and quota before commit; owner remap preserves stable scoped ids and replay.
An actual multi-space bundle filled to within one legal activity unit of the 8 MiB owner cap round-trips through
export/import; adding that next unit is rejected with zero rows committed.

Trusted FastAPI routes and exact Tauri proxy commands now cover list/load/save/snapshot/restore/attach/export/
delete. They expose no owner field, renderer, file path, URL, HTML/SVG/JS/plugin content or browser persistence.
The source API returns canonical JSON for an eventual user-chosen-file shell; PNG remains optional derived output.
No Web editor, canvas dependency, package/bundle change or scene claim is included.

### Phase F · S-3 Tutor whiteboard port — DONE

- Versioned allowlisted element commands only; model cannot emit JS/SVG path/URL/plugin data.
- Validate and preview every proposed mutation before CAS; rejected command does not advance checkpoint.
- Save/snapshot/attach/cancel/recover bind the same Tutor activity/revision and do not create a second activity graph.
- Whiteboard failure returns readable Tutor/check and preserves learner answer.

Implemented as a dedicated `TutorWhiteboardPort`, not as another graph or a
generic model tool. Its exact v1 batch permits at most 32 `put_element` or
`delete_element` commands and delegates every element and complete prospective
scene to the S-2 validator. Duplicate targets, no-ops, missing deletes,
unknown operations/fields, executable/external content and over-limit scenes
fail before either database changes.

Preview is read-only and returns a fingerprint over owner/space/activity,
Tutor revision, base/result working revisions, canonical command hash and
prospective scene hash. Apply echoes that fingerprint and, under the common
cross-process write fence, rechecks the Tutor run revision plus working CAS
before the S-2 transaction. Stable scoped idempotency binds the Tutor revision,
caller key and command fingerprint; an exact replay returns its first result,
while drift conflicts. The port never writes `tutor_runtime.db`, so rejected
commands do not advance Tutor checkpoint truth.

Snapshot/attach/recover/cancel are host-only lifecycle methods. Each validates
the same Tutor key and revision under that fence, always uses the Tutor
activity id, and cannot create a second activity graph. Snapshot provenance
records the Tutor checkpoint revision. Trusted FastAPI/Tauri source commands
expose this port without owner input; error responses include only a sanitized
readable Tutor output/check fallback. Tests also claim a learner answer before
a rejected command and prove the exact checkpoint, including the answer,
remains unchanged. The provider wire remains typed-Markdown-only and therefore
has no alternate canvas/JS/tool route around this port.
