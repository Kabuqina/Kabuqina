# CTL-C02 stop-producing / autostart JIT plan

**Control:** CTL-C02 / C-1

**Frozen base:** `e5c020f885dc041f73cd00bd841cf3c9aaa747e5`

**Owner:** C integrator
**Depends on:** CTL-C01 (`DONE`), CTL-G00 (`DONE`)

## Outcome

Make the C01 manifest executable at every state-producing boundary. Under
`mainland_cn`, only `weixin`, `qqbot`, and `dingtalk` may be visible or start a
gateway child. Under `sea`, only `telegram`, `whatsapp`, and `email` may do so.
Desktop remains available in both profiles. Unknown profiles and unknown or
removed delivery targets fail closed.

Existing removed credentials, profiles, jobs, and secrets are preserved. They
must not create new profile/config/child/network/send state. Physical adapter,
dependency, plugin, and bundled-file removal is explicitly deferred to CTL-C03.

## Allowed paths

- `python/src/product_profile_policy.py`
- `python/src/gateway_policy.py`
- `python/src/gateway_env_loader.py`
- `python/src/network_policy.py`
- focused tests under `python/tests/`
- `tauri/src/gateway_supervisor.rs`, `tauri/src/paths.rs`, `tauri/src/lib.rs`,
  gateway env/config commands, and retained/removed QR worker launch commands;
  only profile gating, child identity, and single-platform config isolation are
  in scope
- `web/src/` profile/platform registry, route guards/tombstones, and focused tests
- `hermes_core/gateway/config.py`, the versioned gateway delivery contract,
  cron/messaging write preflight call sites, and focused tests under
  `hermes_core/tests/`
- C02 evidence, sign-off, decision/control-board updates under `docs/`

## Forbidden in this control

- deleting platform adapters, plugins, source trees, dependencies, or bundle files
- deleting or rewriting existing secrets, jobs, profiles, or target text
- silently mapping a removed or unknown target to `local`, Desktop, or another channel
- changing unrelated A/B hot zones or doing broad refactors

## Implementation slices

1. Establish one versioned profile/platform contract matching the C01 manifest.
2. Make Python profile resolution, gateway enablement, and host derivation exact
   and fail closed; remove wildcard/stale-credential host expansion.
3. Make Rust discovery, migration, readiness, profile creation, and child spawn
   profile-scoped and validate before any filesystem write.
4. Make Web route/catalog exposure consume the trusted active profile; retained
   routes only, removed/unknown deep links render an explicit tombstone.
5. Reject new removed/unknown cron and messaging targets with an actionable,
   versioned error. Preserve old target text; execution reports
   `unsupported_delivery` without network access or rerouting.
6. Prove the stop-producing boundary and record residual readiness work for later
   C controls without claiming physical absence.

## Verification

- Python focused unit tests for both profiles, unknown-profile fail-closed
  behavior, stale credentials, and exact network-host derivation
- Rust focused tests for profile-scoped eligibility/discovery/migration/spawn
  validation and no-write behavior
- Web focused tests plus `npm run build` and `npm run lint`
- canonical `hermes_core/scripts/run_tests.ps1` for core delivery/write contracts
- C01 manifest/regression check and repository search proving removed platforms
  are not in C02 producer allowlists

## Rollback

Revert the C02 implementation commits as a unit. No migration deletes data, so
rollback needs no secret/profile/job recovery. If a retained platform proves
unready, leave its persisted data untouched and report the later readiness gate;
do not re-enable a removed platform as a fallback.

## Exit evidence

- stale removed credentials alone create no new config/profile/child/network/send state
- new removed or unknown delivery writes fail with the contract-versioned error
- old removed targets stay list/edit/delete capable and execute as
  `unsupported_delivery`, with no network attempt or silent reroute
- exact visible/autostart sets match the C01 manifest for both profiles
- evidence and release-captain sign-off identify any accepted gaps and next gate
