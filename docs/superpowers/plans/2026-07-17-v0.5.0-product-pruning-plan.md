# v0.5.0 产品裁剪计划：渠道、工具、依赖与兼容退场

> **性质：** v0.5.0 专项设计/审计计划。本文冻结裁剪原则、候选清单、
> 数据迁移与验收门；每个物理删除切片动工前仍须另出 JIT 实施 plan。
>
> **状态：** Approved v2（2026-07-17）。Owner 已冻结 mainland/SEA 最终渠道集：
> mainland 外部渠道仅微信、QQ Bot、钉钉；SEA 外部渠道仅 Telegram、WhatsApp、
> Email；企业微信、飞书/Lark、Discord 与所有未入清单的上游长尾彻底删除。

## 0. 目标与基线建议

v0.5.0 把 Kabuqina 收束为两个明确的学生产品 profile，不再为未发布平台承担
源代码、依赖、配置、测试和安全维护成本。

**冻结的产品矩阵：**

| Profile | 产品壳 | 唯一允许的外部 gateway |
|---|---|---|
| `mainland_cn` | Desktop/Tauri | `weixin`、`qqbot`、`dingtalk` |
| `sea` | Desktop/Tauri | `telegram`、`whatsapp`、`email` |

Desktop 是 Tauri 产品壳和 desk child，不是 `gateway.config.Platform` 中的消息 adapter；
因此 profile manifest 分开记录 `product_shells` 与 `gateway_platforms`，不得拿
`Platform.LOCAL` 或 API server 冒充 Desktop。

**彻底删除：** `discord`、`feishu/lark`、`wecom`（含 callback/crypto）、Slack、
Signal、Matrix、Mattermost、Home Assistant、SMS/Twilio、BlueBubbles、Yuanbao、
Webhook、API Server，以及 bundled platform plugins IRC、Microsoft Teams。

不删除 Git 历史；需要恢复时从历史或独立分支重新引入，不在主干留死代码。

## 1. 当前事实

- `python/src/product_profile_policy.py` 仍把 `feishu` 列为 mainland 可见和可
  autostart 平台，`GatewayPolicy` 也默认启用飞书；
- `python/requirements-desktop.txt` 正式打包 `lark-oapi`，bundle 还复制
  `feishu_qr_worker.py`；
- Rust/Tauri、Web Settings、network host 派生和 gateway profile 都有飞书入口；
- `sea` 当前没有独立 visibility mapping，会回落 mainland 列表；SEA 不是可发布 profile；
- DingTalk 当前被 `GatewayPolicy` 禁用，旧 SDK 因 `websockets<13` 冲突不进桌面 bundle，
  保留它意味着 v0.5 必须另做 transport/SDK 升级而非只改 allowlist；
- Discord 已从当前桌面 bundle 的工具层隐藏/裁掉部分内容，但 owned core 仍保留
  adapter、工具、脚本、大量测试和 `discord.py[voice]` messaging extra；
- owned core 仍有 Telegram、WhatsApp、Email/SMS、Slack、Signal、Matrix、
  Mattermost、BlueBubbles、Home Assistant、Webhook、API server、Yuanbao、
  DingTalk、WeCom 以及 plugin IRC/Teams 等平台面；“UI 不显示”不等于已裁剪。

因此本轮不能只改两个可见列表。裁剪必须从 producer、consumer、依赖、数据、
测试、文档和 bundle 七个面同时闭合。

## 3. C-0 · 全量 surface 与依赖审计

审计范围：

- core platform enum/registry、lazy imports、platform package、通用 gateway dispatch；
- CLI/config env metadata、profile policy、network policy、toolset/plugin/skill catalog；
- Rust supervisor、credential profiles、QR commands、deep links、autostart eligibility；
- Web routes、Settings blocks、i18n、状态 hooks、onboarding/capability payload；
- Python requirements、core extras、npm bridge、bundle copy/drop、license manifest；
- cron `deliver`、home channel、existing jobs、session/profile directories、stored secrets；
- tests、fixtures、docs、sample config、release checks和 CI discovery。

输出不是字符串命中数，而是一张 profile/import/配置/持久化/交付依赖图。共享 helper
只有在 retained 平台仍使用时保留，并改成中性命名；仅被删除平台使用时一起删。

## 4. C-1 · 先停止生产与启动被删渠道

物理删除前先让新版本不再制造被删状态：

- mainland gateway visible/autostart 只含微信、QQ Bot、钉钉；SEA 只含 Telegram、
  WhatsApp、Email；两者都保留 Desktop shell；
- Web 不再创建企业微信/Discord/飞书及长尾配置、QR 请求、deep link 或 home channel；
- Rust 不再用旧 credential 让 gateway eligible，也不再为其生成 profile env；
- cron/messaging 新写入不接受被删 deliver target；API 返回 versioned actionable error；
- network allowlist 不再因旧 credential 动态加入相关 host；
- bundle verifier 先证明 Desktop、mainland 三渠道和 SEA 三渠道不 import 被删模块。

这一阶段不自动清除用户 secret、job 或 profile 目录，避免在迁移语义冻结前丢数据。

## 5. C-2 · 企业微信、Discord 与飞书物理退场

### 5.1 Discord

- 删除 gateway adapter、Discord-specific helper、tool/admin surface、voice doctor、
  WhatsApp 之外不共享的 voice/opus glue；
- 从 registry、config、commands/help、toolset、plugin/capability 和 docs 删除入口；
- 从 `pyproject.toml` messaging extra 和桌面 requirements 中移除 Discord 依赖；
- 删除只验证 Discord 的 tests/fixtures；通用 gateway 合同改由 retained adapter
  测试承接，不能因为删平台顺便失去 shared-kernel 覆盖；
- `git grep` 只允许历史/决策/本计划中的明确归档命中。

### 5.2 飞书/Lark

- 删除 `feishu.py`、comment/rules、飞书专用 tools、worker 和 onboarding helper；
- 删除 Rust `feishu_env`/`feishu_qr` wiring、commands、profile prefix 与 tests；
- 删除 Web page/block/registry/i18n/路由/QR 状态；
- 删除 `lark-oapi` 及其 license/bundle verification，验证 runtime 不再出现
  `lark_oapi` 包；
- 删除飞书 host 派生与 allowlist；
- 通用 `messaging_policy`、cron delivery、home channel 不再使用飞书作为示例或默认。

### 5.3 企业微信

- 删除 `wecom`、`wecom_callback`、callback crypto、QR worker 与专用测试；
- 删除 Rust env/QR、Web Settings、profile prefix、network hosts 和 credentials；
- shared Weixin crypto/helper 必须先做 import/use audit，不按名称猜测后一并删除；
- old WeCom home channel/job/secret 遵守 C-4 的不静默改投和显式清理语义。

每个平台独立提交和 review；不把三次大删除、generic gateway 重构与 Tutor hot path
混在同一 diff。

## 6. C-3 · 长尾平台与 plugin platform 删除

按独立平台族拆小切片：

1. SMS/Twilio（Email 保留，但 SMS 是独立 adapter，必须拆净配置污染）；
2. Slack、Signal、Matrix、Mattermost；
3. BlueBubbles、Home Assistant、Yuanbao；
4. Webhook、API server（先证明 Desktop loopback/desk server 不依赖）；
5. bundled plugin platforms IRC、Teams；
6. registry/dynamic enum/config/docs/test/shared helper 收口。

所有项目都物理删除。Retained smoke 分别覆盖 mainland 的微信/QQ Bot/钉钉和 SEA 的
Telegram/WhatsApp/Email；不能只验证其中一个 profile。

## 7. C-4 · 数据、凭据与任务兼容

- 旧企业微信/Discord/飞书及长尾 secret/profile 默认**不自动删除**；首次检测时
  说明该渠道已退场，提供显式清理动作或卸载说明；
- 旧 home channel 指向被删平台时，不静默改投桌面或其他人。将其标为 unavailable，
  要求用户重新选择；
- 旧 cron job 的 `deliver` 指向被删平台时保留 job 和正文，但执行结果为可见的
  `blocked/unsupported_delivery`，不调用 LLM 重试、不产生其他渠道副作用；
- 被删 gateway session/profile 可导出或显式删除；upgrade 不递归猜测目录；
- 新版本不得因为残留旧 env/secret 自动启动 gateway child；
- release notes 列出已删除平台、残留数据位置、显式清理方法和不可恢复行为。

## 8. Bundle、性能与安全收益门

裁剪必须记录可验证收益：

- v0.4 release baseline 与 v0.5 裁剪后 Python runtime、site-packages、MSI/NSIS、
  cold start、gateway import time 的 delta；
- removed dependency、transitive package、license 和 advisory 数量；
- platform env key、network host、credential surface、QR command、Web route 数量；
- retained Desktop、微信、QQ Bot、钉钉、Telegram、WhatsApp、Email 的分 profile
  regression 结果。

禁止为追求数字删除 OpenAI-compatible transport、共享 media、安全校验或 retained
platform 所需依赖。收益没有达到预期时要解释共享成本，而不是伪造归因。

## 9. 测试与完成标准

- 机器 manifest 与 registry/bundle/filesystem 对齐，新增未分类平台失败；
- 企业微信、Discord、飞书和所有长尾平台的 live source、imports、routes、deps、
  runtime packages、tests 和用户文档归零；只允许历史、决策和迁移说明中的精确命中；
- final retained platform set 在 Python/Rust/Web 三层完全一致；
- stale removed-platform credentials 不 autostart、不扩网络、不发送消息；
- removed delivery target 的旧 job 可枚举、可解释、无静默改投；
- Desktop shell + mainland 三渠道 + SEA 三渠道的 clean install/profile isolation/v0.4
  upgrade smoke 通过；
- bundle/installer/许可证清单无被删 SDK，体积与启动 delta 已记录；
- `DECISIONS.md`、capability matrix、roadmap、release notes 与真实范围一致。
