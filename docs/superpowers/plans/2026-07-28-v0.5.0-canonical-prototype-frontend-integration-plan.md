## 0. 这份计划解决什么

生产 `web/src/` 已经有一套**功能完整但 IA 不同**的前端：Study 只在
`/study/:id/practice` 上是书桌，其余是「顶栏 + 生命周期导航 + 页面 outlet」；
Chat 是带侧栏与工作台面板的 agent 对话；Studio 是三栏 rail/main/sources 卡片页；
没有全局外壳、没有台灯、没有 Activity 入口、没有杂记本。

原型定的是**另一套信息架构**。本计划把生产面按原型重排，**不丢已接好的后端能力**。

## 1. 两条已定的范围决定（owner，2026-07-28）

1. **Chat：保留能力，只换布局。** 按原型改成居中对话纸 + 按需历史抽屉，去掉
   `ChatSidebar` / `WorkspacePanel` / 并列作用域条；附件走 composer 的「＋」，
   语音 / agent 进度 / 桌面投递保留但收进低强调位置。**能力不删，代码不弃。**
2. **顺序：先地基后表面。** 见 §3 的分片顺序，每片独立提交。

## 2. 不可越过的红线（来自架构与原型 AGENTS）

- Study **没有对外出口**：书桌与课程 Chat 不出现任何「发送到 Studio」。跨域取材
  一律由 Studio 发起。自由 Chat 是唯一例外。
- 任何界面都**不出现覆盖率 / 对齐百分比 / 连续天数 / 达标徽章**。
- 草稿默认停在 draft：只有闪卡与测验直接激活，计划 / 知识库 / 资源包仍需确认。
- 全部颜色走双主题设计令牌，两个主题都不新增硬编码色值。
- 内部对象名（`SourceSnapshot`、`revision`、`space_id`）不出现在学生可见层。
- 窄窗目标是 **720 × 520**（真实最小桌面窗口），不是手机。

## 4. S1 已落地内容

`web/src/index.css` 新增 canonical 令牌块，令牌名**与原型逐字一致**
（`--page` / `--ink` / `--paper` / `--desk` / `--purple` / `--manila` …），
因此原型 CSS 可以逐段搬运而不必改写变量引用。

选择保留裸名而不加前缀的理由：生产 CSS 此前没有任何裸名自定义属性
（`desk.css` 用 `--c-*`，其余用 `--kq-*` / `--hd-*`），实测无冲突；
Tailwind 4 的 `@theme` 命名空间也不受影响。

旧的 `--kq-*` 一套**不删**：设置页、onboarding、companion 等仍在用它。
两套并存是过渡态，等表面全部迁完再评估收敛。

## 5. S2 已落地内容

`web/src/shell/AppShell.tsx` 作为 layout route 包住 `/study`、`/studio`、`/chat`。

顺带修掉了三处**同一事实两个主表达位置**（信息原则 §7.3 重复测试）：

1. `WindowTitleBar` 里那套「聊天 / 课程本 / Studio / 设置」链接删掉了——它是**窗口**
   标题栏，现在只剩品牌、缩到小娜和系统窗口控制；
2. `DeskChrome`（书桌自带的那条页眉）删掉了，`/study/:id/practice` 不再自己画顶栏；
3. Study 顶栏与 Studio 顶栏里的「返回聊天 / 去课程本 / 问小娜」跨域链接删掉了，
   功能性控件（课程切换、导入、草稿箱）保留。

**两处顺带修的真实缺陷：**

- 台灯的切换原本把副作用写在 state updater 里，StrictMode 下 updater 跑两次，
  结果是 DOM 翻了而灯不亮。已改为先算再写，并有回归测试钉住。
- 导入弹窗「读完就退出」把两件该说的话一起吞掉了：后端把档位压回偏好时的
  `limited` 提示、以及哪一份读失败了。现在 `onImported` 上报
  `{ paths, limited }` 由 shell 接着说，**有读失败就不自动关**。

**全窗口只有一条横条（owner，2026-07-28）：** 产品面上 `AppShell` 的页眉**就是**标题栏——
整条 `data-tauri-drag-region`，最右端接 `components/WindowControls.tsx`（缩到小娜 +
最小化/最大化/关闭），贴到窗口右上角，与产品控件之间隔一道竖线：左边管应用，右边管这扇窗。
`WindowTitleBar` 退回只服务设置、引导、导出、启动页，且只剩品牌 + 同一个 `WindowControls`。
`main.tsx` 按路径二选一，任何时候都不叠两条。

**Activity 的过渡态：** 页眉那颗按钮经 `shell/activityBridge.ts` 的事件桥接到已经接好
真实数据的课程学习动态面板。真正的跨域面板（Study 现场 + Studio 现场 + 恢复）是 S10，
届时这座桥换成真正的面板宿主。

## 6. S3 已落地内容

**做法：把 `DeskScene` 推广成承载五页的书桌，而不是在它旁边另建一个。**
这一条是关键——0.4 留下的割裂是「练习那一页是书桌，其余四页是另一套外壳」，
同一门课翻一页就换一个世界。现在书立在上、笔记本在中、书堆/复习/杯子在右，
五个分页共用同一本本子：练习正文仍由书桌自己画（只有它带作答面、检查反馈、
页边批注），其余四页把 `StudyPageOutlet` 铺进 `pageBody`。

因此 `StudyTopBar` / `StudyLifecycleNav` / `SpaceSwitcher` / `DeskLeftObjects` 退场：
换课在书立上，翻页在笔记本分页上，放资料在书堆的「＋」上。

**顺带修的一个真实缺陷：** `loadDesk` 在课程还没有可用测验时会抛 `no active quiz`。
如果让它决定整张书桌在不在，一门刚建、还没出题的课会连扉页/计划/学习/评估一起打不开。
现在承载其它分页时书桌照常摊开（书立走不经网络的 `bookstandFallback`），
只有本子里那一页说清练习还没准备好。

**没有弄丢的东西：** `DeskTutorInvoke`（可审核的提问卡）、`DeskCardReview`、
`DeskWorkFolder`、`DeskActivityPanel`、精确返回、versioned Study↔Chat handoff 全部还在。
草稿箱（`DraftInboxButton`）暂时安置在书桌右栏，S10 随 Activity 一起搬到它该在的地方。

窄带从 `max-width: 720px` 改为 `860px`——原来那条只在正好 720 时才触发，
而真实最小窗口就是 720（Iteration 18）。
