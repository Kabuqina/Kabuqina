## 0. 这份计划解决什么

生产 `web/src/` 已经接入一批真实后端能力，但 **Study 五页产品循环并未完成**：Study 只在
`/study/:id/practice` 上是书桌，其余是「顶栏 + 生命周期导航 + 页面 outlet」；
Chat 是带侧栏与工作台面板的 agent 对话；已有 Studio 是三栏
rail/main/sources 卡片页，但它不进入 v0.5.0 交付；没有全局外壳、没有台灯、没有
Activity 入口、没有杂记本。

原型定的是**另一套信息架构**。本计划把生产面按原型重排，**不丢已接好的后端能力**。

## 1. 已定的范围决定（owner，2026-07-28；2026-07-31 更新）

1. **Chat：保留能力，只换布局。** 按原型改成居中对话纸 + 按需历史抽屉，去掉
   `ChatSidebar` / `WorkspacePanel` / 并列作用域条；附件走 composer 的「＋」，
   语音 / agent 进度 / 桌面投递保留但收进低强调位置。**能力不删，代码不弃。**
2. **顺序：先地基后表面。** 见 §3 的分片顺序，每片独立提交。
3. **Studio：顺延至 v0.6。** v0.5.0 导航保留 Studio，但只打开不可交互的“开发中”
   页面；不提供 Project、Brief、取材、Studio Chat、恢复现场或自由 Chat 转交入口。
   已有 Studio 后端与持久化作为 dormant groundwork 保留，不删除、不迁移，也不再为
   v0.5.0 扩展。Studio 不参与本版完成度、QA 与发布阻塞判断。

Studio 占位页固定文案：

> **Studio 正在开发中**
>
> 小娜正在准备一个把灵感变成作品的空间。当前版本请先使用 Study 专注学习。

## 2. 不可越过的红线（来自架构与原型 AGENTS）

- Study **没有对外出口**：书桌与课程 Chat 不出现任何「发送到 Studio」。跨域取材
  一律由 Studio 发起。自由 Chat 是唯一例外。
- 任何界面都**不出现覆盖率 / 对齐百分比 / 连续天数 / 达标徽章**。
- 草稿默认停在 draft：只有闪卡与测验直接激活，计划 / 知识库 / 资源包仍需确认。
- 全部颜色走双主题设计令牌，两个主题都不新增硬编码色值。
- 内部对象名（`SourceSnapshot`、`revision`、`space_id`）不出现在学生可见层。
- 窄窗目标是 **720 × 520**（真实最小桌面窗口），不是手机。

## 4. S1 已落地内容

`web/src/index.css` 新增 canonical 令牌块，令牌名**与原型逐字一致**
（`--page` / `--ink` / `--paper` / `--desk` / `--purple` / `--manila` …），
因此原型 CSS 可以逐段搬运而不必改写变量引用。

选择保留裸名而不加前缀的理由：生产 CSS 此前没有任何裸名自定义属性
（`desk.css` 用 `--c-*`，其余用 `--kq-*` / `--hd-*`），实测无冲突；
Tailwind 4 的 `@theme` 命名空间也不受影响。

旧的 `--kq-*` 一套**不删**：设置页、onboarding、companion 等仍在用它。
两套并存是过渡态，等表面全部迁完再评估收敛。

## 5. S2 已落地内容

`web/src/shell/AppShell.tsx` 作为 layout route 包住 `/study`、`/studio`、`/chat`、`/settings`。

顺带修掉了三处**同一事实两个主表达位置**（信息原则 §7.3 重复测试）：

1. `WindowTitleBar` 里那套「聊天 / 课程本 / Studio / 设置」链接删掉了——它是**窗口**
   标题栏，现在只剩品牌、缩到小娜和系统窗口控制；
2. `DeskChrome`（书桌自带的那条页眉）删掉了，`/study/:id/practice` 不再自己画顶栏；
3. Study 顶栏与 Studio 顶栏里的「返回聊天 / 去课程本 / 问小娜」跨域链接删掉了，
   功能性控件（课程切换、导入、草稿箱）保留。

**两处顺带修的真实缺陷：**

- 台灯的切换原本把副作用写在 state updater 里，StrictMode 下 updater 跑两次，
  结果是 DOM 翻了而灯不亮。已改为先算再写，并有回归测试钉住。
- 导入弹窗「读完就退出」把两件该说的话一起吞掉了：后端把档位压回偏好时的
  `limited` 提示、以及哪一份读失败了。现在 `onImported` 上报
  `{ paths, limited }` 由 shell 接着说，**有读失败就不自动关**。

**全窗口只有一条横条（owner，2026-07-28）：** 产品面上 `AppShell` 的页眉**就是**标题栏——
整条 `data-tauri-drag-region`，最右端接 `components/WindowControls.tsx`（缩到小娜 +
最小化/最大化/关闭），贴到窗口右上角，与产品控件之间隔一道竖线：左边管应用，右边管这扇窗。
`WindowTitleBar` 退回只服务引导、导出、启动页，且只剩品牌 + 同一个 `WindowControls`。
`main.tsx` 按路径二选一，任何时候都不叠两条。

**进行中（原 Activity）：** 页眉按钮经 `shell/activityBridge.ts` 打开全局 S10 抽屉，读取 B-10
`cmd_activity_records` 的跨域投影。按照 2026-07-31 范围覆盖，v0.5.0 产品面只保留 Study
Tutor 记录并使用后端给出的稳定返回目标；Studio Project 记录在前端过滤，不提供恢复入口。
失败信息不暴露内部对象。

## 6. S3 已落地内容（S3A–S3F）

> **边界纠正（owner，2026-07-29）：**S3 过去只解决了“五页装进同一本笔记本”，不能据此
> 宣称 Study 五页完成。五页当前产品合同以
> [Study 五页产品行为规格](../specs/2026-07-29-v0.5.0-study-five-page-behavior-spec.md)
> 为准；开发和验收必须引用其中的编号。

**做法：把 `DeskScene` 推广成承载五页的书桌，而不是在它旁边另建一个。**
这一条是关键——0.4 留下的割裂是「练习那一页是书桌，其余四页是另一套外壳」，
同一门课翻一页就换一个世界。现在书立在上、笔记本在中、书堆/复习/杯子在右，
五个分页共用同一本本子：练习正文仍由书桌自己画（只有它带作答面、检查反馈、
页边批注），其余四页把 `StudyPageOutlet` 铺进 `pageBody`。

因此 `StudyTopBar` / `StudyLifecycleNav` / `SpaceSwitcher` / `DeskLeftObjects` 退场：
换课在书立上，翻页在笔记本分页上，放资料在书堆的「＋」上。

**顺带修的一个真实缺陷：** `loadDesk` 在课程还没有可用测验时会抛 `no active quiz`。
如果让它决定整张书桌在不在，一门刚建、还没出题的课会连扉页/计划/学习/评估一起打不开。
现在承载其它分页时书桌照常摊开（书立走不经网络的 `bookstandFallback`），
只有本子里那一页说清练习还没准备好。

**没有弄丢的东西：** `DeskTutorInvoke`（可审核的提问卡）、`DeskCardReview`、
`DeskWorkFolder`、`DeskActivityPanel`、精确返回、versioned Study↔Chat handoff 全部还在。
草稿箱（`DraftInboxButton`）暂时安置在书桌右栏，S10 随 Activity 一起搬到它该在的地方。

窄带从 `max-width: 720px` 改为 `860px`——原来那条只在正好 720 时才触发，
而真实最小窗口就是 720（Iteration 18）。

### 6.2 S6 / S9 已落地内容（2026-07-30）

- 碰杯不再把练习页替换成一张 Tutor 全屏卡，而是在当前笔记本页边展开轻量小娜框；五页均按

- 轻量框复用真实 Chat 的消息流、流式回答和 text / choice 澄清交互；完整 Chat 使用同一个

- 书立只把真实 `resource_pack` 作为可抽出的文件；阅读器由 artifact 反查可信导入路径，前端
  既不能提交任意路径，也不会收到本地绝对路径。
- PDF 每次只读取至多 12 页；目录支持折行和内部滚动，正文独立滚动，前后翻页可到达完整文件，
  每份文件单独记住阅读位置。阅读位置不写入 Study 继续状态，也没有“完成 / 高亮 / 保存”动作。

### 6.3 S3B 已落地内容（2026-07-30）

- 每门课程只有一个 versioned Study location；学习与练习共用 `knowledgeCoreId`，练习另记每个知识核
  最近的 `exerciseId`，换课程使用独立存储键。
- 学习页前后移动、练习页前后移动和两页互切都只更新同一游标；当前知识核没有匹配题目时保留
  空态，不借用其他知识核的题。
- 动态继续书签投影计划范围、学习/练习模式以及草稿、检查、待修改、完成状态；它没有手动创建或
  删除入口，打开阅读器或普通浏览不会移动它。
- 已删除或失效的知识核不再自动跳到第一项：继续状态降级到同课程计划范围，等待用户重新进入
  有效知识核。恢复元数据写入失败不会阻断课程真值或作答。

### 6.4 S3C 已落地内容（2026-07-30）

- 材料目录最多显示三级；原文件更深的真实节点压平到第三级，并保留文件 artifact、文件名、页码和
  完整来源路径。阅读器仍展示并可跳转原文件完整目录。
- 计划任务可声明 `mode=learn|practice|review` 和可选 `outline_node_id`。旧任务无字段时兼容为学习；
  `review` 进入练习页，不凭空增加第六页。
- 绑定真实目录节点的行动在该节点内显示为独立行动队列，不成为第四级目录；未绑定的旧行动继续按
  阶段显示。开始行动会同时保存计划项、目录节点和当前知识核，再进入正确页面。
- 完成与跳过继续记录为两类独立活动；都不写掌握、覆盖率、连续天数或达标状态。

### 6.5 S3D 已落地内容（2026-07-30）

- 学习页一次只呈现一个知识核、其可确认来源说明和学生自己的说法，不铺知识列表或资源列表。
- 每个知识核分别保存文本和是否已打开教材对照；空白文本保持空白，不由系统补写。
- 对照只并列教材说法与学生说法，不评分、不判对错、不改写；上一核/下一核可往返恢复各自现场。
- “去练习这个知识核”只切换页面模式，沿用同一个 `knowledgeCoreId`。

### 6.6 S3F 已落地内容（2026-07-30）

- 扉页始终只有“我的目标 / 我的偏好 / 时间与约束”三条可选输入和三个动作；空白可直接确认，
  不要求先去 Chat，也不显示 weak points、当前知识核、活动或下一调整。
- “请小娜帮我拟一版”只登记一次有时限的显式请求；请求之前已有的 `student_state` 草稿不会被误认。
  用户未修改时，新草稿回到同一组三条输入行，确认前不生效；用户已有未确认输入时不静默覆盖，
  第三个按钮改为“采用小娜建议”，由用户主动选择。
- 未改动的小娜草稿确认后直接成为 active；用户在建议上继续修改时，保存一份正式合同并拒绝原建议，
  因而直接填写、小娜起草和混合修改仍只有一份 active 真值。放弃修改恢复原 active。
- 评估结论只有在存在有界 `evidence_refs` 时展示；没有可追溯证据的评估不会驱动调整。
  知识核证据可回到对应学习页，失效时降级到本课程计划页；活动证据可回到对应原题。
- 错题回访已经接入实际承载练习的 `StudyDeskPage`：按活动解析原题，再映射其知识核与题目游标；
  原题或知识核失效时留在当前知识核，没有当前知识核才降级到计划，不会借用别的题或跳错课程。
- 评估页只呈现错题证据与最近可靠评估，不再重复 Activity Log。

### 6.7 S3E 已落地内容（2026-07-30）

- 每道题分别恢复答案、最后一次检查结果与 `dirty / needs_revision / completed` 状态；刷新、切题或
  从其它页面回来不会只剩答案而丢掉“小娜批注”。`checking` 不作为可恢复状态，意外中断后回到
  `dirty`，避免页面永久卡在“正在检查”。
- 正确答案不再因提交成功而从恢复缓存清除；后端 `quiz.attempt` 仍是证据真值，本地快照只负责恢复
  作答现场。缓存写入失败不会把一次已成功的后端检查变成重复提交。
- 同一知识核内新增独立的上一题/下一题导航；切题先同步保存当前题，再恢复目标题自己的答案和反馈。
  上一/下一知识核仍使用另一组导航，回学习继续保持共享知识核游标。
- 未检查修改离开五页继续由 `StudyShell` 保护；打开页边 Chat 或阅读器不卸载作答面。Chat 返回合同
  恢复同一题、答案、反馈与答案焦点。练习正文仍只显示一条“小娜批注”和最短“提示”。
- 当前练习 API 只返回 active quiz，draft 不能作答或产生证据；当前知识核无匹配题时保持空态，
  不跳到其他知识核。

题目纵向合同已增加可选 `knowledge_core_id / origin / source_refs`：新题以稳定 ID 精确归核，明确不匹配
时不再回退标题/tag；同核 active 题按资料原题 → 资料改编 → 小娜生成排序，并在题面显示来源类型和
bounded 材料位置。确定性改编保留原题材料引用、标记为 `adapted`，且仍先进入 draft；Web 只加载
active quiz，因此未采用草稿不能作答或形成证据。旧题没有新字段时继续使用保守 tag 兼容。

练习草稿在草稿箱内只预览题目、来源类型与有界材料位置，不泄露答案或评分规则；`quiz` 不再误走
知识库语义审查。用户点击“采用并开始”后才激活，并精确写入该题的 `knowledgeCoreId + exerciseId` 后
进入练习页。跨多份 active quiz 作答时，检查请求提交给题目自身的 artifact，不会错误提交到列表第一份
quiz。学习页异步返回也不能把正在进入练习的书签写回学习页。

S3E 的页面与纵向题目合同至此完成。B-13 已接入：服务端 revisioned location 是共享真值，
`localStorage` location 只承担离线恢复投影，不能覆盖更新的服务端 revision。

### 6.8 S3G 自动化验收（2026-07-30）

- 五页分页与继续书签共用同一笔记本层级，正文不再重复页面名；长内容由笔记本正文容器承担纵向滚动。
- 课程恢复键、学习者说法、练习答案/批注和每知识核题目游标均带课程边界；即使不同课程复用相同
  `knowledgeCoreId` 或题目 ID，也不会读取另一门课程的现场。
- 切换课程会取消旧请求；已经在途且迟到的旧课程响应不能覆盖新课程。整本笔记本加载失败时只显示
  不含内部 ID 的有界错误，并可在原位重试。
- 720×520 是最小窗口验收规格；不再保留 360 宽度规格，也不把 360 浏览器宽度当作系统 200% 缩放
  的代理。720×520 结构检查无页面级横向溢出；G-04 的 Windows 原生 200% 视觉与动作可达性由产品方
  最终确认。

### 6.9 B-13 前端接入（2026-07-30）

- 计划页优先读取服务端学习地图的可靠三级目录；学习页按地图的稳定顺序显示知识核。
- 练习页只采用 `exerciseLinks` 中显式绑定到当前知识核的题，并按后端 order 排序；地图存在但当前核
  没有链接时保持空态，不再用标题、tag 或整份 quiz 猜题。
- Study 打开时以服务端 location 和 map revision 恢复现场；本地移动通过 revision CAS 回写。
  revision/map 冲突会重新读取服务端真值，断网才保留本地恢复现场。

## 7. S4 已落地内容

杂记本按 design-qa Iteration 10 / 12 实现：牛皮纸本子待在书立**最右端**（离开课程那一组），
选中后换成**一页纸**——随手写（KaiTi，学习者自己的手）加上从对话落进来的条目。
刻意缺席：五个生命周期分页、笔记本页眉、卡片盒、书堆、任何计数或徽章。小娜还在。

它**不走** `DeskScene`：那张书桌的一切都围着当前练习转，而杂记本一样都没有；
硬塞一个 variant 只会让两边都变糊。`ScratchDesk` 共用书立、纸张与杯子——
也就是"同一张桌子"该共用的那些东西。

**后端完全不存在，所以入口有条件：**只有某个 space 报 `kind: "scratch"` 时书立上才出现
这本。今天没有任何 space 会这么报，因此生产面上看不到它——**不上线一个点了没反应的入口**。
契约见账本 B-12，后端落地即亮。

**顺带修的一个真实缺陷：** `desk.css` 里 `.kq-desk button` / `.kq-desk textarea`（0,1,1）
压过裸类选择器（0,1,0），S3 的书立与书脊配色其实一直没生效——当前那本没有真的与纸面
连成一体。新物件已全部按本文件既有惯例挂到 `.kq-desk` 下，两处一并修好。
