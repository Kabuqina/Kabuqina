> 也不负责颜色、材质、插画、品牌资产或高保真视觉。

## 0. 目标与版本判断

v0.4 已经建立 `/study/:spaceId/:page`、五页 lifecycle、草稿箱、练习、错题和学习数据，
但“功能存在”尚不等于“用户知道下一步并能完成任务”。当前实现至少存在以下断点：

- 测验有输入控件，但入口、作答状态和提交路径让用户误以为不能回答；
- 闪卡只有翻面和四档评分，提示、快捷键、焦点与完成反馈不形成完整主动回忆；
- “开新本”把用户送回聊天，而课程空间创建 API 没有一等 UI 调用；
- “继续上次”只聚焦计划项，没有启动任何学习活动；
- 草稿箱对多种 artifact 不展示正文，却允许用户激活或拒绝；
- 知识点旁的“去复习”是静态标签，错题与评估也缺少可执行的下一步；
- 未保存、browser back、space 切换、pending/blocked、键盘和隐喻文案缺少统一合同。

本轨的目标不是继续给页面追加按钮，而是冻结一条可理解、可恢复、可测试的学习闭环：

```text
建立/选择课程
  → 看清当前目标与下一步
  → 开始或恢复真实学习活动
  → 阅读/练习/主动回忆
  → 获得可解释结果
  → 审核 AI 草稿或调整计划
  → 回到明确的下一步
```

若核心任务流与场景美术发生排期冲突，Study detail 先交付清晰可用的 semantic flat UX，
延期场景精修；标准宽屏的全局书桌 semantic skeleton 仍是 E/V 的产品 P0。不得用更漂亮的
书桌/卡片盒掩盖假入口、不可审查动作或断裂的恢复路径。

## 1. 与产品架构、功能、UI 美术计划的边界

| 轨道 | 负责 | 不负责 |
|---|---|---|
| **E · 产品体验架构** | 产品承诺、一级 IA、Chat/Study/Create 职责、共同对象、handoff/return、跨面原型 | Study 题型/闪卡/Tutor/Whiteboard 的详细状态 |
| **X · Study UX 交互设计** | 课程内任务、内部 IA、状态机、动作命名、焦点/键盘、恢复、低保真原型、可用性证据 | 一级产品 IA、Report 领域归属、API 实现、视觉风格、品牌资产、production CSS |
| **L/P/S/U · 功能轨** | runtime state、repository/API、持久化、grader、checkpoint、artifact、错误码与实现测试 | 临场发明交互语义或视觉隐喻 |
| **V · UI 美术轨** | tokens、排版、密度、场景构图、图标、插画、动效、响应式视觉和品牌交付 | 改写已冻结任务流、用视觉状态代替不存在的 runtime state |

约束如下：

1. X-0 可与 E-0 并行；X-1 消费 E-1，X-2 消费 E-2，不另造全局入口、context 或 return；
2. X 轨可以要求功能轨补充最小数据合同，但不在交互稿里假造数据；
3. 每个可见状态必须映射到版本化 runtime/repository 状态或明确的纯本地 UI 状态；
4. V 轨消费 E/X 冻结的 screen/state matrix，不重新决定按钮语义、流程顺序或恢复策略；
5. 功能实现可先交付无美术的 semantic surface，但必须符合 E/X 合同；
6. 高保真视觉原型不能替代低保真任务测试，两者证据分别记录。

- 不以一次 owner walkthrough 代替首次用户和键盘用户验证；
- 不因 UX 调整扩大默认关闭、内容最小化的 IA telemetry。

## 3. 交互原则

1. **每个主按钮兑现字面承诺。** “继续学习”必须真正继续活动；若只能定位内容，
   就写“查看当前项”。
2. **主动作清晰，隐喻为辅。** “启用草稿（落墨）”“拒绝草稿（擦掉）”优于只写
   “落墨/擦掉”；首次用户无需理解笔记本世界观才能完成任务。
3. **始终标明轮到谁。** Tutor 在讲、等待学习者、等待工具审批、后台复核和已停止
   必须是不同状态。
4. **草稿不是事实。** AI draft、semantic suggestion、grader result 和 learner content
   有不同动作权限与可见来源。
5. **离开前说明会失去什么。** 未提交答案、未保存白板、未完成活动分别处理；
   browser back、space 切换、页面导航和关闭窗口遵循同一合同。
6. **后台工作必须有终点。** pending 显示正在做什么、能否取消、失败后如何恢复，
   blocked 不伪装成 loading。
7. **鼠标与键盘路径等价。** 快捷键可发现；焦点不会因弹窗、翻卡、换题或异步刷新丢失。
8. **结果必须导向下一步。** 错题、评估和完成总结至少提供一个上下文正确的动作，
   不把用户丢回无差别首页。
9. **不伪造精度。** 没有 scheduler interval、来源、恢复或成本数据时，界面不编造估计。

## 4. X-0 · Study 现状任务流审计（硬门）

建立逐屏、逐任务 inventory，而不只列 route。至少覆盖：

- Chat STUDY 面板、`OpenStudyLink`、知识点捕获和“问小娜”返回的 Study 端行为；
- Study 首次空态、建课、切换、五页 lifecycle、草稿箱和高级数据治理；
- Flyleaf 设定、Plan、Learn、Practice、Evaluate；
- Tutor start/interrupt/resume/cancel/terminal；
- 练习④⑤、闪卡、自测、wrongbook retry、evaluation draft；
- Whiteboard 进入/退出、保存、快照、贴回和失败降级；
- Settings/Onboarding 中与 provider readiness、费用和地区 profile 有关的前置状态。

每个任务记录：

| 字段 | 要求 |
|---|---|
| 触发点 | 用户从哪里、带什么 context 进入 |
| 预期结果 | 用户认为动作会发生什么 |
| 实际状态 | 当前 UI/runtime 真正做了什么 |
| 断点 | dead end、false affordance、状态不明、不可恢复、不可达、术语不明 |
| 严重度 | P0 blocker / P1 major / P2 polish |
| 数据需求 | 已存在、需新增、禁止伪造 |
| 证据 | 代码/测试、截图、owner walkthrough、首次用户观察 |

**Gate X0：** P0/P1 task inventory、状态截图/semantic snapshot、已知测试缺口和 U-13～U-20
映射经 owner review；问题不得只以“感觉不顺”登记。

## 5. X-1 · Study 内部 IA、任务模型与文案语义冻结

### 5.1 Study 内部任务模型

**前置：Gate E1。** 一级目的地、默认落点、Create 位置和跨 surface 术语以 E-1 为
真值；本节只冻结用户进入 Study 后的课程任务与 E 已定义入口在 Study 端的呈现。

冻结以下入口及其目标：

- “创建课程”在空态与 space switcher 中直接可达，不以回到聊天作为唯一实现；
- “问小娜”消费 E-2 的 `ExperienceContextRef/ReturnTarget`，携带当前
  `spaceId/page/artifact/activity` 的最小上下文，并明确会离开当前任务；
- “继续学习”解析为明确目标：Tutor activity、当前计划项、到期复习或指定练习；
- lifecycle 是非线性导航，不伪装为已完成/未解锁的线性向导；
- 每页只保留一个主要下一步；secondary actions 不与 destructive action 同权重。

### 5.2 术语表

确定中英文 canonical copy，并规定隐喻的使用层级：

| 当前词 | 待验证主文案 | 隐喻位置 |
|---|---|---|
| 开新本 | 创建课程/学习空间 | 图标、辅助说明可用“新本” |
| 扉页 | 学习设定 | 页面副标题可保留“扉页” |
| 落墨 | 启用草稿 | 按钮辅助词或成功动效 |
| 擦掉 | 拒绝草稿 | 不单独作为 destructive 动词 |
| STUDY | 学习 | 英文环境使用 Study |

文案冻结同时覆盖 pending、blocked、stale、empty、offline、ungraded、timeout、
unsupported 和 destructive confirmation，不等高保真阶段临时补写。

**Gate X1：** Study task map、内部导航、canonical copy、返回/退出规则和 scope trade-off
经 owner 确认；与 E-1 无冲突，所有主动作都有唯一可观察结果。

## 6. X-2 · 交互合同与状态机冻结

**前置：Gate E2。** 跨 surface context、return、space rebind、pending activity 和 deep link
由 E-2 冻结；X-2 只补 Study task 的详细 dirty/focus/keyboard/recovery 合同。

### U-13 · 自测作答闭环

目标流程：

```text
测验卡（题数/状态/开始或继续）
  → 题目 + 明确“作答区”
  → 题目导航（已答/未答/当前）
  → 提交前检查
  → 判分 pending/timeout
  → 结果解释 + 错题重练/返回下一步
```

基线合同：

- 选择、判断、简答、Python 代码和推导题都有可见、带 label 的 answer surface；
- 进入题目后焦点落在题目标题或作答区的确定位置，Tab 顺序固定；
- 前后题切换保留答案；单题/整卷 answered 状态可见；
- 允许暂时跳题，但提交时明确列出未答题并要求再次确认；
- internal navigation、space switch、browser back 与窗口关闭统一处理 dirty answer；
- 结果页显示题目、学习者答案、确定性结果/未判分原因和下一步，不只列总分；
- crash/restart 是否恢复必须由数据合同明确；未实现时如实说明“离开会清除”。

验收：首次用户无需提示即可进入一份简答测验、输入、跨题返回、识别未答题并提交；
键盘用户可完成等价路径；空题、timeout、unsupported code 和提交失败均可恢复。

### U-14 · 闪卡主动回忆

状态机固定为：

```text
front/recall → optional hint → reveal/compare → grade pending → next | complete | error
```

基线合同：

- hint 在 reveal 前可用；没有 hint 时不展示空动作；
- Space 与 1–4 快捷键在界面可见，鼠标点击和键盘路径使用同一状态机；
- 翻面、评分、下一张和失败返回后焦点位置可预测；
- 四档评分说明语义；只有 scheduler 返回真实 interval 时才显示下次时间；
- 最后一张后进入完成总结，而不是无提示返回首页；
- 退出显示剩余数量，不把已评分卡重复写回；
- 可选回忆草稿默认不持久化、不判分、不进入模型 prompt。

P1 增强：一次评分撤销、真实 interval preview、不持久化 scratchpad。没有原子 undo API
前不画可用的撤销按钮。

### U-15 · 首次进入、建课与 space 管理

- `/study` 空态直接提供“创建课程”，标题校验、pending、重复名/失败和成功选择可见；
- space switcher 中同样可创建，不再把“开新本”无上下文地送回 `/chat`；
- Chat 可以带预填上下文辅助建课，但不是唯一入口；
- 创建成功后进入明确的第一步：补充学习设定或从聊天生成设定草稿；
- 切换失败保留原 space 和页面；切换前处理 dirty activity；
- course/space/notebook 的主文案统一，内部 ID 不暴露给普通用户。

### U-16 · 计划执行、下一步与继续学习

- “继续上次”必须启动/恢复真实 Tutor、Practice 或 Learn 目标；若只有页面定位能力，
  改名为“查看当前项”；
- 当前项显示为什么是下一步、完成标准、预计所需输入和关联 artifact；
- “完成”与“跳过”写入前说明影响；跳过可选填原因，失败保持原状态；
- 全部完成后提供复盘、生成下一阶段草稿或返回评估，不停在“已完成”；
- Tutor restart/checkpoint 恢复沿用 U-01/U-08，Plan 不建立第二套 resume 真值。

### U-17 · 草稿审核与信任边界

- 所有可激活的 artifact 必须先提供内容预览，或把用户带到所属页的完整审核面；
- 草稿显示类型、来源、生成原因、semantic review 状态、会替换/新增什么；
- 主动作使用“启用/拒绝”，隐喻作为辅助；不可逆动作确认，能归档则不伪称删除；
- semantic review 未通过时说明阻断原因和重试结果，不只禁用按钮；
- 同一 artifact 在草稿箱和所属页使用同一 action/status contract；
- activation 成功后明确去向，reject 后提供可恢复性说明；
- evaluation/weak point 永不因一次模型判断自动变成 active learner state。

### U-18 · Learn 到 Practice 的上下文动作

- 知识点上的“去复习”若呈现为动作就必须可点击；否则改为状态 chip；
- 从知识点、资料、辅导笔记进入练习时携带 source artifact/item，不打开无差别练习首页；
- 没有现成练习时提供“生成练习草稿”，显示调用/pending/审核要求，不自动激活；
- 阅读内容保留选中项、滚动/焦点和返回位置；
- 统一“去复习”继续作为安全降级，不阻断 v0.5 基线。

### U-19 · 错题、评估与行动闭环

- 错题条目至少显示题目摘要、学习者答案摘要、结果/未判分原因、薄弱点和本地化时间；
- “再试一次”明确重练一题、失败题集合还是整卷，并携带 exact source context；
- 结果页和错题本都能回到原题证据，不以分数/标签替代解释；
- evaluation 明确区分 grader truth、semantic draft 与已激活记录；
- 建议可显式转为计划草稿、练习草稿或 Tutor 讨论，均需用户确认；
- 历史趋势属于 P1，不在数据不足时画伪精确成长曲线。

### U-20 · 跨页面交互完整性

消费 E-2 的全产品 navigation/context 状态，并冻结 Study 各页面共享的详细矩阵：

| 维度 | 必须定义 |
|---|---|
| 数据状态 | idle/loading/ready/empty/stale/error/offline/unsupported |
| mutation | pending/succeeded/failed/conflict/blocked/cancelled |
| navigation | internal link/browser back/space switch/chat handoff/window close |
| dirty state | quiz answer/whiteboard/activity input/draft edit 的保存与放弃 |
| focus | page entry/dialog open-close/async refresh/item removal/route change |
| keyboard | nav、listbox、quiz、flashcard、dialog、whiteboard 的可发现按键 |
| copy | plain action、隐喻辅助、error recovery、destructive confirmation |
| accessibility | DOM 顺序、name/role/value、non-color cue、200% zoom、reduced motion |
| AI/provider | readiness、调用中、预算 blocked、降级、取消和费用说明 |

**Gate X2：** U-13～U-20 state diagrams、screen/state matrix、focus map、keyboard map、
copy table 和所需 API delta 经产品/功能/a11y review；不存在高保真稿才能解释的行为。

## 7. X-3 · 低保真原型与可用性验证

原型使用灰阶线框、真实长度文案和可点击状态，不使用品牌插画、材质或完成态动效。
至少覆盖以下 Study 端到端任务；跨 Chat/Study/Create 的宏观可理解性、成果找回和
restart 由 E-3 验证，X-3 复用其 context/return 结果而不重复发明产品结构：

1. 首次进入 Study → 创建课程 → 明白第一步；
2. 从 E 已定义的 Chat/Plan handoff 进入 → 继续真实 Tutor 或练习 → 中断 → 恢复；
3. 打开草稿 → 看懂来源与影响 → 启用或拒绝；
4. 简答测验 → 输入 → 跨题 → 未答检查 → 结果 → 错题重练；
5. 闪卡 → 提示 → 翻面 → 键盘评分 → 完成总结；
6. 从知识点/评估建议生成练习草稿 → 审核 → 开始练习；
7. 带未提交内容执行 lifecycle、space、E 定义的 Chat return、browser back 和关闭窗口。

验证对象至少包含：

- owner walkthrough；
- 2 名未参与设计、不了解“扉页/落墨”等隐喻的首次用户；
- 1 次完整键盘路径；
- 读屏 spot check 与 200% zoom/reduced-motion 走查。

每个任务记录 task success、错误/回退次数、需要解释的术语、停止点、恢复成功与否、
严重度和修订结论。没有上传 telemetry 时使用本机/手工 evidence，不把小样本包装成统计显著性。

**Gate X3：** P0 task 无未解决 blocker；首次用户不依赖口头指导完成主路径；键盘路径等价；
所有 P1/P2 问题有接受、修复或延期记录。

## 8. X-4 · UX 冻结与实现交接

冻结包必须包含：

- task inventory、IA/nav map、canonical copy/glossary；
- 每条 P0 flow 的低保真原型和版本；
- screen/state/component matrix；
- focus/keyboard/back/dirty/offline/error contracts；
- API/data delta 清单及对应 L/P/S/U owner；
- 可用性记录、问题严重度、变更和未采纳原因；
- P0/P1/P2 scope、降级、非目标和 implementation slicing 建议；
- 提供给 UI 美术 V 轨的行为边界、真实状态和内容长度样本。

冻结后：

- 功能实现按 U-13～U-20 分 JIT plan，不建立 UX mega implementation branch；
- UI 美术可以改变构图与视觉层级，不能静默改变主动作、状态机或恢复语义；
- 行为变更记录 UX delta，并判断是否需要重跑对应任务测试；
- 视觉可用性问题进入 V 轨，任务/状态问题回到 X/U 轨。

**Gate X4：** owner、功能 owner 和 UI owner 共同签字；P0 状态齐全；交付包可让实现者在
无高保真稿时先完成 Study semantic flat interaction。全局书桌 shell 由 E-4→V-0A/V-2
独立冻结，不等待 X-4；E-4 与 X-4 都通过后，V 才能覆盖详细 Study activity。

## 9. 数据、安全、隐私与成本门

- 所有动作继承 owner/space 作用域；从 Chat、wrongbook、Plan 深链进入时不串 space；
- learner answer、回忆草稿和白板输入不因可用性分析上传或进入第三方 telemetry；
- 草稿 preview 遵循内容最小化，但不能以“隐私”为由要求用户盲目激活；必要时进入所属页读取；
- dirty/recovery 数据若落盘，必须定义加密/路径、TTL、删除、导出和 crash 语义；
- provider 调用前说明用途；长任务显示 pending/cancel/blocked；失败不重复扣费式自动重试；
- evaluation suggestion 只生成 draft，grader truth 不被语义模型覆盖；
- destructive data governance 继续与普通课程/草稿动作分离。

## 10. 依赖与顺序

```text
v0.4 UI/Study baseline + U register
        ├── E-0 product audit ─► E-1 product IA ─► E-2 shared contracts
        │         │                    │                    │
        └── X-0 Study audit ───────────┴──► X-1 internal IA┴──► X-2 states
                                                                  │
                                    E-3 product prototype ─────────┼─► X-3 Study usability
                                    E-4 architecture freeze ───────┴─► X-4 UX freeze
                                                                          ├── V-0..V-5 UI art
                                                                          └── U-13..20 JIT
```

- L-0/P-0/S-0 可与 E-0/X-0 并行提供 runtime/data constraints；
- X-1 等 E-1；X-2 必须引用 E-2 与 L/P/S 的版本化状态，不能等待视觉稿后补状态；
- V 轨可在 E-0/X-0 期间收集现状截图和资产事实；全局 shell 构图等待 E-4，详细 Study
  场景 state design 等待 X-4；
- semantic flat implementation 可在 E-2 与相应 X-2 合同冻结后按独立 JIT plan 开始；
- U-13～U-20 不要求同一批合入，按依赖和 hot files 分纵切。

## 11. Scope trade-off 与允许延期

若 v0.5 容量不足，按以下顺序减载：

1. 延期 P1：闪卡撤销/interval preview/scratchpad、趋势图、批量草稿、搜索排序；
2. 降低场景美术密度，保留完整 semantic flat UX；但正常宽屏仍保留中性全局书桌骨架，
   不能退回旧 Workbench/通用 Dashboard；
3. 白板按既有 DOM+KaTeX fallback 降级；
4. 不削减建课、真实 resume、可审查草稿、可输入测验、主动回忆基线、错题解释和
   dirty/back/focus 等 P0 合同。

新增 UX Must 必须说明替换/延期项。视觉冻结后仅接受 P0/P1、数据安全、升级和 release
blocker；“已经画完”不是拒绝修正错误任务流的理由，但修正必须记录 delta 与返工影响。

## 12. 完成标准

本 UX 轨只有同时满足以下条件才完成：

- U-13～U-20 已完成问题定义、优先级、目标行为、非目标、依赖和验收；
- X 的内部 IA、context 入口和返回行为与 E-1/E-2 冻结包一致；
- 七条端到端任务都有低保真证据，P0 blocker 为零；
- 主动作无 false affordance，隐喻不妨碍首次用户理解；
- Practice、Flashcard、Plan、Draft、Evaluate 的状态机和恢复路径完整；
- Chat↔Study 的 Study 端、space、browser back、dirty、focus 与 keyboard 合同统一，
  跨面真值与成果流回链 E-2/E-3；
- 所有可见状态可映射到真实数据/runtime 状态，无视觉层伪造；
- P1/P2 明确延期版本，JIT implementation slices 和 UI V 轨输入清楚；
- Gate X4 获 owner/功能/UI sign-off，冻结包可追踪。
