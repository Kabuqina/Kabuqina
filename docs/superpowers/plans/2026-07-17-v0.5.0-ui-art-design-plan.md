# v0.5.0 UI 美术设计计划：视觉系统、Learning Space 与交付规格

> **性质：** 独立 UI/美术设计轨。本文不授权直接实现 React/CSS 或投产品牌资产；
> 视觉冻结后，各实现切片另出 JIT plan。
>
> **状态：** Draft v2（2026-07-17）。这是 v0.5.0 production scene art 的硬前置，
> 不再作为 Learning Space 功能实现中的附属任务；它自身必须等待
> [UX 交互设计计划](2026-07-17-v0.5.0-ux-interaction-design-plan.md) Gate X4。

## 0. 目标

为 v0.5.0 建立一套可实现、可访问、可降级、可在公开占位与官方品牌两种构建间
复现的 UI 美术规格。视觉层消费已冻结的任务流、状态机、焦点与文案合同，不重新
决定产品行为。重点不是“给现有页面换皮”，而是让视觉层稳定表达：

- 小娜是陪伴者，不替学习者完成动作；
- 笔记本/书桌隐喻映射真实学习状态，不制造虚假家具；
- Tutor、练习④⑤、白板课的运行状态一眼可辨；
- Chat、Study、Settings、Onboarding 仍像同一个 Windows 产品；
- 窄窗、200% zoom、键盘、读屏、reduced motion 有等价体验。

## 1. 与功能计划的边界

| 本计划负责 | UX 交互计划负责 | 功能实现计划负责 |
|---|---|---|
| 视觉原则、tokens、密度、排版、图标、插画、材质、动效语言 | 用户任务、IA、主动作与 canonical copy | route、repository、API、checkpoint、grader、artifact schema |
| 冻结状态的高保真构图和视觉层级 | screen/state matrix、返回/退出/恢复语义 | React 组件拆分、数据获取、mutation、错误处理 |
| public placeholder / private branded 资产规格 | low-fi 原型与首次用户任务验证 | overlay、hash、bundle、runtime loading |
| responsive、a11y 的视觉规格 | DOM 顺序建议、focus/keyboard map、非颜色语义 | ARIA、focus 实现和自动化测试 |
| handoff 标注与视觉验收基准 | UX delta 与行为验收 | 像素实现、性能优化和 release build |

设计不得改写数据合同或 UX 合同；功能层也不得在没有视觉规格时自行发明新的场景语言。

### 2.1 UX 前置门

- Gate X4 前只允许收集现状截图、既有 token/资产事实和实现债务；
- 不开始产品屏幕视觉 brief、高保真构图、场景 state design 或可被误认为已冻结的 hero mock；
- U-13～U-20 的主动作、状态、焦点、键盘、失败恢复和文案由 UX 冻结包提供；
- V 轨发现行为缺口时回到 UX delta，不在高保真稿中静默补一个新流程；
- private Tier 2 可继续做与具体产品任务无关的角色/材质探索，但不能覆盖公开产品事实。

## 2. 设计范围

### P0 · v0.5 必须完成

- 全局 shell 视觉审计：顶部导航、侧栏、dialog、toast、empty/loading/error；
- Study/Learning Space：书立、书堆、打开的笔记本、卡片盒、书签、页边小娜；
- Tutor activity：start、explaining、waiting、remediate、blocked、completed、cancelled；
- Practice ④⑤：独立作答、hint ladder、直接答案、讲解、pending review、draft 审核；
- 白板课：进入/退出、工具区、递笔、保存、快照贴回、离线/依赖失败 fallback；
- Companion：场景杯与 CompanionWindow 的单一状态视觉；
- light/dark/system、中文/英文、窄/中/宽、100%/200%、reduced motion；
- public placeholder 和 private branded 两套同构资产。

### P1 · 一致性收口

- `/chat`、Onboarding、Settings、能力/模型配置的 token 和组件一致性；
- removed gateway 后的 Settings 信息架构与空态；
- installer/release screenshot、应用商店图、帮助页所需的产品截图规范。

### 非目标

- 不做 three.js/PixiJS/游戏引擎、3D 翻页、逼真木纹/皮革、默认音效；
- 不做通用白板品牌重塑、REPORT 发射台场景化或把设置藏进拟物抽屉；
- 不用装饰动画表达唯一状态；不以单张 hero mock 代替系统设计；
- 不在公开仓库提交 Tier 2 私有 master。

## 3. V-0 · 现状审计与视觉 brief

**前置：Gate X4。** UX inventory 中已完成的 route/task/state 事实直接复用；V-0 只补
视觉问题、组件复用、token、构图、密度、品牌和视觉 a11y，不重复发明任务流。

输出一份逐屏 inventory：route、尺寸、状态、现有 token、组件复用、视觉问题、
a11y 风险、实现债务、截图基线。至少覆盖 Chat、五个 Study lifecycle 页面、
Tutor/Practice/Whiteboard 新面、Settings、Onboarding、CompanionWindow。

视觉 brief 必须冻结：

- 品牌性格关键词与反关键词；
- “柔和薰衣草/粉 + 纸面 + 低对比玻璃”的使用边界；
- 学习内容、系统 chrome、AI draft、学习者输入、确定性结果、语义建议的视觉层级；
- 哪些品牌元素来自 private Tier 2，哪些必须有 Apache-2.0 中性占位；
- P0/P1 屏幕和禁止设计漂移清单。

**Gate V0：** owner 认可 brief、屏幕 inventory 和优先级，才进入高保真探索。

## 4. V-1 · 视觉基础系统

冻结可编码 token，而不是只给颜色截图：

- semantic colors：background/surface/paper/ink/muted/accent/success/warning/error/focus；
- typography：中英文字体栈、display/body/label/code/math、行高与最小字号；
- spacing、radius、border、shadow、glass/blur 上限、纸张噪点强度；
- elevation 与 overlay；focus ring、selection、disabled、skeleton；
- icon stroke/fill/optical size；illustration line/shape/palette；
- motion durations/easing/distance、reduced-motion 静态替代；
- density 与 container-query breakpoints。

每个 token 给出 light/dark 值、用途、禁止用途和 CSS 映射名。颜色组合通过 WCAG
对比检查；纸纹/玻璃关闭后仍保持层级。

**Gate V1：** token table、基础组件 sheet、a11y check 和与现有 `index.css`/
brand tokens 的 migration map 通过 review。

## 5. V-2 · Learning Space 场景构图

为宽屏场景与 flat fallback 同时设计，二者共享信息结构和 DOM 顺序：

- 宽屏：书立/当前本、书堆、主笔记本、卡片盒、页边栏、咖啡杯的空间层级；
- 中窗：减少布景、保留主本与功能入口；
- 窄窗/200%：普通文档流，物件变成清晰 section/controls；
- 每个物件标注数据来源、交互、空态、加载、错误、stale、离线和读屏名称；
- 学习者内容始终是视觉主体，小娜旁注和 AI draft 不抢主栏；
- 五页 lifecycle 和 `/chat` 逃生门始终可发现。

至少产出以下关键帧：首次空本、已有课程、今日有复习、等待 learner check、
存在 draft、space 切换、服务错误、离线、窄窗、200% zoom、dark mode。

**Gate V2：** “撒谎检查表”逐物件通过；flat/scene 信息等价；无装饰物进入 P0。

## 6. V-3 · Tutor、练习与白板状态设计

- 将 UX 冻结的 Tutor 回合、当前一步、停止原因、resume/cancel 映射为视觉层级；
  learner interrupt 与 tool approval 使用不同颜色、icon 和非颜色线索；
- 将非线性 Hint ladder、直接答案、主动回忆和测验作答状态做成可见层级；
- 为确定性 pass/fail、semantic draft、pending/blocked 设计不同视觉语言；
- 区分学习者笔迹、Tutor 建议/预览、已确认元素；保存/快照/贴回是三个视觉动作；
- 为 timeout、ungradable、sandbox failure、network failure、budget blocked 消费 UX
  错误文案与恢复动作，并提供非颜色线索。

产出 visual component/state matrix、UX focus map 的视觉标注、reduced-motion storyboard
和错误状态视觉表；键盘流程与 canonical error copy 以 X4 冻结包为真值。

**Gate V3：** 功能 owner 能把每个视觉状态一一映射到 versioned runtime state；
不存在只能靠模型自由文本决定的 UI 状态。

## 7. V-4 · Companion 与品牌资产生产

- 固定 `idle/speaking/thinking/notify/sleeping/celebrating` 六态的姿态、表情、蒸汽和
  静态替代，不新增第二套角色状态机；
- 明确场景杯、compact pill、CompanionWindow 的共用资产和尺寸裁切；
- 产出 SVG/PNG/WebP 的尺寸、viewBox、透明边、颜色覆盖、命名和优化预算；
- private repo 保存 master；公开 repo 保存中性 placeholder；两者 component bounds、
  semantic state、alt/aria contract 完全一致；
- 每项资产登记 license、source hash、overlay target 和 restore 验证。

**Gate V4：** public 与 branded 构建可互换而不改布局；私有 master leak scan 通过。

## 8. V-5 · 原型、可用性与冻结

视觉原型在已通过 UX 低保真验证的任务上覆盖至少三条端到端路径：

1. 换本 → 继续书签 → Tutor learner check → 完成；
2. Practice ④ hint 跳级/直接答案 → ⑤讲解 → evaluation draft 审核；
3. 进入白板课 → learner/tutor 轮换 → 保存 → 快照贴回 → 返回本页。

本阶段验证视觉层级、内容可读性、响应式和品牌表达，不把它当成首次发现主任务流的
替代品。测试对象至少包含 owner walkthrough、首次使用者和键盘用户；没有上传 telemetry 时，
记录本机/手工 evidence，不把主观判断包装成数据。每轮记录问题、严重度、变更和
未采纳原因。

视觉冻结包包括：

- 高保真源文件 URL/版本或导出包；
- screen/state/component/token inventory；
- responsive、focus、motion、copy 和 asset specs；
- public/branded 对照；
- redline、验收截图和已知降级；
- implementation handoff checklist。

**Gate V5：** P0 状态齐全、P1 明确延期项、owner sign-off 后，功能分支才可合入场景
视觉实现；冻结后变更必须走 design delta 记录。

## 9. 实现交接顺序

1. UX Gate X4 与交接包；
2. token 基础与旧 token migration；
3. 无视觉隐喻的 semantic flat layout；
4. Study scene shell；
5. Tutor/Practice 状态组件；
6. Whiteboard chrome 与状态；
7. Companion/品牌资产 overlay；
8. Chat/Onboarding/Settings 一致性收口；
9. WebView2 visual QA 与 release screenshots。

每步必须在 public placeholder 下先完整可用，再套 branded overlay。禁止为了追求
截图效果破坏 DOM 顺序、文本选择、复制、国际化或降级布局。

## 10. 视觉验收

- design source、token、组件、状态和实现之间可追踪；
- 所有 P0 页面有 light/dark、中文/英文和窄/中/宽规格；
- 200% zoom、键盘、focus、读屏 spot check、reduced motion 不依赖场景隐喻；
- 无 overflow、重叠、截字、低对比、错误 z-index、不可见焦点；
- Tutor/approval、grader/evaluator、draft/active 的 trust boundary 可视化明确；
- `/chat` initial chunk 不因场景美术增长，重资产 route-level lazy；
- public placeholder 与 official branded 两轮截图基线均通过；
- owner review 通过后才记视觉轨完成，不以“设计文件已存在”代替实现验收。
