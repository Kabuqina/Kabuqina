## 0. 目标

为 v0.5.0 建立一套可实现、可访问、可降级、可在公开占位与官方品牌两种构建间
复现的 UI 美术规格。视觉层消费已冻结的任务流、状态机、焦点与文案合同，不重新
决定产品行为。重点不是“给现有页面换皮”，而是让视觉层稳定表达：

- 小娜是陪伴者，不替学习者完成动作；
- 用户在标准桌面窗口看见的第一张完整内容画面继承既有书桌母版，书签与卡片盒徽标先
  回答“上次学到哪、今天要复习什么”；
- 笔记本/书桌隐喻映射真实学习、对话、制作与成果状态，不制造虚假家具；
- Tutor、练习④⑤、白板课的运行状态一眼可辨；
- Chat、Study、Create、Onboarding 和 utility Settings/Capabilities 像同一个完成态 Windows
  产品，同时一眼能分清各自职责与当前作用域；
- 窄窗、200% zoom、键盘、读屏、reduced motion 有等价体验。

## 1. 与产品架构、UX 和功能计划的边界

| 本计划负责 | 产品架构 E / Study UX X 负责 | 功能实现计划负责 |
|---|---|---|
| 视觉原则、tokens、密度、排版、图标、插画、材质、动效语言 | E：产品/一级 IA；X：Study 任务/内部 IA；共同冻结主动作与 canonical copy | route、repository、API、checkpoint、grader、artifact schema |
| 冻结状态的高保真构图和视觉层级 | E：跨面 context/return；X：Study screen/state/focus/recovery | React 组件拆分、数据获取、mutation、错误处理 |
| public placeholder / private branded 资产规格 | low-fi 原型与首次用户任务验证 | overlay、hash、bundle、runtime loading |
| responsive、a11y 的视觉规格 | DOM 顺序建议、focus/keyboard map、非颜色语义 | ARIA、focus 实现和自动化测试 |
| handoff 标注与视觉验收基准 | UX delta 与行为验收 | 像素实现、性能优化和 release build |

设计不得改写数据合同或 UX 合同；功能层也不得在没有视觉规格时自行发明新的场景语言。
E 轨拥有产品承诺、一级 IA、surface hierarchy、context/return 与成果归属；V 轨只把这些
关系做成清楚、一致、可访问的视觉系统，不在高保真稿里新增 Dashboard、Report Center、
业务状态或跨面动作。

权威链固定为：**既有书桌愿景 = 场景宪法；E 轨 = Chat/Create/成果的接入关系；X 轨 =
Study 行为；V 轨 = 美术生产与响应式。** 未在 V 计划重复列出的扉页、五页 lifecycle、错题本、
铅笔夹页/落墨、书签、学习日志、页边小娜和白板课并不代表删除，必须完整继承愿景 §3/§8。
用户导出的 PPT 背景、母版和演示文稿样张不属于本计划；它们由
[PPT 生成质量与视觉母版完整优化计划](2026-07-17-ppt-generation-and-visual-master-optimization-plan.md)
独立负责，避免应用品牌 UI 与通用学生交付物母版互相绑死。

### 1.1 产品架构与 UX 前置门

- Gate E4/X4 前允许整理已经确认的场景母版、现状截图、既有 token/资产事实和实现债务；
- 全局 shell/一级导航/context/return/output hierarchy 等待 E4；Tutor、Practice、Flashcard、
  Quiz、Whiteboard 的详细构图与状态等待 X4；
- 在对应 gate 前不开始可被误认为已冻结的产品 hero mock 或 production composition；
- U-13～U-20 的主动作、状态、焦点、键盘、失败恢复和文案由 UX 冻结包提供；
- V 轨发现行为缺口时回到 UX delta，不在高保真稿中静默补一个新流程；
- private Tier 2 可继续做与具体产品任务无关的角色/材质探索，但不能覆盖公开产品事实。

## 2. 设计范围

### P0 · v0.5 必须完成

- 全局书桌 shell：Study/Chat primary、Create action、utility navigation、active context、
  activity status、return 和 recent output 的视觉层级；标准宽屏 first viewport 继承左桌角书堆、
  中央本、右卡片盒、右下小娜杯，并在笔记本前缘/下层增加一只“制作/成果”工作夹；
- 同一书桌构图的 `empty / course_clean / course_attention / create_overlay /
  safe_degraded` 五类组合 fixture；课程基础态与 Create/Deliverable/故障投影正交，不把它们
  实现成互斥 state enum，也不为五类各做一套重资产背景；
- Activity/Recent 最小入口覆盖多任务 count、waiting/blocked/running/failed/completed 排序、
  独立成果找回与窄窗 sheet；它属于 product chrome，工作夹只镜像相关计数，不新增桌上票据；
- Onboarding/默认落点、普通 Chat、课程 Chat、Create launch/review/running/blocked/output/
  return 与 Study 是同一系统，同时 surface 职责可辨；
- context/material/progress/output 抽屉在宽窗与窄窗同构，不让核心动作因右栏隐藏而消失；
- 全产品 dialog、toast、empty/loading/error/offline/restart 与 canonical trust states；
- Study/Learning Space：书立、书堆、打开的笔记本、卡片盒、书签、页边小娜，以及愿景
  §3/§8 的全部笔记本内部视觉语法；
- Create/Report 桌面锚点：同一只薄工作夹露出“＋制作 / 成果”文字标签；完整 Create/成果
  工作面仍使用清晰表单、状态面和标准按钮；
- Tutor activity：start、explaining、waiting、remediate、blocked、completed、cancelled；
- Practice ④⑤：独立作答、hint ladder、直接答案、讲解、pending review、draft 审核；
- 白板课：进入/退出、工具区、递笔、保存、快照贴回、离线/依赖失败 fallback；
- Companion：保留单一现有 fallback，确保不双状态/双通知；新六态、跨 surface 合并和
  额外品牌动效按 U-24 replacement ledger 默认延期；
- light/dark/system、中文/英文、窄/中/宽、100%/200%、reduced motion；
- public placeholder 和 private branded 两套同构资产。

### P1 · 一致性收口

- Settings/Capabilities 的详细页面整理、removed gateway 后的信息架构与空态；
- installer/release screenshot、应用商店图、帮助页所需的产品截图规范。

### 非目标

- 不做 three.js/PixiJS/游戏引擎、3D 翻页、逼真木纹/皮革、默认音效；
- 不做通用白板品牌重塑、把完整 REPORT 编辑/审核流程伪装成机器或把设置藏进拟物抽屉；
  但制作/成果必须在全局书桌有清楚、带文字的空间锚点；
- 不把 Create/Report 画成新的一级产品中心；其增量位置、材料/成果关系与返回以 E4 为真值，
  但 E4 不得重排 owner 已确认的场景母版；
- 不设计或验收用户导出的 PPT 母版、背景图案和演示文稿模板；
- 不用装饰动画表达唯一状态；不以单张 hero mock 代替系统设计；
- 不在公开仓库提交 Tier 2 私有 master。

## 3. V-0 · 现状审计与视觉 brief

V-0 拆成两个有不同前置的包，避免全产品 shell 被详细 Study 状态无意义串行阻塞，也避免
视觉分支越过 X4 发明 Tutor/Practice 行为。

### V-0A · 全产品 shell brief

**前置：Gate E4。** E inventory 提供 route/surface/context/return/activity/recent 与工作夹
增量，desk base composition 直接继承愿景母版。输出普通冷启动 first viewport、五类组合 fixture、Onboarding/default destination、
ordinary/course Chat、Study shell、PPT Create launcher/review/status/output/return、utility
Settings/Capabilities 的 route/尺寸/状态/token/组件/视觉问题/a11y/截图 inventory。

**Gate V0A：** owner 认可 primary/utility、surface hierarchy、desk first-view、
context/activity/return/output、窄窗优先级与全产品 flat fallback，才进入 shell 高保真和
V-1 基础系统。书桌首屏不等待 X4；X4 只阻塞本内 Tutor/Practice/Whiteboard 详细构图。

### V-0B · Study detail brief

**前置：Gate X4。** X inventory 提供五个 Study lifecycle、Tutor/Practice/Flashcard/Quiz/
Whiteboard 的详细 task/state/focus/error；V-0B 只补这些面的视觉问题、构图与视觉 a11y，
不重复发明任务流。CompanionWindow 只审计当前 fallback；新六态/合并属于延期项。

**Gate V0B：** owner 认可 Study detail inventory 与 P0/P1 屏幕优先级，才进入 V-2 中
Study detail 部分和 V-3 活动高保真；V-0A + V-1 已可放行 V-2 的全局书桌/中窗/窄窗构图。

两个 brief 共同冻结：

- 品牌性格关键词与反关键词；
- “柔和薰衣草/粉 + 纸面 + 低对比玻璃”的使用边界；
- 学习内容、系统 chrome、AI draft、学习者输入、确定性结果、语义建议的视觉层级；
- 哪些品牌元素来自 private Tier 2，哪些必须有 Apache-2.0 中性占位；
- P0/P1 屏幕和禁止设计漂移清单。

## 4. V-1 · 视觉基础系统

直接继承愿景已冻结的质感/技术基线：kq-glass 的柔和底子、克制纸感、DOM/CSS/SVG 承重、
场景资产懒加载；禁止位图纹理、重 canvas、皮革/逼真木纹和游戏引擎。V-1 细化 token 与
component spec，不重新生产一张不可交互的背景插画。

冻结可编码 token，而不是只给颜色截图：

- semantic colors：background/surface/paper/ink/muted/accent/success/warning/error/focus；
- typography：中英文字体栈、display/body/label/code/math、行高与最小字号；
- spacing、radius、border、shadow、glass/blur 上限、纸张噪点强度；
- elevation 与 overlay；focus ring、selection、disabled、skeleton；
- icon stroke/fill/optical size；illustration line/shape/palette；
- motion durations/easing/distance、reduced-motion 静态替代；
- density 与 container-query breakpoints。

每个 token 给出 light/dark 值、用途、禁止用途和 CSS 映射名。颜色组合通过 WCAG
对比检查；纸纹/玻璃关闭后仍保持层级。

**Gate V1：** token table、基础组件 sheet、a11y check 和与现有 `index.css`/
brand tokens 的 migration map 通过 review。

## 5. V-2 · 全局书桌与 Learning Space 场景构图

### 5.1 继承母版，不重新做概念方向比赛

宽屏构图不再以 A/B/C 三个候选比较；它已经由 owner 确认。V-2 只做生产化和响应式翻译：

| 层级 | 构图 | 本轨任务 | 裁决 |
|---|---|---|---|
| 宽屏场景母版 | 左桌角书堆、中间打开本、右卡片盒、右下小娜杯 | 忠实实现既有空间、书签/到期首眼层级和轻纸感 | **继承，不重选** |
| 中窗适配 | 母版物件收紧，笔记本扩宽；工作夹变本下横条 | 保留对象关系、文字入口与 DOM 顺序 | **响应式变体** |
| 窄窗/读屏 | 课程、下一步、今日复习、材料、制作、成果、Chat 顺序排布 | 语义等价与焦点可靠 | **flat fallback** |

普通冷启动先看全桌，进入 Study page 后中央本扩大；打开 Chat 时右侧形成 contextual sidecar；
进入 Tutor/Whiteboard/完整 Chat/Create 后书桌退为边缘背景与 return anchor。不得为此增加
Home route、第二套状态，或把原场景包装成“新提出的中央本方案”。

唯一需要做低保真位置比较的新增物是**制作/成果工作夹**：

- A：从笔记本前缘/下层露出“＋制作 / 成果”标签，推荐；最符合“学习为主、工具随手可取”；
- B：仅保留 product chrome 的“制作 / Activity-Recent”文字动作，作为重叠、焦点或热文件预算
  无法安全实现 A 时的技术 fallback；
- 两种都不得移动书堆、卡片盒或杯子，也不得新增独立成果托盘、Activity 票据或第四列。

### 5.2 宽屏 first viewport

```text
┌ context / activity / utility chrome ───────────────────────────┐
│ [书立/新本]   ┌────── 当前课程笔记本 ──────┐   [卡片盒]        │
│ [桌角书堆]    │ 书签 · 生命周期 · 下一步    │   今日到期        │
│ 已引用材料    │ Study 主舞台 / 页边小娜     │                   │
│               └──────────────────────────────┘╲                  │
│                [工作夹：＋制作 | 成果]            ☕ 问小娜     │
├ 学习 ─ 对话 ─ ＋制作 ─ 活动/成果 ───────────── desk edge ┤
└───────────────────────────────────────────────────────────────┘
```

建议宽屏 grid 为 `220–250px / minmax(640px, 1fr) / 240–300px`；笔记本视觉面积不低于
55%。左域同时容纳不同语义的书立与书堆；右域上方固定为卡片盒、下方固定为杯子。工作夹
在视觉上从笔记本前缘/下层露出，交互 DOM 仍占独立 grid row，不能用绝对定位制造焦点顺序
错乱。Chat sidecar 打开后覆盖/压缩右域，不增加第四列。顶部 chrome 保留 current context、
Activity 与 utility，不把设置做成台灯/抽屉；desk-edge 文字入口与物件调用同一 semantic action。
书签、卡片盒徽标、draft 活页、错题页签与页边小娜完整继承愿景：杯子是全局 Chat 入口，
页边小娜是本内低干扰旁注，二者消费同一 session/context，不能产生两套状态。

sidecar 是推荐高保真方向，不是无条件技术硬门。E3 先用低保真比较“杯子→sidecar”和
“杯子→完整课程 Chat + return”，E4 冻结结论；V-0A 只消费该结论并画高保真。若前者不能
复用同一 session/composer/focus 合同，v0.5 使用后者，不能另造一个简化但不持久的假 Chat。

### 5.3 物件、真值与 flat 等价

| 物件 | 真实数据/动作 | 必做状态 | medium/narrow 等价 |
|---|---|---|---|
| 当前本/书签 | space + next/resume target | empty/current/stale/switching/dirty | 当前课程 + 继续学习卡 |
| 书立/空白本 | space switch/create | loading/error/selected/new | 课程按钮 + 全屏 switcher |
| 桌角书堆 | 当前课程 READ/知识库；P0 为 canonical artifact/draft `source_refs` 只读聚合 | empty/loading/missing/ready | “本课已引用材料” section；未关联 source 不出现 |
| 卡片盒 | current-space flashcard deck + due queue | empty/due/loading/error/stale | “今日复习”section；不显示伪跨课总数 |
| 笔记本内部语法 | lifecycle、weak points、draft/active、learning log、tutor/whiteboard checkpoint | 愿景 §3/§8 + X4 冻结态 | 普通分页、草稿审核、复习与课堂入口 |
| 制作/成果工作夹 | CreateActivity/CreateAttempt + DeliverableRecord/Version | blank action；单 selected；多任务摘要+数量；成果 empty/available/missing/provenance | 制作 action + 最近成果 section；不静默选最新 |
| 小娜杯 | ordinary/course Chat action | context/provider blocked/return；角色只用现有 fallback | “问小娜”文字按钮/full-height Chat |
| product chrome Activity | ActivitySummary | empty/count/waiting/blocked/running/query error | Activity/Recent 全屏列表；不是桌上家具 |

所有物件必须能回答“对应哪个 ID、读取哪个状态、点击哪个现有动作、flat fallback 是什么”。
咖啡杯热气、纸纹、光斑等只能增强氛围，`aria-hidden`，不承担唯一状态。工作夹中的资料纸
表示 pinned reference，不表示移动文件；工作夹从本下露出不表示成果已进入学习真值。
五类 fixture 可以组合：无课程也可有独立成果，course attention 也可同时有两个 Create；
视觉稿和测试不得用一个顶层 scene state 隐藏另一维事实。

### 5.4 响应式与密度

为宽屏场景与 flat fallback 同时设计，二者共享信息结构和 DOM 顺序：

- 宽屏：完整继承母版，overview/focused/deep 三档密度；
- 中窗：收紧母版并把工作夹变成本下横条，保留书堆、本、卡片盒、小娜与 chrome Activity；
- 窄窗/200%：语义等价的 flat 文档流；DOM 顺序为 current context → next/recovery →
  due/今日复习 → Activity → lifecycle/content → materials/drafts → Create/results → Chat；
- 每个物件标注数据来源、交互、空态、加载、错误、stale、离线和读屏名称；
- 学习者内容始终是视觉主体，小娜旁注和 AI draft 不抢主栏；
- 五页 lifecycle 和 `/chat` 逃生门始终可发现。

至少产出以下关键帧：首次/回访空桌、course clean、course attention、多 activity、
Create draft/running/blocked/completed、最近成果、今日有复习、等待 learner check、存在 draft、
space 切换、服务错误、无 provider、离线、窄窗、200% zoom、dark mode。

**Gate V2：** “撒谎检查表”逐物件通过；5 秒内能指出当前课程/下一步、今日复习、Chat、
Create/成果和 product chrome Activity-Recent；flat/scene 信息等价；无装饰物进入 P0 点击区。

## 6. V-3 · Tutor、练习与白板状态设计

- 将 UX 冻结的 Tutor 回合、当前一步、停止原因、resume/cancel 映射为视觉层级；
  learner interrupt 与 tool approval 使用不同颜色、icon 和非颜色线索；
- 将非线性 Hint ladder、直接答案、主动回忆和测验作答状态做成可见层级；
- 为确定性 pass/fail、semantic draft、pending/blocked 设计不同视觉语言；
- 区分学习者笔迹、Tutor 建议/预览、已确认元素；保存/快照/贴回是三个视觉动作；
- 为 timeout、ungradable、sandbox failure、network failure、budget blocked 消费 UX
  错误文案与恢复动作，并提供非颜色线索。

产出 visual component/state matrix、UX focus map 的视觉标注、reduced-motion storyboard
和错误状态视觉表；键盘流程与 canonical error copy 以 X4 冻结包为真值。

**Gate V3：** 功能 owner 能把每个视觉状态一一映射到 versioned runtime state；
不存在只能靠模型自由文本决定的 UI 状态。

## 7. V-4 · 核心品牌资产与条件 Companion 增强

- P0 先完成 shell/Study 所需 public/branded 同构资产和现有 Companion fallback 边界；
- `idle/speaking/thinking/notify/sleeping/celebrating` 新六态只在 §11.1 ledger 经 owner
  以等量 scope 恢复时进入 production；否则可保留设计探索，不作为 v0.5 release gate；
- 明确场景杯、compact pill、CompanionWindow 的共用资产和尺寸裁切；
- 产出 SVG/PNG/WebP 的尺寸、viewBox、透明边、颜色覆盖、命名和优化预算；
- private repo 保存 master；公开 repo 保存中性 placeholder；两者 component bounds、
  semantic state、alt/aria contract 完全一致；
- 每项资产登记 license、source hash、overlay target 和 restore 验证。

**Gate V4：** P0 public 与 branded 构建可互换而不改布局；私有 master leak scan 通过；
延期的 Companion 状态不得出现在 release claims。

## 8. V-5 · 原型、可用性与冻结

视觉原型在已通过 E/X 低保真验证的任务上覆盖至少七条端到端路径：

1. 首次/回访冷启动 → 识别既有母版四件与新增工作夹 → 开新本、继续书签或进入今日复习；
2. Study 内容 → 带 context 问小娜或发起 Create → 成果/回答 → 返回原处；
3. 独立 PPT Create → 生成中切换 surface/重启 → Activity/Recent 找回 → retry/open；
4. 多任务 waiting/blocked/running 并存 → 窄窗切换/取消互不覆盖；
5. 换本 → 继续书签 → Tutor learner check → 完成；
6. Practice ④ hint 跳级/直接答案 → ⑤讲解 → evaluation draft 审核；
7. 进入白板课 → learner/tutor 轮换 → 保存 → 快照贴回 → 返回本页。

本阶段验证视觉层级、内容可读性、响应式和品牌表达，不把它当成首次发现主任务流的
替代品。测试对象至少包含 owner walkthrough、首次使用者和键盘用户；没有上传 telemetry 时，
记录本机/手工 evidence，不把主观判断包装成数据。每轮记录问题、严重度、变更和
未采纳原因。

视觉冻结包包括：

- 高保真源文件 URL/版本或导出包；
- screen/state/component/token inventory；
- responsive、focus、motion、copy 和 asset specs；
- public/branded 对照；
- redline、验收截图和已知降级；
- implementation handoff checklist。

**Gate V5：** P0 状态齐全、P1 明确延期项、owner sign-off 后，功能分支才可合入场景
视觉实现；冻结后变更必须走 design delta 记录。

## 10. 视觉验收

- design source、token、组件、状态和实现之间可追踪；
- 所有 P0 页面有 light/dark、中文/英文和窄/中/宽规格；
- Study/Chat/Create 的 surface hierarchy、active context、activity、return 与 output 状态
  一致且可辨；ordinary Chat 与课程 Chat 不靠颜色单独区分；
- 标准桌面冷启动第一张完整内容画面忠实继承既有书桌母版；5 秒 first-sight test 能指出当前
  课程/开新本、书签下一步、卡片盒今日复习、问小娜、制作/成果及 chrome Activity；
- 200% zoom、键盘、focus、读屏 spot check、reduced motion 不依赖场景隐喻；
- 无 overflow、重叠、截字、低对比、错误 z-index、不可见焦点；
- Tutor/approval、grader/evaluator、draft/active 的 trust boundary 可视化明确；
- `/chat` 和全局 shell initial chunk 不因场景美术增长，重资产 route-level lazy；
- public placeholder 与 official branded 两轮截图基线均通过；
- owner review 通过后才记视觉轨完成，不以“设计文件已存在”代替实现验收。
