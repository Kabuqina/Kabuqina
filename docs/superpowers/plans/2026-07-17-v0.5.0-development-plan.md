# v0.5.0 开发计划：产品收束 · 结构化辅导 · 练习④⑤ · Learning Space

> **性质：** 版本级路线计划（地图）。每个实现切片动工前必须另出
> just-in-time 实施 plan；本文只冻结版本范围、依赖、风险门、降级路径与
> release acceptance，不授权把所有工作压进一个分支或一次提交。
>
> **状态：** Draft v3（2026-07-17）。渠道 profile 与彻底删除清单已获 owner
> 批准；Tutor、UI 美术和后续功能调整仍按独立 gate 继续细化。可立即开始文档、
> 审计与设计切片；
> v0.5.0 运行时代码进入 `main` 前，必须先满足 §2 的 v0.4.0 release 基线门。

## 0. 版本判断

v0.4.0 已把学习数据、生命周期 IA 和前端主路径铺好：M1-M6、练习梯子②③、
一等 `/study/:spaceId/:page`、A-R1..R3 政名与 graph-default 收口都已进入
`main`。v0.5.0 不再继续横向堆页面，而是完成三次纵向汇合，并主动缩小
产品维护面：

1. **M7 · 结构化辅导活动：** 将 LG1/LG2/H2 从 requirements 变成可中断、
   可恢复、owner/space scoped 的 tutor loop；普通聊天保持普通 agent turn。
2. **M8 · 练习梯子④⑤：** 独立练习、hint ladder、讲解/费曼评估接入
   LG4 条件边，确定性判分仍是真值来源，语义评估只产生 draft。
3. **M9 · Learning Space：** 在既有五页笔记本 IA 上完成书桌/纸面场景、
   旁注式小娜与白板课；场景只呈现真实数据，不建立第二套 Study 状态。

新增两条版本级横轨：

4. **C · 产品裁剪：** 冻结双 profile：mainland 为 Desktop + 微信 + QQ Bot +
   钉钉，SEA 为 Desktop shell + Telegram + WhatsApp + Email；企业微信、飞书/Lark、
   Discord 和所有未入清单的上游长尾/IRC/Teams plugins 彻底删除。
5. **V/U · 设计与升级治理：** UI 美术成为独立硬门，先冻结视觉系统、状态和
   资产交付再允许场景实现；其他功能调整统一进入 living register，逐项定义问题、
   目标、优先级和替换成本，不直接混进 mega diff。

另设一条独立的 **R4 兼容退场轨**：把 v0.4.0 的 canonical Kabuqina +
legacy Hermes 双栈收窄为“新代码和正常运行只依赖 Kabuqina；旧名只存在于
有清单、有理由、有升级边界的兼容、协议、谱系或历史位置”。R4 不物理改名
`hermes_core/`，也不以字符串归零为目标。

**六个版本支柱：**

| 支柱 | 必须交付 | 不是成功标准 |
|---|---|---|
| Tutor runtime | 显式 start → explain/check → interrupt → resume → terminal 的完整闭环 | 把普通聊天意图猜成 tutor；重新造第二个 agent loop |
| Practice ④⑤ | 独立作答、分级 hint、学习者讲解、evaluation draft、可测试升降级 | 强制线性闯关；模型替代确定性判分 |
| Learning Space | 三层主舞台、可访问 flat fallback、白板课最小闭环、场景内小娜 | 游戏引擎、装饰性拟物、通用协作白板 |
| Product pruning | 双 profile 精确白名单、企业微信/Discord/飞书/长尾退场、旧任务安全 | 只从 UI 隐藏；为假设中的未来版本长期背维护成本 |
| UI art | 独立视觉系统、关键帧/状态/资产/交付规格、public+branded 同构 | 功能开发者边写边决定美术；用 hero mock 代替系统设计 |
| R4 + quality | canonical-only producer、新旧升级安全、精确 legacy manifest、完整 release gates | 为追求零命中删除 home/keyring 迁移能力 |

## 1. 非目标

- 不物理改名 `hermes_core/`；它继续表示 owned fork 的源码边界和上游谱系。
- 不删除 Nous Hermes 模型名、ChatML/tool-call parser、外部协议、法律署名、
  release history 或必须兼容的第三方 metadata 名。
- 不重新引入 `HERMES_AGENT_ENGINE` 或任何等价 engine selector；tutor 是显式
  structured activity，不是另一个全局 agent 模式。
- 不把普通 `/chat` 自动转成 tutor，也不把 REPORT/PPT/文档任务强行学习化。
- 不做 Gateway tutor UI、跨设备同步、多人白板、实时协作或身份自动合并。
- 不做通用 solver、完整 CAS、自由证明自动判真或“完全隔离”的代码沙箱承诺。
- 不强制五级梯子线性推进；学习者可从任一级进入，并可直接索取完整答案。
- 不把 evaluation、weak point 或 kq-kp 自动激活为永久能力标签。
- 不引入 three.js、PixiJS、游戏引擎、逼真木纹/皮革位图或 3D 翻页作为理解前提。
- 不因 v0.5 场景工作扩大 IA telemetry：仍保持 default-off、只计数不引用，
  不新增第三方分析 SDK 或未经独立评审的上传 endpoint。
- 不保留企业微信、Discord、飞书/Lark 或任何 profile 白名单外平台的 live adapter、
  依赖、配置、测试和 runtime package；Git 历史是恢复路径。
- 不把 `Platform.LOCAL`、Webhook 或 API Server 当作 Desktop；Desktop 是 Tauri/desk
  product shell，不是外部 gateway adapter。
- 不在 UI 美术 V0-V5 冻结前把设计探索直接写成 production scene CSS/资产；
  semantic flat layout 和功能合同可以先行。

## 2. v0.4.0 继承门与开工边界

当前规划基线为 `main@a27ac48d`。A/C/D 轨已关闭，B 功能链已进入 main；v0.4.0
仍须完成独立的 updater trust-root 与发布物 runbook，不能只因代码合并宣告 release
ready。D 轨最终收口已取得 Rust 97 tests、真实 runtime verifier、Web 自动门与
installed current-data WebView2 证据；pre-D5 Study localStorage 的 installed-NSIS
升级专测由 owner 接受为验证缺口而非通过，兼容 adapters 保留。后续按最终 diff、
既有命令输出和证据时点做 delta audit，只补受影响范围或缺失证据。

v0.5 只继承最终结论，不把以下收口工作倒灌成自身功能：

- 复核既有 Rust 全测、bundle/runtime verifier 证据是否覆盖 D 轨最终提交；若收口只改
  文档或未触及对应边界，则记录复用理由；若触及 Rust、bundle inputs、runtime imports
  或 migration contract，再按影响面补跑 focused/full gate；
- 继承 v0.4 current-data install/child restart 证据；pre-A-R3/pre-D5 Study upgrade 的
  accepted gap 不倒灌为 v0.5 功能开工门，但任何 legacy reader/adapter 删除仍必须先补
  真实旧 app-data installed-upgrade 证据；
- 复用 D-5 WebView2 布局、主题、语言、键盘、200% zoom、reduced motion、离线/重启与
  治理安全证据；不得把未执行的旧 Study installed-upgrade 矩阵写成已通过；
- 冻结 v0.4.0 release tag/branch、manifest、bundle 大小、测试证据索引和已知降级记录。

### 2.1 现在可以开始

- 本总计划与每个切片的设计/威胁模型；
- C-0 平台/工具/依赖/持久化 surface manifest、双 profile 精确白名单，以及企业微信/
  Discord/飞书/长尾删除边界；
- R4 文件名+内容审计、过期文档和明显运行产物清理；
- tutor state machine、checkpoint schema、hint/evaluation、whiteboard artifact 的
  contracts-only 设计与失败测试计划；
- V-0 全屏视觉审计/brief 和 U-0 功能调整 intake；
- 私有品牌仓库中的 v0.5 P1 场景探索，但必须进入 V 轨，不写入公开仓库、不覆盖
  v0.4 overlay，也不直接变成 production CSS；
- 记录 v0.4 release manifest 之后要使用的性能/升级基线脚本。

### 2.2 暂时不得进入 main 的运行时变化

- graph_engine/checkpoint/interrupt 实现；
- Discord/飞书或其他 gateway 的 runtime/source/dependency 删除；
- legacy env/import/home/keyring 兼容删除；
- 新 scene shell、Excalidraw 依赖、白板持久化与新品牌 overlay targets；
- 会改变 v0.4 release bundle、数据库 schema 或 WebView2 验收面的功能代码。

运行时开工门是“v0.4 release 基线已冻结”，不是某个日历日期。若 v0.4 只切
release branch 而 main 转入 v0.5，必须记录该 branch/tag 和回补策略，不能让
v0.5 变更污染未完成的 v0.4 release 证据。

## 4. Workstream C — 产品渠道与依赖裁剪

详细边界、候选清单、迁移和验证见
[v0.5.0 产品裁剪计划](2026-07-17-v0.5.0-product-pruning-plan.md)。总计划只冻结
版本承诺与依赖顺序。

### C-0 · 全量产品 surface manifest（硬门）

- owner 已冻结双 profile：mainland gateway 只含 `weixin/qqbot/dingtalk`，SEA gateway
  只含 `telegram/whatsapp/email`；Desktop shell 两版都保留但不进入 platform enum；
- 企业微信（含 callback）、Discord、飞书/Lark、SMS/Twilio、Slack、Signal、Matrix、
  Mattermost、BlueBubbles、Home Assistant、Webhook/API server、Yuanbao 与 bundled
  IRC/Teams platform plugins 全部进入物理删除；
- manifest 同时覆盖 core adapter、tool、plugin、registry、env/config、Rust、Web、
  requirements、bundle、network hosts、tests、docs、credential/profile/job 数据；
- machine manifest 必须让任何白名单外新增平台直接失败，不能回到默认 auto-load。

### C-1 · 停止生产/启动被删渠道

- visible/autostart、Web Settings、QR/deep link、新 cron delivery 先按 profile 收束；
- stale 企业微信/Discord/飞书/长尾 credential 不再启动 gateway、不扩 network allowlist；
- 旧任务/secret/profile 暂不自动删除，等待 C-4 迁移语义；
- Desktop、mainland 三渠道和 SEA 三渠道先证明不 import 被删平台，再做物理删除。

### C-2 · 企业微信、Discord 与飞书/Lark 物理退场

- 企业微信、Discord 与飞书分别做独立 slice、独立 diff、独立 tests；
- 删除 adapter、专用 helper/tool/script/worker、registry/config、Rust/Web、i18n、
  requirements/transitive package、tests 与 active docs；
- `discord.py[voice]`、`lark-oapi` 和 runtime `lark_oapi` 必须从最终 bundle 退场；
- shared gateway security/media contracts 迁到 retained adapter 测试承接，不能随平台
  tests 一起失去覆盖。

### C-3 · 长尾平台、IRC/Teams plugins 与 gateway kernel 收束

- 按 SMS、协作长尾、设备/自动化、Webhook/API server、plugin platform 分批删除；
- IRC 与 Teams 是会自动加载并向动态 platform registry 注册的 bundled gateway plugins，
  不是 Kabuqina 桌面插件市场能力；两者都删除；
- registry、help、sample config、capability matrix 与最终 retained set 完全一致；
- generic helper 改中性名，只保留 retained 平台实际使用的路径。

### C-4 · 旧凭据、profile、home channel 与 cron job

- 不自动删除旧 secret/profile；提供明确说明与显式清理；
- removed home channel/job target 标为 `unsupported_delivery`，不静默改投桌面或他人；
- 残留旧 env 不 autostart；旧 job 仍可枚举、编辑和删除；
- 记录 Python runtime、site-packages、installer、cold start、依赖/license/advisory delta；
- release notes 公布已删除平台、残留数据和清理方式。

## 5. Workstream R — R4 兼容退场与命名卫生

### R-0 · 精确 legacy manifest 与低风险清理

目标不是重跑一次宽泛 `git grep`，而是建立可长期阻止回流的基线：

- `scripts/audit_a_r3_legacy_names.py` 同时扫描 tracked **内容和路径名**；
- 取消“整个 desktop/docs 目录都算 compatibility/history”的宽泛兜底；
- 每个允许项记录 category、reason、owner、minimum supported source version、
  earliest removal version；未知项和新增项直接失败；
- 区分 forever（上游/法律/模型/协议/`hermes_core`）、stable internal id、
  read-old compatibility、test fixture、history；
- 修正 `docs/ROADMAP.md`、active capability matrix、`kabuqina_core` 过期说明，
  删除 `tauri/Ctemp_hermes_out.txt` 等明显运行产物；历史 incident 文档可保留原名，
  但必须在头部标为 archive 并指向当前权威文档；
- CI/本地门禁止新产品代码、文件名、logger、UI 文案和 canonical API 使用旧名。

**完成定义：** manifest 可机器检查；每个剩余项都有精确分类；新增未分类命中
会失败。`0 defects` 不再依赖宽泛目录 allowlist。

### R-1 · canonical-only producer

先停止生产旧名，再谈删除消费者：

- Tauri 为自有 Python children 只把 `KABUQINA_*` 作为 authoritative contract；
  Python consumer 暂时保留 old-name fallback；
- shell 内部只调用 `/api/kabuqina/*` 与 `X-Kabuqina-Auth`，deprecated route/header
  只为 separately-versioned/old child 保留；
- Web 新写入只使用 `kabuqina.*` storage keys，旧 key reader 必须是隔离 one-shot
  migrator，不能进入日常 UI 状态机；
- canonical-only web child、gateway child、QR workers、cron、approval/secret bridge
  分别启动验证，证明正常运行不依赖镜像的 `HERMESDESK_*`；
- `HERMES_HOME` 与 core/third-party provider env 单独分类，不能和桌面自有
  `HERMESDESK_*` 一把删除。

### R-2 · 可退役 shim、路径与内部 ID

按数据风险拆开：

1. **无状态/临时：** `.hermesdesk_uploads`、临时文件 prefix、日志显示名等改为
   canonical name；旧临时目录可有界清理，不做危险递归猜测。
2. **大缓存：** workspace `.hermesdesk` 下的 STT/load-package 数据若改名，采用
   old-only 原子 rename、both-exist 新目录优先且旧目录不删除；不得触发大型模型重下。
3. **Python/CLI：** `hermes_cli`、四个 `hermes_*` module alias、旧 console scripts
   只有在 core、bundle、active skills/plugins 和 external invocation audit 通过后删除。
4. **API/storage：** legacy route/header/browser keys 以 minimum supported source
   version 为门；producer 已 canonical-only 后才允许删 reader。
5. **稳定数据 ID：** `hermesdesk-reminders`、activity source、plugin metadata key 等
   必须先判断是否是数据库/schema/外部插件契约。用户不可见且迁移收益极低的 ID
   可以永久保留并列为 stable legacy id，不能为观感制造重复 session 或断插件。

### R-3 · 高风险持久化兼容决策

`hermes-home`、`~/.hermes`、`HERMES_HOME`、Credential service `HermesDesk`、
旧 browser Study/profile 数据不能按“v0.4 后就是下一版”机械删除：

- 若 v0.5 仍支持 v0.3 → v0.5 直接升级，old-only home/keyring/storage reader 必须保留；
- 只有 minimum supported source version 明确排除旧版本，且 release upgrade 样本覆盖，
  才能删对应 fallback；
- keyring canonical miss → legacy read/copy-forward 的成本低、数据风险高，默认继续保留；
- explicit sign-out 的 clear-both 默认长期保留，避免遗留旧 secret；
- both-exist 始终新目录获胜且不自动 merge/delete；失败回退不得静默创建空白新家；
- 最终发布说明列出“已删除”“仍兼容”“永久保留”的 manifest，不用总命中数替代语义。

## 6. Workstream L — M7 结构化辅导运行时

### L-0 · Tutor implementation design（硬门）

- `LearningActivityRequest` 与 `LearningInterrupt` 的 versioned wire schema；
- `LearningCheckpointStore` port、revision/CAS、schema migration、retention、space delete；
- checkpoint 与 `learning.db`/artifact/activity 的边界；不得把 checkpoint 变成第二份
  student state，也不得以 chat session/gateway id 为 key；
- crash/restart、duplicate answer、stale revision、two-tab concurrency、cancel race、
  timeout/budget exhaustion 的确定性语义；
- learner-check interrupt 与 tool approval interrupt 的类型、ID、UI、timeout 完全隔离；
- 模型调用预算、每次 resume 最大 node/call/token/time、post-node provider policy；
- prompt/content retention、日志 redaction、checkpoint 禁止字段与 threat model；
- desktop API/Tauri/Web wire、错误 taxonomy、capability readiness 与降级路径；
- graph contract 测试、DB migration test、fresh/upgrade bundle test 计划。

**默认方向：** checkpoint 通过 core 中的 port 持久化，具体 adapter 优先评估
`learning.db` 的独立表；无论采用何处，都必须跟随 owner/space 删除并保持 revision
并发控制。禁止直接把完整 graph state 塞入 Web localStorage 或 `state.db` chat session。

### L-1 · Checkpoint 与 activity lifecycle

状态机固定为：

```text
created → running → waiting_for_learner → running
                         └──────────────→ cancelled
running → completed | blocked | cancelled
```

- key 至少绑定 owner + space + activity_kind + explicit activity id；
- 每个 activity 最多一个 unresolved learner-check；
- save/clear 使用 expected revision；stale writer 不得覆盖；
- duplicate/stale/cross-owner/cross-space answer 在推进 graph 前拒绝；
- disconnect 只保留 pending，不自动继续、重试、投递或唤醒 cron；
- completed/cancelled activity 只能通过显式 new request 重开；
- checkpoint 不包含 API key、tool credential、raw source document、gateway id；
- space/owner secure delete 与导出策略必须明确，不能留下不可枚举 orphan。

### L-2 · 最小 tutor graph 纵切

先交付最小但真实的闭环，不一次实现所有教学策略：

```text
start/probe → explain one bounded concept → learner_check interrupt
resume(answer) → validate → terminal completed 或一次 remediate → learner_check
```

- 用户从 `/study` 显式开始；普通 `/chat` 不做 intent detection；
- explain 节点必须经 `handoff_to_learner` 边结束，不能因模型“感觉说完”自由续写；
- 每次 resume 有硬 node/call/time/token budget；耗尽返回 user-visible `blocked`，不死循环；
- cancel 在任何等待点可达；工具副作用仍走现有 approval，不与 learner check 混用；
- desk child restart 后能恢复同一 pending check；两窗口竞争只有一个 revision 成功；
- Web 先做普通可访问表单/choice/step surface，再叠场景视觉。

### L-3 · LG4 advance/remediate 条件边

- 输入只取受信 attempt/check 结果、bounded weak-point projection、显式 hint request；
- 策略函数确定性返回 `advance / remediate / hint / complete / blocked`；
- branch decision 与 policy version 写 checkpoint metadata，便于 golden test 和审计；
- 对已掌握内容默认推进，不强迫苏格拉底；练习场景 hint-first，但用户直接索取答案
  时遵守 answer-then-teach；
- 不用模型自由文本决定 owner、space、revision、是否通过或是否激活 evaluation。

### L-4 · LG3 kq-kp v2 post-node

- 主模型不再负责在正文尾部稳定输出 raw `kq-kp` block；
- post-node 只接收 bounded visible assistant answer，输出现有 versioned knowledge-point
  candidate schema；规则/廉价模型优先，失败静默且不污染主消息；
- candidate 仍经现有 capture/draft/用户动作进入学习存储，不自动成为事实；
- desktop/gateway/chat export/TTS 均证明不会暴露 fenced raw block；
- 只有 v2 在所有 surface 达到 parity 后，才退役 H1 的 desktop-only prompt 门控。

### L-5 · H4 tutor-aware compression 与成本治理

- learner utterance、错误答案、当前 unresolved check、branch reason 为高保留级；
- tool noise、重复解释、已物化的旧 observation 可压缩；
- compression 不复制 raw source document 或 secret 进 checkpoint；
- golden tests 证明“学习者说错的关键句”在长 activity 中仍可用于 remediate；
- cheap post-node、semantic evaluation 和主 tutor 调用分别计费/限额；
- budget/retry/fallback 可观测，但不把学习内容写入 usage/IA telemetry。

## 7. Workstream P — M8 练习梯子④⑤

### P-0 · 合同与交互设计

在现有 `quiz` code/derivation、sandbox grader、M4 evaluation 和 D-3 PracticePage
上增量设计，不发明第二套练习仓库：

- level ④ independent attempt 与 hint ladder 的 request/result/activity schema；
- hint 层级、最大次数、直接看答案、resume/retry、cost 和 failure semantics；
- level ⑤ learner explanation 的 bounded input、semantic rubric、review failure/pending；
- evaluation draft 的 source evidence、tags/weak-point 最小化、user activate/reject；
- LG4 消费哪些确定性字段；自由文本不进入 telemetry、URL 或 branch predicate；
- code/derivation/choice/free-text 各自的适用边界和不可判定状态；
- Web editor/推导板、键盘、离开确认、窄窗、离线和 desk restart 状态矩阵。

### P-1 · Level ④ 独立练习与 hint service

- 现有 grader 继续决定 pass/fail；模型不能给自己的题或答案判通过；
- hint 至少分“概念方向 → 定位下一步/错误 → 局部脚手架 → 显式完整解答”，
  但不强制逐级解锁；学习者可跳级或直接索取答案；
- hint 只暴露当前层允许的信息，不能从 `reference`/`test_code` 意外泄漏答案；
- timeout、ungradable、sandbox failure 与 wrong answer 分开；
- hint 请求/使用记 bounded activity evidence，不保存不必要的模型推理或 telemetry 文本；
- code sandbox 的既有残余网络/本机权限风险继续显式披露，不借 v0.5 UI 淡化。

### P-2 · Level ⑤ 讲解/费曼评估

- 学习者先讲，模型按 versioned rubric 找缺口并追问；
- 语义 evaluator 不可用时停 `pending`，不自动通过、拒绝或重试到超预算；
- evaluator 只能创建 `evaluation` draft；用户审核后才 active；
- 不从一次讲错永久标记能力；weak point 只来自有界 tags/evidence projection；
- prompt injection、超长输入、source spoofing 与跨 space 引用有测试；
- 评估结果可被 LG4 用于 remediate，但 branch 只读结构化/受信字段。

### P-3 · 与 tutor graph 汇合及 Practice UI 收口

- level ④/⑤ 是同一 structured activity 的 practice/teach 分支，不复制 checkpoint；
- PracticePage 中编辑器/推导板占主舞台，小娜进入旁注栏；
- 非线性入口清晰可见：示范、临摹、变式、独立、讲解均可直接选择；
- 系统可以基于证据“建议”级别，不自动锁定或隐藏其他级别；
- wrongbook retry、plan resume、due review 与 tutor activity 的 URL/context 不串 space；
- completion/activity/evaluation 写入后，Plan/Evaluate/Learning Index 通过既有事件刷新。

## 12. 数据、安全、隐私与成本硬门

### 12.1 Owner/space 与并发

- 所有 activity/checkpoint/interrupt/artifact/API 显式绑定 owner + space；
- Web URL 中只允许 enum 和 opaque id，不出现题目、回答、标题、source excerpt；
- desktop 与 gateway 是不同进程/owner surface，不假设共享内存；
- stale revision、duplicate answer、two-tab race、restart 恢复必须有真实 DB 测试；
- secure delete 同时处理 checkpoint、whiteboard、evaluation draft 与 derived preview。

### 12.2 Prompt 与不可信内容

- learner answer、source excerpt、whiteboard text、grader output 均为不可信内容；
- 不可信文本不能决定 tool approval、owner、space、revision、schema、pass/fail 或 branch；
- sandbox output 继续截断并不直接进入模型；semantic evaluator 输入/输出均有大小上限；
- 日志、exception、IA/usage event 禁止学习正文、答案、白板文本和 source_refs。

### 12.3 成本与停止条件

- 每次 start/resume 有硬 node、LLM call、token、wall-clock budget；
- cheap post-node 与 main tutor/evaluator 分账，失败不得无界 fallback 到昂贵模型；
- reviewer 不可用停 pending；budget exhaustion 终止为 blocked；
- background cron 不自动恢复 tutor；网络/desk child 重连不自动制造模型 turn；
- release 文档公布可能发生额外模型调用的功能，不把“nearly free”写成“free”。

- canonical runtime imports 不依赖 legacy shims；若保留 shims，独立 legacy verifier 通过；
- bundle manifest 中无测试 sink、fixture、private master、dev server、被删平台 SDK 或
  未声明模型权重；retained set 在 Python/Rust/Web 完全一致。

- 两个 space 深链、switch、wrongbook retry、plan resume、draft refresh 不串本；
- Companion/scene state 与通知/复习完成不双发；
- Settings 不出现企业微信/Discord/飞书和长尾平台；旧 deep link/profile/credential 有明确
  unavailable/cleanup 行为，不产生网络或消息副作用；
- V-5 冻结的关键屏幕逐项 visual diff/人工验收，无重叠、截字、低对比和焦点丢失；
- telemetry evidence 不含本轮 fixture 文本/id。

## 15. 降级路径与不可降级项

| 风险 | 允许的降级 | 不允许的伪完成 |
|---|---|---|
| 场景 IA 证据不足 | 先交付 flat 三栏 Learning Space，减少昂贵 P1 美术 | 用 mock/主观判断声称“数据验证了完整场景” |
| 白板依赖/体积/安全门失败 | 保留 DOM+KaTeX 推导板，白板延期 | 临时自研未审计 canvas 或把依赖塞首屏 |
| 品牌私有资产未就绪 | 官方/公开 build 都用中性占位 | 把私有 master commit 到公开仓库 |
| UI 美术 V-5 未冻结 | 发布 semantic flat layout，场景视觉延期并如实改版本声明 | 开发者自行补一套临时美术并声称视觉完成 |
| retained 渠道某项尚未可用 | 该 profile 暂不发布或明确降级，不回填长尾替代 | 留下不可安装、不可测试、仍扩攻击面的半平台 |
| eligible shim 退役证据不足 | 保留精确 allowlist 和 reader | 为命中数好看删除 home/keyring 数据路径 |
| kq-kp v2 不稳定 | 保留 H1 desktop prompt 门控 | 主消息或 Gateway 暴露 raw fenced block |
| Companion 合并未稳 | 保留单一旧 Companion fallback | 场景杯与 Companion 双状态/双通知 |

**不可降级：** M7 start→interrupt→resume→terminal 的 owner-safe 闭环、M8 ④⑤的
真实学习者动作与 draft trust boundary、确定性 grader 真值、checkpoint revision、
learner/tool interrupt 隔离、企业微信/Discord/飞书/Lark/长尾 live surface 退场、removed target 不静默
改投、数据删除/升级安全、正常运行 canonical-only 证明。
若这些未完成，不能以“场景已做好”为由宣告 v0.5.0 学习里程碑完成。

## 16. 风险登记

1. **Tutor graph 变成第二个 agent loop。** 缓解：只实现 explicit structured
   activity，复用 graph_engine/tool/approval/provider；L-0 架构 review 先行。
2. **Checkpoint 变成第二份 learning database。** 缓解：只持久化恢复 graph 所需
   状态；student state/artifact/activity 继续经现有 services；投影与漂移测试锁定。
3. **Learner interrupt 与审批混淆。** 缓解：不同 type/id/store/UI/timeout，cross-use
   contract test；learner answer 永不授权副作用。
4. **并发/重放推进两次。** 缓解：revision CAS、exactly-once resume、two-tab/crash tests。
5. **模型成本和 loop runaway。** 缓解：每 resume 硬预算、pending/blocked 明确终止、
   cheap post-node 不无界 fallback。
6. **语义评估固化错误标签。** 缓解：evaluation 只产 draft、用户激活、weak-point
   bounded evidence、单次错误不永久化。
7. **Whiteboard 成为供应链和包体黑洞。** 缓解：依赖复审、route-level lazy、
   element allowlist、DOM fallback、失败即延期而非自研。
8. **Scene 牺牲可访问性。** 缓解：同一 DOM 的 flat fallback；200%/键盘/reduced
   motion 是合并门，不在最后补票。
9. **Compat cleanup 导致跳版用户丢数据。** 缓解：以最低支持来源版本为退场门，
   home/keyring reader 与 clear-both 默认保留。
10. **三大轨同时改 hot files。** 缓解：L/P/S/R 独立 slice/worktree；依赖链只在
    固定 commit 汇合；机械改名不与 graph/DB/schema/UI 重构混 commit。
11. **品牌资产泄漏。** 缓解：Tier 2 whitelist、private leak scan、apply/build/restore、
    public placeholder 为默认事实来源。
12. **v0.4 release 证据被 v0.5 污染。** 缓解：运行时 merge 等 release baseline/tag，
    release branch 回补有记录，不能用 v0.5 bundle 代替 v0.4 验收。
13. **只隐藏渠道而没有真正裁剪。** 缓解：C manifest 同时检查源码、registry、依赖、
    runtime package、Rust/Web、测试和文档；bundle 验证是完成门。
14. **删除平台导致旧 reminder 投错人。** 缓解：removed target 进入显式
    `unsupported_delivery`，绝不自动改投 desktop/其他渠道。
15. **未来 profile 假设无限保留代码。** 缓解：保留必须有 owner、场景、发布承诺、
    smoke 与成本；Git history 是默认恢复机制。
16. **功能实现吞并 UI 美术决策。** 缓解：S 只做 semantic surface；V-5 是 scene art
    merge gate；冻结后用 design delta 变更。
17. **新增升级要求造成 scope 无界。** 缓解：U register、Must 替换成本、scope freeze，
    Could 默认移到 v0.5.x/0.6。

## 17. 版本完成标准

v0.5.0 只有同时满足以下条件才可宣告完成：

- v0.4 release 基线和全部继承门有最终证据；
- M7：显式 tutor activity 可 start/resume/cancel/recover，checkpoint owner/space/revision
  安全，H2 结构性 handoff 生效；
- M8：④独立+hint 与⑤讲解+evaluation draft 可用，LG4 分支可测试且非线性；
- LG3 kq-kp v2 或明确保留的安全 H1 fallback 保证所有 surface 无 raw block；
- H4 长 activity 保留 learner error evidence，成本/停止条件可观测且有上限；
- C：双 profile 精确白名单和隔离生效；mainland 的微信/QQ Bot/钉钉与 SEA 的
  Telegram/WhatsApp/Email 均有正式 runtime smoke；企业微信、Discord、飞书/Lark、
  长尾与 IRC/Teams plugins 的 live adapter/tool/config/Rust/Web/dependency/runtime
  package 退场；旧 target 无静默改投；
- M9：Learning Space 在宽屏有场景、窄窗/读屏有等价 flat layout；白板最小闭环
  通过，或按 §15 明确降级且不伪称完成白板课；
- V：独立视觉轨已有 P0 token/state/responsive/asset/handoff 冻结和 owner sign-off；
  若按 §15 降级为 flat layout，release scope/截图/notes 必须同步改写；
- U：所有 Must 已完成或明确从 v0.5 scope 移除，Should/Could 有版本归属；
- R4：正常运行 canonical-only；每个剩余 legacy 内容/路径都有 manifest；升级数据安全；
- placeholder 与 branded 两条资产构建链都通过且私有 master 未进入公开仓库；
- Core/Python/Rust/Web/bundle/WebView2/upgrade/security/privacy/performance gates 全部关闭；
- P0/P1 为 0，P2 已接受或明确延期，release notes/DECISIONS/QA/roadmap 与真实实现一致；
- worktree clean，最终 review PASS 后才 commit/push/tag release closeout。
