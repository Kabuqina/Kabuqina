状态：**待评审**　·　日期：2026-08-27　·　目标版本：0.5.0

本文把最新平板原型拆成可并行开发、可逐段联调的工程工作包。视觉模型的具体厂商、SKU 和 API
仍由 owner 后续确认；在此之前使用 versioned mock，不阻塞 UI、图片摄入、数据合同和错题存储。

## 0. 结论：适合分离开发，但应按三条工程线组织

**适合前后端分离。** 现有代码已经具备天然边界：React 只通过 Tauri command 调用桌面能力，
Tauri 再代理 loopback Python API，学习语义落在 `hermes_core`。

但这不是普通 Web 项目的“前端 / 服务端”两层，而是三条线：

| 工程线 | 主要目录 | 负责 |
|---|---|---|
| 产品前端 | `web/` | 三面 IA、本子状态、拍照/上传入口、裁剪交互、转写确认、提示、讲评、卡片盒、窄屏与可访问性 |
| 桌面平台 | `tauri/` | Windows 摄像头/文件路径边界、临时图片、Tauri command、视觉凭据、子进程注入、loopback 代理 |
| 学习后端 | `python/` + `hermes_core/` | API 编排、预处理、结构化视觉转写、提示/讲评语义、外部错题生命周期、受管媒体、导出与删除 |

如果团队只能分成前后端两组，**Tauri 归后端组，并指定一名集成 owner**。不建议让前端组和 Python
组各自做完后再联调；拍照、视觉信任和图片生命周期都跨层，必须按纵向切片逐段打通。

推荐并行方式：

1. 先冻结 v1 wire contract 和 mock fixtures；
2. 前端基于 mock repository 开发完整状态机；
3. 桌面平台和学习后端实现相同合同；
4. 每完成一条合同就做一次真实纵向联调，不等全部完成。

## 2. Phase 0 必须冻结的决策与合同

Phase 0 未完成前，前后端可以做视觉样式和纯函数，但不得各自发明字段。

### 2.1 IA 路由口径

三个 slug 表示三个**可深链的桌面状态**，不是三张互相替换的普通页面：

- `/notebook`：本子工作态；`学 / 练` 原地切换，共享知识核游标；
- `/cards`：保留本子上下文并打开卡片盒；关闭后回到原 notebook 状态；
- `/bookend`：保留本子上下文并打开书立/材料；扉页作为本子的第一页。

旧 `/flyleaf` 的精确落点需在 Phase 0 评审锁定。推荐：重定向到
`/notebook?view=flyleaf`；旧 `/plan` 进入 `/bookend`。如果坚持二者都去 `/bookend`，则
`bookend` 必须能恢复到扉页子态，不能只打开材料列表。

### 2.2 Renderer 状态机

状态必须拆成正交维度，不复制原型的单一数字 `step`：

```text
surface: notebook | cards | bookend | flyleaf
mode: learn | practice
capture: idle | choosing | cropping | submitting | transcribing |
         confirming | assisting | reviewing | failed
captureSource: camera | upload
purpose: stuck | review | printed_source
```

刷新/返回只恢复可持久化身份（space、surface、mode、knowledge core、capture_id）；摄像头 stream、
Blob URL 和临时预览不持久化。

### 2.3 CaptureSessionV1

建议在 `hermes_core/learning/study_capture_contract.py` 冻结 Python validator，并在
`web/src/chat/study/study-capture-api.ts` 写对应 TypeScript 类型与 fixtures。

```json
{
  "schema_version": 1,
  "capture_id": "client-generated-idempotency-id",
  "space_id": "course-id",
  "purpose": "stuck|review|printed_source",
  "source_kind": "camera|upload",
  "status": "temporary|normalized|transcribed|drafted|confirmed|abandoned",
  "revision": 1,
  "preview": { "width": 1280, "height": 960 }
}
```

约束：

- renderer 不得到后端受管文件的绝对路径；
- `capture_id` 是所有重试、升档和错题确认的幂等身份；
- 上传图片和拍照只在来源阶段不同，之后进入同一 normalize/transcribe 管线；
- 未确认图片只存在临时目录，应用退出/超时/取消后可回收。

### 2.4 CaptureTransformV1

```json
{
  "schema_version": 1,
  "capture_id": "...",
  "expected_revision": 1,
  "crop": { "x": 0.08, "y": 0.12, "width": 0.82, "height": 0.64 },
  "rotation": 90,
  "grayscale": false,
  "max_edge": 1280
}
```

裁剪坐标统一为 0..1；rotation 只允许 0/90/180/270；灰度可撤销。前端负责即时预览，本机
Python/Pillow 负责生成送视觉模型的 canonical normalized image，避免浏览器与后端各算一套尺寸。

### 2.5 StudyTranscriptionV1

沿用需求 R3/R4 的字段，并补上上下文核对：

```json
{
  "schema_version": 1,
  "capture_id": "...",
  "purpose": "stuck",
  "question_text": "...",
  "student_work": "...",
  "lines": [],
  "unreadable_regions": [],
  "confidence_band": "high|medium|low",
  "question_match": "same|different|unknown",
  "provider": "internal-only",
  "model": "internal-only"
}
```

`provider/model` 可持久化供质量回溯，但 renderer 的学生视图不显示。`question_match != same` 时，
后端不得直接生成当前题提示；`unreadable_regions` 涉及关键行时，不得基于该行给确定性讲评。

### 2.6 Assistance / Review / Wrongbook 合同

- `StudyAssistanceV1`：`mode=next_step|full_answer`。默认 `next_step` 只能有一个方向提示；
  `full_answer` 必须由学生显式触发，并返回知识点与跳过项。
- `StudyReviewDraftV1`：只允许“从哪一步开始偏 + 依据 + 不确定项”，没有自动分数和 mastery。
- `ExternalWrongbookEntryV1`：`draft → confirmed → active`，绑定 `capture_id`、media ID、题干、
  我的写法、正确写法、知识点、讲评、确认状态和时间戳。
- 确认动作固定为 `wrong|correct|unreadable`；只有 `wrong` 可以把 draft 推到 active。

### 2.7 统一错误码

前端只依赖稳定 code，不解析英文异常字符串：

```text
capture_camera_unavailable
capture_permission_denied
capture_invalid_image
capture_too_large
capture_revision_conflict
vision_not_configured
vision_unavailable
vision_contract_invalid
vision_unreadable
capture_question_mismatch
wrongbook_idempotency_conflict
```

每个错误必须说明：是否可重试、临时图是否保留、应该回到哪个 UI 状态。

## 3. 目标调用链与层级归属

```text
React Study
  ├─ 拍照：getUserMedia → canvas JPEG bytes
  └─ 上传：Tauri dialog → selected path
          ↓
Tauri capture command
  ├─ 校验来源、格式、大小
  ├─ 写 app-data 临时 capture 目录
  └─ 只把 capture_id / managed path 交给 loopback Python
          ↓
Python desk capture routes
  ├─ Pillow canonical crop/rotate/grayscale/resize
  ├─ 调 hermes_core Study capture service
  └─ 管临时媒体与确认后的受管 media
          ↓
hermes_core learning
  ├─ structured vision transcription
  ├─ question-match / unreadable fail-closed
  ├─ next-step / full-answer / review contracts
  └─ external wrongbook + cards projection
          ↓
Vision provider（仅首次转写带图） / DeepSeek（后续只带结构化文本）
```

关键边界：

- React 不读取 Credential Manager，不拼 provider prompt，不直接管理 app-data 文件；
- Tauri 不复制学习/讲评语义，只做 Windows、secret、文件和可信代理；
- Python route 不复制 wrongbook/提示规则，只做桌面编排；
- `hermes_core` 不 import Tauri/FastAPI，不感知 Windows toast、WebView 或绝对 app-data 路径。

## 4. 实施工作包与并行关系

### Phase 0 — 合同与两个技术 spike（2–3 人日）

| ID | Owner | 任务 | 退出条件 |
|---|---|---|---|
| C0 | 前后端共同 | 冻结 §2 的 JSON fixtures、错误码、状态机 | FE mock 与 Python validator 消费同一组 golden fixtures |
| P0 | 桌面平台 | Windows WebView 摄像头 spike：权限拒绝、无设备、拍照、释放 stream | 在目标 Windows 10/11 机器证明可行；失败时“上传图片”始终可用 |
| V0 | 后端 | 用 fake vision adapter 返回合法/非法/不可读/串题四组结果 | 不依赖真实千问 SKU/API 即可跑 contract tests |
| IA0 | 前端 | 冻结旧 URL 与三状态路由映射 | route tests 明确 replace、history/back 和 scratch notebook 行为 |

**Gate 0：** C0、P0、V0、IA0 全部完成后，才允许大面积改 `DeskNotebook.tsx` 和生产路由。

### Phase 1 — 三面 IA 与原型静态落地（前端主线，4–6 人日）

- `routeModel.ts` 的 `PAGE_SLUGS` 五 → 三，补旧 URL replace redirect；
- `StudyPageOutlet.tsx` 收敛为 notebook/cards/bookend 状态，不再挂五个独立页面；
- `DeskNotebook.tsx` 删除五分页 tabs，改为本子页眉、学/练原地切换、两页结构；
- 复用 `DeskBookend`、`DeskCardReview`，将其改为覆盖面板而非替换整个本子；
- 扉页只留课程/范围/目标，材料导入不是建本前置；
- 先接 `MockStudyCaptureRepository`，完整跑通原型状态；
- 窄布局优先修复物件重叠、双页独立滚动和关键动作下沉；
- 可点击物件使用真实 button/link，补键盘、焦点、44px+ 命中区。

本阶段与 Phase 2/3 可并行，但 `routeModel.ts`、`StudyRoute.tsx`、`DeskNotebook.tsx` 由前端线独占，
其他分支不得同时重构这些热文件。

### Phase 2 — Windows 摄入与本机预处理（平台 + 后端，5–7 人日）

#### 前端

- 新增 `StudyCaptureChooser`：只显示“拍照 / 上传图片”；
- 拍照使用 `getUserMedia`，明确 permission denied / no device；关闭时停止所有 MediaStream track；
- 上传复用 `@tauri-apps/plugin-dialog`，只接收 png/jpeg/webp；
- 新增裁剪、旋转、重裁、可撤销灰度 UI；
- renderer 生成预览，不把 provider、token 或绝对路径显示给学生。

#### Tauri

- 新建 `tauri/src/study_capture.rs`，避免继续膨胀 `study.rs`；
- `cmd_study_capture_stage_upload(path)`：校验用户选择、真实 MIME、文件大小后复制到临时目录；
- `cmd_study_capture_stage_camera(bytes)`：限制 payload、验证 magic bytes 后写临时目录；
- 新增 normalize/transcribe/abandon/confirm 的 proxy command；
- command response 只返回 capture wire，不返回 secret 或 managed absolute path；
- 注册到 `lib.rs`，补 path traversal、伪扩展名、oversize 和清理测试。

#### Python

- 新建 `desk_server/routes/study_capture_routes.py`；
- 新建桌面 `study_capture_media.py`，负责 temp/managed media、SHA-256、原子移动和孤儿清理；
- Pillow 执行 canonical transform；所有输出限制在 app-data capture 根；
- 取消、失败、超时删除临时图；确认前不得进入长期 media。

**Gate 1 纵向切片：** 使用 fake vision，从“上传图片”真实选一张图，经 Tauri/Python 裁剪后返回
normalized capture；随后同样跑一遍摄像头路径。两条路径从裁剪后开始必须产生相同 wire。

### Phase 3 — 独立视觉路由与结构化转写（平台 + core，5–8 人日）

#### 视觉配置与 secret

- 在 `secrets.rs` 增加独立 `VisionProviderConfig`，Credential account 使用 `vision:<provider>`；
- `bridge.rs` 增加独立一次性 vision secret token，不复用主模型 token；
- `python_supervisor.rs` 给 web child 注入 vision 非秘密字段和 secret URL；gateway child 独立握手；
- `network_policy.py` 同时加入主模型与 vision host；普通模式可用；
- Settings 只显示 provider/model/base URL/是否已配置，不回显 key。

#### core 视觉合同

- 新增 `study_capture_contract.py`、`study_capture.py` 和 injected `StudyVisionPort`；
- production adapter 可复用 `vision_tools` 的本地图与 router，但必须把自由文本收口为 exact JSON；
- 供应商输出解析失败、缺字段、未知字段、关键区域不可读全部 fail closed；
- picture 只调用视觉模型一次，后续提示/讲评只传 `StudyTranscriptionV1`；
- provider/model 写内部质量记录，不进入学生能力画像和普通 UI。

**Gate 2 纵向切片：** fake adapter 的 high/low/malformed/mismatch 四条 E2E 通过。真实供应商仅在 owner
确认 SKU/API 后替换 adapter 配置；不得为了等供应商停住 Gate 2。

### Phase 4 — 下一步提示、讲评与外部错题（后端主线，7–10 人日）

- `purpose=stuck` 默认只产出一个 next-step hint；显式 full-answer 才返回答案、知识点、跳过项；
- `purpose=review` 产出待确认讲评，不生成自动分数；
- question mismatch 先让学生确认题目上下文，不把别题照片并入当前知识核；
- unreadable 只允许讲看清的部分，不得引用不可读行作确定性判断；
- 在既有 learning artifacts/items/activities 上实现外部错题，不另建第二数据库；
- `capture_id` 作为 stable idempotency key；同图重试不得生成两条错题；
- `WrongbookService.projection()` 合并 quiz attempt 与 external active entries；
- `retry_target()` 能解析纸上错题的重做目标，同时保持旧 app 错题兼容；
- 确认 wrong 后原子移动 normalized image 到受管 media，数据库只存 media ID + SHA-256；
- correct/unreadable/取消不会创建 active entry。

**Gate 3 纵向切片：** 一张纸上错题无需打字完成：上传/拍照 → 转写确认 → 待确认讲评 →
“确实做错” → 卡片盒 → 重做一次。同一 `capture_id` 重放仍只有一条记录。

### Phase 5 — 卡片盒、书立、数据治理与代码练习退场（5–7 人日）

- 卡片盒统一显示到期卡片、app 错题和纸上错题，不分两个入口；
- 书立只陈述知识点、练习、照片、材料的历史，不做掌握度报告；
- `printed_source` 复用拍照/上传和裁剪管线，但印刷体可走本机 OCR；
- 学习数据导出包含 external wrongbook metadata 和受管媒体 manifest；
- 一键删除覆盖数据库记录、临时目录和受管照片，并扫描孤儿文件；
- 删除 `CodePracticeSurface` 产品入口和新建 code quiz 路径；历史 code quiz 只读；
- 把 `check_numeric_equivalence` 拆出/保留，锁住推导题回归。

代码练习撤除会触碰 `DeskNotebook.tsx` 和 quiz contract；应在 Phase 1 UI 结构稳定后串行落地，不与
同一热文件的 IA 重写并行合并。

### Phase 6 — 真实供应商、整体验收与发布证据（4–6 人日）

- owner 确认视觉供应商、SKU、base URL、价格和备案口径；
- 用 20–30 张真实学生手写图跑对比，记录读对率、版面保持、承认读不出的比例；
- 普通模式、非超级用户完成一次真实视觉调用；
- 扫描 app data、配置、日志、crash report、子进程命令行，不得出现视觉明文 key；
- Windows 10/11、无摄像头、拒绝权限、断网、供应商超时、低置信度、串题、重复确认全部走查；
- 横屏和 ≤720px 窄布局通过触屏、键盘、焦点、缩放与屏幕阅读器冒烟测试；
- 完成 S1→S6 出货回路，更新 `DECISIONS.md` 与发布证据。

## 9. Stop rules

- 真实学生样本上出现高比例静默编造：停止出货，不用提示文案掩盖模型问题；
- `unreadable_regions` 被后续讲评当作已读内容：测试必须失败；
- question mismatch 仍能直接生成当前题答案：测试必须失败；
- 视觉 key、图片 base64、原始作业正文进入日志或命令行：停止发布；
- 删除条目后存在孤儿图片，或导出缺少外部错题：停止发布；
- 摄像头权限不可靠时可以显示不可用，但不得挡住上传图片；
- 不得为赶排期恢复自动判分、默认完整答案或代码练习入口。
