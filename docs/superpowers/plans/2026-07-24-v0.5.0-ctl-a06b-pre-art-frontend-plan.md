## 2. 实施范围

### A. Direct full course Chat + exact return

- 定义并验证 versioned `StudyChatHandoff`：课程、当前题/步骤、用户问题、来源 surface、
  显式 return target、focus anchor 和 revision。
- 杯子与“让小娜陪我补这一步”先打开可审核的提问卡，再进入真实 `/chat`。
- Chat 显示课程 context/return bar；课程 session 与普通 session 显式区分，不自动继承
  当前课程。
- handoff 与 session 绑定在本地恢复层；重载 Chat 后仍可返回。解绑必须是显式动作。
- 返回练习时恢复原题、原答案、反馈附近的键盘焦点；目标失效时回课程安全概览。
- shipping baseline 只做 direct full Chat；wide sidecar 仍是后续渐进增强。

### B. 制作 / 成果工作夹

- 工作夹成为真实可操作 surface，不再是“未来功能”公告。
- “制作”只允许用户显式勾选当前课程真实材料，再把可审核请求送入同一 Chat/Create
  能力面；不得默认携带整个知识库。
- “成果”只展示有真实记录支持的对象；在 typed deliverable store 未接入前显示可信空态，
  不再从消息文本或 Windows 路径正则伪造课程成果。
- Create 请求保留来源和返回书桌合同；不自动写入 mastery、计划完成度或 active artifact。

### C. Activity / Recent

- Product chrome 的 Activity 打开真实活动 surface，消费现有 Study activities 与可验证
  Chat session read model。
- 展示 empty/loading/error/retry 与最近活动；不在桌上增加票据家具。
- selected activity 必须显式；不得静默把“最新”当作当前活动。

### D. 完整前端状态与降级

- 练习五题型、overview/focused/dirty/checking/needs_revision/completed、刷新恢复、失败重试、
  离开保护继续沿用 `CTL-A06a` 合同。
- 开新本、课程切换、材料、卡片复习、Settings、五页生命周期均有真实入口或诚实空态。
- `720px`、200% reflow proxy、键盘焦点、reduced motion、loading/error/empty 均可达；
  DOM 顺序不因优先级动态重排。
