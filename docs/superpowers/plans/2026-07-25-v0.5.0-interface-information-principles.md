# v0.5.0 界面信息原则：完整结构，克制呈现

> **日期：** 2026-07-25  
> **状态：** `OWNER DIRECTION CONFIRMED · PRODUCT PRINCIPLE`  
> **适用范围：** Kabuqina v0.5.0 的 Study、Studio、Chat、Activity、全局导航与后续前端重构。  
> **上游架构：** `2026-07-25-v0.5.0-study-studio-product-architecture.md`

## 1. 核心判断

> **产品结构可以完整，但单个界面必须克制。**

Study、Studio、Chat 与 Activity 可以拥有完整的领域对象、状态和连接关系，但这些结构不应
同时铺在用户眼前。界面的职责不是证明系统有多完整，而是让用户清楚地知道：

1. 我现在在哪里、正在做什么；
2. 为完成当前动作，我必须知道什么；
3. 我下一步可以做什么。

不服务于这三个问题的信息，即使真实、正确、重要，也不应默认占据当前界面的注意力。

## 2. 每个界面的默认信息预算

v0.5.0 采用**两层界面预算**：只呈现 P0 当前任务和 P1 必要上下文。P2、P3 不进入当前
产品界面，也不因为“以后可能有用”而预留卡片、侧栏、标签或入口。

一个稳定界面默认只保留三层信息：

### 2.1 当前任务

- 当前页面只回答一个主要问题；
- 页面标题描述用户任务或当前对象，不重复解释产品架构；
- 同一视觉区域不并列多个同等级目标。

### 2.2 必要上下文

- 只显示完成当前任务不可缺少的来源、状态或约束；
- 上下文应尽量压缩为一行、一处或一个可展开入口；
- 不重复显示标题、面包屑、状态卡和说明文案中已经表达过的信息。

### 2.3 下一步动作

- 默认只有一个明确主动作；
- 次要动作应降级为文本按钮、菜单或后续步骤；
- 当前不可执行、当前不需要或仅用于解释系统能力的动作不应常驻。

## 3. 信息优先级

所有界面信息按以下顺序决定是否出现：

| 优先级 | 信息类型 | 默认处理 |
|---|---|---|
| P0 | 当前任务与主动作 | 直接呈现 |
| P1 | 完成当前任务必须知道的上下文 | 简洁呈现 |
| P2 | 可回看、可恢复、可展开的辅助信息 | 当前版本先砍掉，不预留界面入口 |
| P3 | 产品架构解释、边界说明、原型状态、开发信息 | 砍掉，不进入产品界面 |

“真实存在”不等于“必须可见”。当前版本不为 P2、P3 做折叠态或占位态；只有后续真实任务
证明某项信息不可缺少时，才重新定义为 P1 并进入界面。

## 4. 渐进呈现原则

- 默认先显示结论，再允许用户查看来源或细节；
- 默认先显示当前项，再允许用户打开列表、历史和其他空间；
- 默认先显示下一步，再允许用户展开完整流程；
- 渐进呈现只服务于 P0、P1 内部的必要细节，不用于给 P2、P3 保留入口；
- 低频辅助信息、完整日志、来源清单、产品边界说明和原型状态在当前版本直接砍掉；
- 系统可以在底层保留状态，但产品界面不为未验证需求建立可见结构。

以下情况不得为了“极简”而隐藏：

- 未保存修改；
- 不可逆或高风险动作；
- 当前作用域可能造成误写；
- 用户必须确认的跨域写入；
- 错误、失败或恢复所必需的信息。

极简不是删除安全反馈，而是删除与当前决策无关的解释和装饰。

## 5. 各产品面的应用

### 5.1 Study

Study 的五页可以拥有完整对象，但每页只突出自己的当前任务：

- **扉页：** 本课程目标和最重要的学习设定；
- **计划：** 当前计划项和下一步；
- **学习：** 当前知识内容与一个继续动作；
- **练习：** 当前题、我的答案和检查；
- **评估：** 当前结论与下一项调整。

课程列表、材料、卡片、历史证据和跨域连接不得在每一页同时争夺注意力。当前任务不需要的
部分先从界面砍掉，而不是全部保留为入口。

### 5.2 Studio

Studio 默认只突出：

1. 当前 Project 的表达目标；
2. 当前阶段或正在处理的内容；
3. 下一步制作或梳理动作。

只有当前动作离不开来源或写入边界时，才以 P1 身份出现；项目历史、完整版本和未确定的输出
格式在当前版本先砍掉。右下角“小娜”是低干扰协作入口，不应与主动作争夺视觉层级。

### 5.3 Chat：自由会话为默认

完整 Chat 的主要职责是提供自由会话空间，不是 Study / Studio 的汇总工作台，也不承担解释
产品架构的职责。用户从全局入口进入 Chat 时，默认进入未绑定 Course 或 Project 的自由会话；
除非用户主动选择，不恢复或展开来自 Study / Studio 的上下文。

Chat 中存在三种会话来源：

- 来自 Study 的会话；
- 来自 Studio 的会话；
- 在 Chat 中直接发起的自由会话。

三者进入同一份普通历史会话列表，按统一规则排序和呈现。Study / Studio 会话不设专属首页、
固定推荐位、独立看板或高权重色块；来源只使用低强调的标签或图标作为辨认信息。用户主动选中
某条历史会话后，才进入对应的 Course 或 Project 作用域。

完整 Chat 的 P0 只有对话正文与输入框；新建自由会话是主动作。会话历史是用户主动查找旧会话
时才出现的必要导航。选中 Study / Studio 历史会话后，仅在确有必要时以 P1 显示简短来源和
返回位置，不展开课程、项目、进度、材料或成果面板。不得用“自由 / Study / Studio”三个
并列主标签页刻意强化来源分类。

Study 与 Studio 右下角的“小娜”属于当前空间内的轻量上下文聊天框：展开时保留当前页面，
需要时可显式打开完整 Chat。轻量聊天框与完整 Chat 复用同一 session、context、transcript
与 composer 真值，不建立独立副本。由轻量聊天框进入完整 Chat 时，可以打开用户刚刚选择的
那条会话；再次从全局入口进入 Chat，仍以自由会话为默认。

自由会话不自动写入 Study 或 Studio。只有用户明确选择保存或转交，并确认去向后，相关内容
才可进入对应领域。

### 5.4 Activity

Activity 只优先呈现：

- 正在运行；
- 需要用户处理；
- 可以恢复。

已完成历史、完整运行日志和领域对象详情当前版本先砍掉。Activity 是状态投影，不是新的内容
空间。

### 5.5 全局 Shell

- Study / Studio 是稳定业务空间；
- Chat 是极简的全局自由会话入口；
- Activity / Settings 是全局工具；
- 原型的 J1–J5 旅程控制、调试状态和模拟说明只属于评审环境，不属于正式产品界面。

## 6. 反 overdesign 规则

出现以下任一情况，应优先删除，而不是折叠或继续优化样式：

1. 同一事实在标题、状态条、卡片和说明中重复出现；
2. 用户必须先阅读产品解释，才能找到当前动作；
3. 多个卡片只是为了证明系统“考虑得很完整”；
4. 页面同时展示当前、历史、来源、边界、状态和下一步；
5. 次要动作使用了与主动作相同的颜色、尺寸或重量；
6. 装饰性边框、阴影、标签和图标多于真正有用的信息层级；
7. 原型说明、领域术语或内部对象名直接泄漏到普通用户界面；
8. 删除某个模块后，用户仍能无损完成当前任务。
9. 试图折叠 P2、P3，却仍在界面上留下菜单、图标、空卡片或“更多”入口。

## 7. 评审方法

每个界面进入实现前后，都应用以下检查：

### 7.1 五秒测试

用户能否在五秒内说出：

- 我在哪里；
- 我现在要做什么；
- 下一步点哪里。

### 7.2 删除测试

对每个常驻模块提问：

> 删除它，用户还能完成当前任务吗？

如果答案是“可以”，直接删除；不保留折叠态或按需入口。

### 7.3 重复测试

同一信息只允许有一个主要表达位置。其他位置若没有新增决策价值，应删除。

### 7.4 行动测试

界面上每个高视觉权重元素都必须对应一个用户当前可理解、可执行的动作。

### 7.5 噪音测试

如果用户需要忽略多个区域才能开始工作，界面即为过度设计，即使每个区域单独看都合理。

## 8. 对后续前端重构的约束

- 先实现完整状态模型，再决定当前状态需要显示什么；
- 不以“后端已有字段”为由把字段全部渲染出来；
- 不以“方便演示”为由让正式界面承担原型说明；
- 不因响应式空间变小才隐藏信息；宽屏同样需要信息预算；
- 新增功能必须说明它取代或删除了什么，不能只做加法；
- 任何新卡片、新侧栏、新状态条都需要通过删除测试。

## 9. 一句话验收标准

> **用户不需要过滤 P2、P3，也能自然完成眼前的一步；任何新增信息必须先证明自己属于 P0 或 P1。**
