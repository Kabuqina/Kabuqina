## 1. MVP 的唯一验收命题

> **一个手上只有纸质教材和草稿纸的学生，能用它完成一次真实的学习，并得到纸给不了的东西。**

任何需求条目只有一个通过条件：**它在这条主回路上**。不在，就不是 MVP。

```text
S1 开本      我在学什么、学到哪
S2 这一步    它说下一步做什么，并小步讲给我听
S3 到纸上做  ← 产品不参与，这是纸的活
S4 卡壳      拍下停笔那一步 → 只给下一步
S5 做完      拍下我写的 → 对照讲评 → 错的进错题本
S6 复习      到期卡片 + 错题重做
```

S3 是产品**故意不在场**的一段。S4 与 S5 是这次 MVP 的全部新价值，其余是把已有能力搬到这条回路上。

这里的“不打字”指 **S3→S5 的卡壳、讲评、确认与入错题本主路径**。MVP 建本允许一次短文本输入；
自动从书封 / 目录建本仍是 P1，不能拿尚未实现的能力验收 0.5.0。

## 2. 视觉链路：路线、选型与成本

**这一节定不下来，S4 / S5 都立不住，MVP 也就不存在。**

### 2.1 两条路线，优劣不对称

| | 路线甲：视觉模型直读 | 路线乙：本机识别后送文本 |
|---|---|---|
| 链路 | 照片 → 多模态模型 → 讲评 | 照片 → EasyOCR / CodeFormula → 文本 → 模型 |
| 现成资产 | `tools/vision_tools.py::vision_analyze_tool` | `tools/ocr_tools.py::ocr_image_tool`、docling CodeFormula |
| 首次体验 | 无下载，拍完就用 | **必须先下能力包**，且本机 CPU 推理慢 |
| **二维结构** | 保留（行序、划掉的尝试、箭头、跨项分数线） | **压成字符流，结构全丢**——学生"卡在第三行"这个概念不复存在 |
| **失败形态** | 能说"这里看不清，是 dx 还是 dt" | **静默返回合理的错字**，模型据此自信讲评 |
| **手写体** | 随模型能力，通常可用 | **弱**——两者都不是为手写推导训练的 |

**结论：MVP 走路线甲。** 注意排序——「二维结构」和「静默失败」比手写识别率更根本：
**即使手写识别做到完美，路线乙对 S4 / S5 仍不适用**，因为讲评需要的是版面与意图，不是字符流；
而静默编造对一个靠信任立身的学习产品是最贵的失败。

这修正了设计修订 §5.1 的隐含判断——那里把本机能力包当成了这座桥的承重件，核查后它不是。

**路线乙降为辅助**：拍**印刷体**（书页、题干、印刷公式）仍走本机识别，免费、离线、不外传。

### 2.2 不替换 DeepSeek，只加挂一路视觉

DeepSeek 无视觉能力（owner 确认，2026-08-20）。但**不需要迁移主模型**：

核查发现 `vision_analyze_tool` 走的是 `providers/chat_completions.py::async_call_llm`，
而该层已有**独立的视觉 provider 解析**（`resolve_vision_provider_client` /
`is_vision_backend_configured`，视觉的 provider、model、base_url、api_key 均可与主模型分开配置）。
文件 docstring 里的 OpenRouter + Gemini 是上游 Hermes 的**陈旧注释**，代码未绑死。

> **形态：DeepSeek 继续承担对话与推理主链路，视觉模型只挂在拍照这一路。**
> 这是增配一路，不是迁移；95% 的 token 仍走 DeepSeek 的成本曲线。

但 provider core 已支持“独立视觉路由”不等于桌面产品已经接通：当前 Tauri 配置、Credential Manager
握手与网络 allowlist 仍只表达一路主模型。0.5.0 必须先完成 R0，视觉 key **不得**写入
`config.yaml` 的 `auxiliary.vision.api_key`；该字段只算 core 兼容能力，不是桌面端可接受的秘密存储方案。

### 2.3 选型候选（须为境内已备案模型）

0.6.0 大陆上架 + 算法备案，境外模型不可用。以下均提供 OpenAI 兼容端点：

| 候选 | 定位 | 理由 |
|---|---|---|
| **Qwen-VL（阿里云百炼）** | **首选** | 文档 / OCR / 公式理解是其主打能力，手写为明确宣传项；型号阶梯多，可按难度分流；生态最成熟 |
| **豆包视觉（火山引擎）** | 成本首选 | 定价最激进，中文强，适合做主力档 |
| **GLM-4V（智谱）** | 免费档 | 有便宜 / flash 档，适合免费用户额度 |
| 阶跃 Step | 不作首选 | 多模态能力可以，价格与生态不占优 |

> ⚠️ **具体 SKU 名称与价目不在本文冻结**：境内厂商改名与降价频率高。
> 选型前必须按**当时的**价目表重新核算。

**自建开源 VLM（Qwen-VL 开源权重 / MiniCPM-V / InternVL）**：MVP 阶段不做。
规模上来后再比 GPU 自建与 API 的单位成本。

### 2.4 成本架构（比选型更重要）

**最大的杠杆：把视觉当一次性转录层，不要每轮带图。**

```text
拍一次 → 视觉模型输出结构化转写
        （"学生的推导：第1行… 第2行… 第3行处停笔；第2行分母疑似写错"）
      → 之后整场追问全部走 DeepSeek 文本
```

一次卡壳对话可能十几轮，但只有 **1 次**视觉调用——成本从 O(轮数) 降到 O(照片数)。

**结构化转写合同（P0）**：视觉调用不得只返回一段自由文本，至少返回：

| 字段 | 要求 |
|---|---|
| `capture_id` | 客户端生成的幂等 ID；同一张图重试不得生成两条错题 |
| `purpose` | `stuck` / `review` / `printed_source` |
| `lines[]` | 保留行序；每行含转写、版面位置与可选的划改 / 箭头 / 上下标说明 |
| `unreadable_regions[]` | 明确列出看不清的位置；不得猜成一个“合理字符” |
| `confidence_band` | 只用 `high` / `medium` / `low`，不得把供应商未经校准的浮点分数当真值 |
| `question_text`、`student_work` | 可为空；缺失时后续模型不得补写成“识别结果” |
| `provider`、`model` | 记录实际调用档位，供质量回溯；不进入学习能力画像 |

任一必需区域不可读、合同缺字段、返回无法解析，均按 `low` 处理并提供“重拍 / 升档 / 我来确认”三条路；
学生点“读错了”也触发升档。原图**不进入 DeepSeek 对话上下文**，后续只传上述转写。

其余四条杠杆：

| # | 手段 | 效果 |
|---|---|---|
| 1 | 客户端预处理：裁到答题区、压到 1280 宽量级；灰度作为可回退选项 | image token 随分辨率走，原图与裁剪图差一个量级；近乎免费的省钱，且不牺牲彩色批注 |
| 2 | 印刷体走本机 EasyOCR，只有手写付费 | 见 §2.1 的分工 |
| 3 | 难度分流：默认便宜档，学生说"读错了"或置信度低再升档重试 | 贵档只服务少数难例 |
| 4 | 额度分档：免费用户每日拍照上限，订阅放开 | 把最贵的动作与付费墙对齐，即 0.6.0 的变现模型 |

**数量级（仅供判断方向，非报价）**：1280px 图约千级 image tokens，单张成本在厘至分量级；
学生每日 10–20 张，人均月成本在几元以内，订阅可覆盖。**须按当前价目自行核算。**

### 2.5 定型前必须做的验证

拿 **20–30 张真实学生手写照片**（不要用干净样张）对三家做一次对比，只看三项：

1. 读对率
2. **多行结构是否保住**（行序、划改、上下标）
3. **读不出时是否承认读不出**——这项最重要，静默编造是本产品最贵的失败

### 2.6 时序约束

模型供应商会写入算法备案材料（见 `docs/reviews/2026-08-14-algorithm-filing-materials-review.md`
与合规上线计划）。**选型须在备案材料定稿前锁定**，否则返工。

> ⚠️ **P0 阻塞项**：完成 §2.5 的三家对比并锁定供应商 + 档位。
> 未完成前，不得联调真实供应商或宣称 S4 / S5 达标；但 R0、图片摄入、预处理、转写合同、
> 外部错题存储与 mock E2E 可并行开发，不能让供应商选择阻塞全部基础工程。

## 3. 需求清单（P0 = MVP 必须）

### R0 桌面视觉路由与秘密存储　`P0`　（S4 / S5 前置）

DeepSeek 主路由与视觉路由是两套独立配置，web child 与 gateway child 必须得到一致结果：

- 新增独立 `VisionProviderConfig`：provider、model、base URL、host、档位；均为非秘密配置
- 视觉 key 单独存 Windows Credential Manager（建议 account=`vision:<provider>`）；不得落入
  `settings.json`、`config.yaml`、日志、命令行或 crash report
- 通过一次性 loopback HMAC URL 注入视觉 key；与主模型 secret URL 分离，并在读取后立即失效
- Python 启动时将非秘密字段接到 `auxiliary.vision`，将 key 只放对应 provider 的进程环境
- network policy 同时允许主模型 host 与选定视觉 host；普通模式可用，不要求超级用户模式
- web child 与 gateway child 分进程启动，必须各自完成一次独立握手，不假设共享内存

验收：主模型固定为 DeepSeek、视觉模型固定为锁定的境内供应商时，普通模式能完成一次
`vision_analyze_tool`；随后扫描 app data、`config.yaml`、日志与子进程命令行，均找不到视觉明文 key。

### R1 建本不依赖文件导入　`P0`

纸质教材导不进来，因此建本**不得以导入为前置**。

- 建本输入：课程名 + 当前范围（章 / 节）；MVP 允许一次短文本输入
- 单份电子材料导入**保留**（`ImportMaterials` 已有），但不是必经步骤
- 建本信息是课程元数据，不冒充教材内容。没有电子材料时，首个下一步只能基于学生声明的范围
  引导其打开相应纸书位置；不得声称“书中写了什么”
- 学生可在本子面拍当前书页建立 `photographed` 来源锚点；这是拍单页，不是“自动识别目录并建范围”
- 小娜基于通识生成的解释必须标为“小娜讲解”；基于书页的解释必须引用对应照片来源
- 验收：手上只有一本纸质书，**不导入任何文件**，输入课程名与范围后能建本并进入 S2；
  在未拍书页前不伪造教材引用，拍一页后能对该页进行有来源的讲解

> 拍书本目录自动建范围 → **P1**。它依赖识别链路，且不在最小回路上。

### R2 摊开的本子：一个知识核、一个下一步　`P0`

合并 `LearnPage` + `PracticePage` 为单面，学习 / 练习模式**原地切换**，不换路由。

- 进入本子即呈现：当前要弄懂的这一件事 + 一个明确的下一步动作
- 不默认铺开知识核列表、资源列表
- 模式切换不改变知识核（沿用五页规格 §2.3 的共享游标语义）
- 验收：进本子后**不需要先选页**就知道该干嘛

### R3 卡壳求助　`P0`　（本版核心新功能）

- 入口：任何位置拇指可达的「拍一张」。它是图片摄入动作名，不等于 0.5.0 必须控制物理相机
- Windows 0.5.0 必做三条摄入路径：选图、粘贴截图、拖入；三者进入同一预处理与转写管线
- 检测到可用摄像头时可提供直接拍摄，但不是 0.5.0 出货阻塞项；Capacitor 相机留 0.6.0
- 预处理支持旋转、手动裁答题区、压到最长边约 1280px；灰度必须可回退，不能抹掉彩色批注
- 默认行为：**只给下一步该往哪想**，不给完整答案
- 学生明说要答案 → 完整给出 + 标注这题建立在哪些知识点上、跳过了什么（铁律 1）
- 验收：从选图 / 粘贴 / 拖入到拿到提示，学生**全程不打字**；默认路径不泄漏完整解答

### R4 拍照对照讲评（不做自动判分）　`P0`

按 owner 选定的方案 A：**摄入 + 讲评 + 入错题本，不做整页手写自动判分**。

- 拍纸上作业 → 识别 → 小娜**对照讲评**（指出哪一步开始偏了）
- 小娜给出的“从哪一步开始偏”是**待确认讲评**，不是系统判分
- 确认态固定为“确实做错 / 其实做对 / 看不清，重拍”；只有“确实做错”进入错题草稿
- 验收：一道纸上做错的题，**不打一个字**就能进错题本

> 为什么不自动判分：多行手写推导的判分质量风险高，判错的代价（学生信任）远大于收益。留 0.6.0 服务端算力就位后再评估。

### R5 错题本的外部摄入路径　`P0`

现有 `hermes_core/learning/wrongbook.py::WrongbookService` 是**对 app 内答题记录与薄弱点的投影**，
只覆盖"在 app 里做错的题"。纸上来的错题**没有摄入模型**——这是新开发，不是搬运。

- 新增外部错题条目，至少包含：`entry_id`、`capture_id`、来源照片引用、题干、我的写法、
  正确写法、关联知识点、讲评、确认状态、创建 / 更新时间
- 生命周期固定为 `draft → confirmed → active`；重拍或重试沿用 `capture_id`，写入必须幂等
- 题干 / 我的写法来自视觉转写；正确写法、知识点与讲评属于 AI 草稿，学生确认后才生效，
  不得把模型生成值伪装成照片识别值
- 原图不写进 SQLite blob。确认入错题本后，将裁剪图存入 app data 的受管 media 目录，数据库只存
  相对 media ID + SHA-256；未确认、取消或识别失败的临时图立即删除
- “学习数据导出 / 一键删除”必须覆盖外部错题与受管照片；删除条目后不得遗留孤儿图片
- 与 app 内错题**合流到同一队列**，可重做
- 验收：拍来的错题和 app 内错题在卡片盒里无差别地排队与重做

### R6 卡片盒　`P0`

- 内容：到期卡片（SM-2，已有）+ 错题重做
- 薄弱点**只作为排序依据**出现，不渲染成报告
- 验收：一个入口就能看到今天要复习什么

### R7 三面 IA 与路由迁移　`P0`

五页 → 三面：**摊开的本子 / 卡片盒 / 扉页与材料**。

- 新 slug 冻结为：`notebook`（摊开的本子）、`cards`（卡片盒）、`bookend`（扉页与材料）
- `PAGE_SLUGS` 五 → 三；旧 URL 使用 `Navigate replace` 重定向：
  `flyleaf`·`plan` → `bookend`，`learn`·`practice` → `notebook`，`evaluate` → `cards`
- `/study/<course-id>` 默认落到 `notebook`；杂记本 `/study/<scratch-id>` 的单页规则保持不变
- 同步收敛：`lib/studyChatHandoff.ts::StudyNanaPage`、`desk/DeskNotebook.tsx::PAGE_TABS`、
  `study/iaEvents.ts::StudyIaPage`
- IA 聚合 key 从 `kabuqina.telemetry.study-ia.aggregate.v1` 升为 `.v2`；启用状态保留，v1 聚合删除，
  不把旧五页计数映射到新三面
- 验收：旧链接不 404，落到语义正确的新面

### R8 触屏规格　`P0`

0.5.0 是 Windows 窗口版，但按触屏建，0.6.0 才不返工。

| 项 | 要求 |
|---|---|
| 命中区 | ≥ 44×44 px，相邻间距 ≥ 8px |
| 主动作 | 下沿锚定（拇指可达），不在右上角 |
| hover | 无 hover-only 的信息或功能 |

| 输入 | 要求长文输入处必须并存非打字通道（拍 / 选） |

- 历史代码题只读展示为“不再支持”，不得重新进入作答、变体生成或沙箱执行路径
- 验收：推导题判分行为不变（回归 `tests/learning/test_code_grader.py` 中的数值等价用例）；
  产品面无代码入口；旧 `code` quiz 可加载；新建 `code` quiz 被拒绝；`run_python_grading` 在产品 E2E 中不可达

### R10 能力包首次体验　`P0`（若路线乙保留为辅助）

印刷体识别仍走本机能力包。下载**必须在「开本」时机触发**，并入既有载入包串行自愈编排
（见 `load-package-serial-orchestrator`），**不得**在学生第一次卡壳、举着草稿纸时才开始下载。

- 能力包只服务 `printed_source`，不作为手写 S4 / S5 的前置；下载失败不得阻断视觉模型直读
- 开本后后台预热，不阻塞进入本子；下载状态可见、可重试、可取消
- 验收：从没用过的新用户第一次拍印刷页时不遇到临时下载；即使能力包失败，手写卡壳仍可走视觉模型

## 5. 明确不做

- 学生报告 / 独立评估页
- 学习日志作为产品面（移至设置 → 学习数据）
- 覆盖率、连续天数、徽章、固定能力标签
- 代码学习（本版起不在产品范围）
- 草稿箱作为独立目的地（审批移到使用当下；仅开本时的批量生成保留一次过目）
- 制作工作夹 `DeskWorkFolder.tsx`（Studio 遗留，删除）

## 6. 不变量（本版不碰）

1. AI 生成内容先草稿、学生确认才生效——信任合同不变，只改出现时机与位置
2. 阅读 / 浏览不构成学习证据
3. 材料必须标来源（`imported` / `builtin` / `photographed`）；课程名与范围只是元数据，
   不算材料；小娜不凭空伪造教材内容，通识生成内容必须明确标为“小娜讲解”
4. 恢复优先于猜测：目标失效降级到正确课程
5. 内置课程只做样板，不做内容供给

## 7. 风险与待验证

| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| 1 | 视觉模型识别质量不足或成本不可接受 | **S4 / S5 全部落空，MVP 不成立** | 排期前完成 §2.5 三家对比；退路见风险 5 |
| 2 | 学生不愿保持"纸上做题"的习惯，想要无纸化平板 | 整个立场需复议（0.6.0 计划已列为最高优先级待验证假设） | MVP 上线后即验证 |
| 3 | 拍照讲评质量不足，学生转而直接要答案 | 沦为答案机，违背产品内核 | 讲评质量作为 MVP 出货判据之一 |
| 4 | 题型枚举收窄导致历史含 `code` 记录不可读 | 老用户数据损坏 | R9 已列为验收项 |
| 5 | 三家视觉模型均不达标或成本超预算 | 路线甲失守 | 退路：本机 OCR + **让学生确认识别结果**，把静默错误变成可见错误；若需要文字修正，则必须明确降级 R3 / R4「全程不打字」验收标准，不能带病宣称达标 |
| 6 | 第二路视觉凭据落盘或 host 未放行 | S4 / S5 在普通模式不可用，且违反秘密存储承诺 | R0：独立 Credential Manager 握手 + 双 host allowlist + 双进程测试 |
| 7 | 外部错题照片无法彻底删除或产生孤儿文件 | 违反学习数据章程与用户信任 | R5：受管 media ID、引用计数 / 删除、导出与残留扫描测试 |

## 8. 出货判据（MVP Done）

1. 一个只有纸质书的学生，**不导入文件**，只在建本时输入一次课程名与范围；S3→S5 不打字，完成 S1→S6 一整轮
2. 至少一道纸上错题进入卡片盒并被重做一次
3. 卡壳求助默认不泄漏完整答案，明确索要时完整给出并附知识点
4. 推导题判分行为与撤除代码练习前一致
5. 旧 Study URL 全部落到语义正确的新面
6. 三面全部满足 R8 触屏规格
