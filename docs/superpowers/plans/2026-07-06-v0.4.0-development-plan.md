## 1. 全局排序：一条硬约束决定一切

**Release-acceptance 观察期（纪律三）与"全量 rename"直接冲突**——大规模
改名会搅动正在发布观察的 graph-default 证据,污染 Step 4 的关闭判断。
因此 rename 必须分环,且第三环排在 3.5 收官之后:

```text
时间 ──────────────────────────────────────────────────────────▶

C 轨(3.5):  [完成] v0.3.0 release-acceptance ──► G2门评审 ──► contracts解冻评审(LG1/LG2/H2)
                                              └──► Task10 双引擎pilot ──► 移除门 ──► Task11 Step5(删旧loop)
A 轨(改名):  Ring1(产品面,随时) ──► Ring2(desktop/web内部,M4后) ─────────► Ring3(core,Step5之后)
B 轨(STUDY): M4 ──► M5 ──► M6支撑契约        练习契约+判分器(并行) ──► 临摹/变式
D 轨(前端):  IA/测试地基 ──► 一等 STUDY 壳 ──► M4 页 ──┬─► 练习页 ──┐
                                                        └─► M5 页 ───┴─► 集成收口
```

四条关键推论：

1. **Ring 3（hermes_core 内部改名）必须等 Task 11 Step 5 删掉旧 loop
   之后**——先删后改名,少改一大块死代码;这也正是重构相位模型
   （delete→consolidate→re-platform→**rename**）本来的顺序,rename 就是
   第 4 相。
2. **M4 立刻可以动工**——纯数据层,不碰引擎,release-acceptance 期安全;其 spec 的
   review gate（"M1-M3 review 意见解决后"）已由 v0.3.0 的 review +
   Codex fix 轮满足（动工前在 M4 实施 plan 里逐条确认一次）。
3. **练习契约 + 沙箱判分器与 M4 并行**——不同文件面（contract 扩展 +
   新 core 服务),互不阻塞。
4. **前端不能等到 M6 才一次性开工**——信息架构、路由壳、测试地基不依赖
   M5,可以立即设计；真正接数据的页面按 B 轨就绪度逐页落地。A-R2 完成前
   只做 D-0，避免大面积 `web/src` 改名与组件重组撞文件；A-R2 后再进入
   D-1 的 UI 波。

### Ring 1b · 品牌资产管线决策（IP，随 R1 窗口）

仓库侧的许可缺口已于 2026-07-06 修复（assets/brand/LICENSE 规则化覆盖：

**v0.5 场景美术（书桌/笔记本/白板/咖啡杯）用哪一档资产管线：**

| 档 | 形态 | 保护强度 | 代价 |
|----|------|---------|------|
| Tier 1（现状延伸） | 美术进公开仓库,靠 LICENSE-ASSETS + SPDX 标记 | 法律保护,技术上可被"带皮 fork"（侵权但需追诉） | 零改动 |
| Tier 2（VSCodium 模式） | 美术进**私有仓库**,官方构建时注入;公开仓库只有无品牌占位资产 | 技术执行:公开代码天生不是"卡布奇娜" | 构建管线加 assets overlay 步骤;贡献者体验略降 |

**决策截止：B-5（M6+笔记本 IA）收口前**——即 v0.5.0 场景美术投产之前。
决策记入 DECISIONS.md;若选 Tier 2,另出构建注入实施 plan（与
load-package 机制同思路,量不大）。

**决策记录（2026-07-11）：选 Tier 2。** 私有仓库
`Kabuqina/kabuqina-mascot` 为品牌资产唯一权威源;已公开美术显式不召回
（历史 + 六个双标记内嵌文件 + CSS 杯子维持法律保护),技术护城河只覆盖
v0.5 起的新场景美术。memo 见 DECISIONS.md;实施见
[Tier 2 overlay plan](2026-07-11-brand-asset-tier2-overlay-plan.md)。

**Owner 独办的法律轨（仓库外,与决策并行）：** 商标注册（文字 + 杯子
图形 + 小娜,9/41/42 类,赶在 v0.5.0 场景公开前提交）、小娜角色设定
著作权登记、v0.5 视觉定稿后的 GUI 局部外观设计专利。

**新美术纪律（对 Codex/所有切片生效）：** 任何新增内嵌品牌美术的文件
必须打 `LicenseRef-Kabuqina-Brand` 标记（assets/brand/README.md 已列为
规则）——B-5 的页边注/卡片盒视觉若引入新图形,从第一个 commit 就带标记。

   需要大修,C 轨顺延,A-R3 与 tutor 契约随之顺延——B 轨不受影响,
   版本仍可发(rename 降级为 R1+R2,R3 挪 v0.5.0)。**预先声明这个
   降级路径,避免 deadline 逼出含糊的第二次豁免。**
3. **沙箱判分器安全面**:实施 plan 必须包含威胁模型一节;发布说明
   不得声称"完全隔离"(残余网络风险)。
4. **前端 UI 波与 Ring 2 改名撞文件**:D-0 只写设计/测试地基,R2 后才开
   D-1；若机械改名仍未收口,UI 改动让路。
5. **M5 语义 reviewer 成本**:reviewer 是额外 LLM 调用,预算与超时
   语义沿四层 §4.3(失败停 pending),不新发明。
6. **v0.5 美术在管线决策前投产**:一旦场景美术以 Tier 1 形态进了公开
   仓库,就永远收不回（Apache 虽不适用,但公开即扩散）。缓解:A-R1b
   决策硬性卡在 B-5 收口前;美术投产是 v0.5.0 的事,v0.4.0 内任何新
   品牌图形必须带 `LicenseRef-Kabuqina-Brand` 标记。
7. **新旧 STUDY 双写漂移**:路由壳与旧侧栏允许短期共存,但同一能力不能
   同时有两套可写状态。每页迁移完成即把旧入口降为跳转/只读,D-5 删除。
