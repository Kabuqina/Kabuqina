## 1. 全局排序：一条硬约束决定一切

**Release-acceptance 观察期（纪律三）与"全量 rename"直接冲突**——大规模
改名会搅动正在发布观察的 graph-default 证据,污染 Step 4 的关闭判断。
因此 rename 必须分环,且第三环排在 3.5 收官之后:

```text
时间 ──────────────────────────────────────────────────────────▶

C 轨(3.5):  v0.3.0 release-acceptance(发布后几天观察,进行中) ──► G2门评审 ──► contracts解冻评审(LG1/LG2/H2)
                                        └──► Task10 双引擎pilot ──► 移除门 ──► Task11 Step5(删旧loop)
A 轨(改名):  Ring1(产品面,随时) ──► Ring2(desktop/web内部,M4后) ─────────► Ring3(core,Step5之后)
B 轨(STUDY): M4 ──► M5 ──► M6+笔记本IA        练习契约+判分器(并行) ──► 临摹/变式
```

三条关键推论：

1. **Ring 3（hermes_core 内部改名）必须等 Task 11 Step 5 删掉旧 loop
   之后**——先删后改名,少改一大块死代码;这也正是重构相位模型
   （delete→consolidate→re-platform→**rename**）本来的顺序,rename 就是
   第 4 相。
2. **M4 立刻可以动工**——纯数据层,不碰引擎,release-acceptance 期安全;其 spec 的
   review gate（"M1-M3 review 意见解决后"）已由 v0.3.0 的 review +
   Codex fix 轮满足（动工前在 M4 实施 plan 里逐条确认一次）。
3. **练习契约 + 沙箱判分器与 M4 并行**——不同文件面（contract 扩展 +
   新 core 服务),互不阻塞。

## 2. Workstream A — Rename：hermes → kabuqina（三环）

已有地基:`kabuqina_core/` 兼容包与 `tests/kabuqina/test_compat_imports.py`
——「新名 re-export 旧实现」的模式已经开了头,三环全部沿用它,
**先立新名、旧名保活一个发布周期、下版删旧名**。

### Ring 1 · 产品面与文档面（随时,零风险）

- 用户可见字符串、日志前缀（`hermesdesk.*` logger）、错误文案、
  README/docs 中指代产品的 hermes 字样;
- `platform="hermesdesk"` → `platform="kabuqina"`（**带兼容**:
  `LEARNING_KQ_KP_PLATFORMS` 同时收两个值一个周期）;
- 新增代码一律用 kabuqina 命名。

### Ring 1b · 品牌资产管线决策（IP，随 R1 窗口）

仓库侧的许可缺口已于 2026-07-06 修复（assets/brand/LICENSE 规则化覆盖：
目录 + `LicenseRef-Kabuqina-Brand` SPDX 标记 + 美术作品条款；六个内嵌
吉祥物美术的代码文件双标记；根 LICENSE/NOTICE/README/BRAND.md 四方
对齐）。v0.4.0 内要完成的是**决策**，不是返工：

**v0.5 场景美术（书桌/笔记本/白板/咖啡杯）用哪一档资产管线：**

| 档 | 形态 | 保护强度 | 代价 |
|----|------|---------|------|
| Tier 1（现状延伸） | 美术进公开仓库,靠 LICENSE-ASSETS + SPDX 标记 | 法律保护,技术上可被"带皮 fork"（侵权但需追诉） | 零改动 |
| Tier 2（VSCodium 模式） | 美术进**私有仓库**,官方构建时注入;公开仓库只有无品牌占位资产 | 技术执行:公开代码天生不是"卡布奇娜" | 构建管线加 assets overlay 步骤;贡献者体验略降 |

**决策截止：B-5（M6+笔记本 IA）收口前**——即 v0.5.0 场景美术投产之前。
决策记入 DECISIONS.md;若选 Tier 2,另出构建注入实施 plan（与
load-package 机制同思路,量不大）。

**Owner 独办的法律轨（仓库外,与决策并行）：** 商标注册（文字 + 杯子
图形 + 小娜,9/41/42 类,赶在 v0.5.0 场景公开前提交）、小娜角色设定
著作权登记、v0.5 视觉定稿后的 GUI 局部外观设计专利。

**新美术纪律（对 Codex/所有切片生效）：** 任何新增内嵌品牌美术的文件
必须打 `LicenseRef-Kabuqina-Brand` 标记（assets/brand/README.md 已列为
规则）——B-5 的页边注/卡片盒视觉若引入新图形,从第一个 commit 就带标记。

### Ring 2 · desktop/web 内部标识（M4 落地后、M6 UI 波之前）

- `python/src`、`web/src`、`tauri/src` 内部的 hermes 标识符、注释、
  测试名;
- **时机刻意卡在 M4 之后**:避免和 M4 的 desk 路由开发在同一批文件上
  互相 rebase。

### Ring 3 · core 标识与持久化名（Step 5 之后,本版最重的一刀）

改名对象:`hermes_cli`、`hermes_constants`、`hermes_state`、
`HERMES_HOME`、`~/.hermes`、pyproject 包名、`hermes-agent` skill 指引等。
**这一环的实施 plan 必须先做兼容审计**,以下每一项都要有迁移或双读:

| 持久化名 | 风险 | 策略 |
|---------|------|------|
| `HERMES_HOME` env + `hermes-home` 数据目录 | 老安装找不到数据 = 灾难 | 新名优先、旧名回退双读一个周期;首启迁移向导 |
| `~/.hermes` 配置目录 | 同上 | 同上 |
| **keyring service name** | 改名即丢 API key | 先审计当前 service 名;凭据迁移(读旧写新),绝不静默丢 |
| `HERMES_AGENT_ENGINE` 逃生门 | Step 3 承诺保留一个发布周期 | 随 Step 5 一并退役,不改名 |
| learning.db / session db 路径 | 跟 HERMES_HOME 走 | 随目录双读 |
| gateway owner id 格式 | `gateway:<platform>:<hash>` 不含 hermes | 不动 |

上游署名（NOTICE/LICENSE/MODIFICATIONS）在 Ring 3 中**逐条复核保留**。

## 3. Workstream B — STUDY M4→M6 + 前端信息架构

### B-1 · M4：student_state / evaluation / learning_plan

按 [M4 设计稿](../specs/2026-07-04-study-m4-state-evaluation-plan-design.md)
原样实施（三个 core service、desk 路由、`context.v1` 迁移、最小 Web 面），
外加两个搭车项：

- **H3**:Learning Index 投影(到期卡/薄弱点/当前计划项)接入
  `ephemeral_system_prompt` 槽——"因材施教"的数据管道;
- **LG6**:goal runner 到期复习提醒(默认静音、opt-in)。

### B-2 · 练习契约 + 沙箱判分器（与 B-1 并行）

按 [数学与代码设计稿 §4/§5](../specs/2026-07-05-study-math-code-practice-design.md)：
`quiz` 判别联合扩展 `code`/`derivation` 题型;沙箱判分器
（`python -I` + 临时目录 + 硬超时 + 输出截断,残余网络风险显式记录,
**单独安全评审**）;数值采样等价检查(零新依赖基线)。

### B-3 · 临摹/变式两级练习（依赖 B-2）

生成器(模板变异优先、模型兜底、变式自检)+ 练习面 UI
(CodeMirror 6 懒加载,decoration 逐字符比对做临摹高亮;推导板 =
DOM + KaTeX,承接 `derivation` 挖空)。D 类两个转换能力凭判分
pipeline 升 available。

### B-4 · M5：知识库 / 资源包 / 辅导笔记 + 语义 reviewer + Gateway /study

四层设计 M5 原样:三个新 kind、必需的语义 reviewer(失败停 `pending`
的契约早已写死)、外部来源审计入口、Gateway `/study` 确定性命令
(owner 粒度=个人,沿用 M1 的 gateway owner 派生)。

### B-0 · 学习数据宪章技术项（随 B-1/B-5 搭车）

[学习数据宪章](../../learning-data-charter.md)（owner 确认 2026-07-06）的
四个技术落实项:T1 learning.db ACL 实效核查（随 B-1 或独立小补丁）、
T2 遥测"只计数不引用"测试断言、T3 一键彻底删除 + 导出入口（进 B-5 的
M6 高级菜单）、T4 source_refs 最小化回归守护。宪章第五条（C 端身份、
不向权力方出售可见性）是产品级约束,对所有切片生效。

### B-5 · M6 + 笔记本信息架构（前端愿景 v0.4.0 部分,依赖 B-1,吃 B-4）

这是四层 M6 与前端愿景 §5 的合流切片：

- STUDY 重组为**生命周期分页**（设置/计划/学习/练习/评估）——
  分页即笔记本标签,用现有视觉语言渲染,不画桌子;
- **错题本**页(weak_points 投影 + quiz.attempt 证据)与**卡片盒**
  (due 队列)成为真实入口;
- 统一草稿箱;页边注形态试点(kq-kp chips 与小娜短旁注视觉上向
  "页边"靠拢);
- 新依赖仅 `motion` + View Transitions;
- 清理 legacy localStorage 读取路径(v0.3.0 已带迁移出门,满一个
  发布周期)。

**验证问题**(H5 遥测):学习者是否按生命周期走?错题本回访率?
——答案决定 v0.5.0 场景皮肤的投资。

## 6. 风险登记

1. **A-R3 是本版最危险的切片**——持久化名迁移错一处就是丢数据/丢
   凭据。缓解:兼容审计先行、双读一个周期、迁移测试用真实旧目录
   样本、放在版本末期(离 bundle 手工轮最近,问题最快暴露)。
2. **release-acceptance 未能关闭**:若 v0.3.0 发布观察暴露引擎级 bug
   需要大修,C 轨顺延,A-R3 与 tutor 契约随之顺延——B 轨不受影响,
   版本仍可发(rename 降级为 R1+R2,R3 挪 v0.5.0)。**预先声明这个
   降级路径,避免 deadline 逼出含糊的第二次豁免。**
3. **沙箱判分器安全面**:实施 plan 必须包含威胁模型一节;发布说明
   不得声称"完全隔离"(残余网络风险)。
4. **M6 UI 波与 Ring 2 改名撞文件**:已用时序隔开(R2 在 M4 后、
   M6 前);若仍撞,改名让路。
5. **M5 语义 reviewer 成本**:reviewer 是额外 LLM 调用,预算与超时
   语义沿四层 §4.3(失败停 pending),不新发明。
6. **v0.5 美术在管线决策前投产**:一旦场景美术以 Tier 1 形态进了公开
   仓库,就永远收不回（Apache 虽不适用,但公开即扩散）。缓解:A-R1b
   决策硬性卡在 B-5 收口前;美术投产是 v0.5.0 的事,v0.4.0 内任何新
   品牌图形必须带 `LicenseRef-Kabuqina-Brand` 标记。
