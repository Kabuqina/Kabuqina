# v0.5.0 功能调整与升级登记表

> **性质：** 活的 scope intake，不是实现 plan。新增需求先在这里完成问题定义、
> 依赖与版本裁决，再进入总计划和独立 JIT plan。
>
> **状态：** Open（2026-07-17）。

## 1. 纳入规则

每个调整项必须回答：当前行为、用户问题/证据、目标行为、非目标、所属层、数据/
兼容影响、依赖、最小纵切、验收和是否阻塞 v0.5.0。只有“想升级一下”而没有可观察
目标的项不进入实现。

优先级：

- **Must**：不完成就无法兑现 v0.5 核心承诺或会造成数据/安全/升级错误；
- **Should**：明显改善主路径，但有安全降级，可在 scope freeze 前决定；
- **Could**：不影响核心闭环，默认移入 v0.5.x/0.6；
- **Reject**：与学生学习产品定位冲突或维护成本大于价值。

## 3. 待 owner 补充/裁决

后续提出的功能调整依次追加为 U-13、U-14……，不覆盖旧记录。每项先选择：

- 修正现有合同；
- 交互/可用性升级；
- 性能/成本升级；
- provider/模型能力升级；
- 文档/PPT/报告能力升级；
- reminder/cron/messaging 升级；
- 延期到 v0.5.x/0.6。

## 4. Scope freeze

- L-0/P-0/S-0/C-0/V-0 review 完成前为需求收集窗；
- schema/视觉冻结后，只接受 P0/P1 bug、数据安全、升级和 release blocker；
- 新增 Must 必须说明替换/延期哪个既有 scope，不能无成本叠加；
- 每个进入实现的 U 项必须回链独立 plan、测试证据和 release note。
