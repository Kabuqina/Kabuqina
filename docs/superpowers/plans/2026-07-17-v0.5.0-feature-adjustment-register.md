## 1. 纳入规则

每个调整项必须回答：当前行为、用户问题/证据、目标行为、非目标、所属层、数据/
兼容影响、依赖、最小纵切、验收和是否阻塞 v0.5.0。只有“想升级一下”而没有可观察
目标的项不进入实现。

优先级：

- **Must**：不完成就无法兑现 v0.5 核心承诺或会造成数据/安全/升级错误；
- **Should**：明显改善主路径，但有安全降级，可在 scope freeze 前决定；
- **Could**：不影响核心闭环，默认移入 v0.5.x/0.6；
- **Reject**：与学生学习产品定位冲突或维护成本大于价值。

## 3. 待 owner 补充/裁决

后续提出的功能调整从 U-25 起追加，不覆盖旧记录。每项先选择：

- 修正现有合同；
- 交互/可用性升级；
- 性能/成本升级；
- provider/模型能力升级；
- 文档/PPT/报告能力升级；
- reminder/cron/messaging 升级；
- 延期到 v0.5.x/0.6。

## 4. Scope freeze

- E-1 先冻结产品承诺、surface 与 v0.5 外边界；E-2 冻结共同对象与跨面合同，之后不再
  以“Big picture”为由新增 Dashboard、Library、Report Center 或第四套业务状态；
- E-4 完成产品架构 freeze；L/P/S/C/V 各自的详细需求窗只在已冻结产品边界内继续；
- schema/UX/视觉冻结后，只接受 P0/P1 bug、数据安全、升级和 release blocker；
- 新增 Must 必须说明替换/延期哪个既有 scope，不能无成本叠加；
- 每个进入实现的 U 项必须回链独立 plan、测试证据和 release note。
- U-21/U-22 在 v0.5 baseline 已延期；若 owner 以等量 scope swap 恢复，任何 PPT stop
  rule 命中即整体回到 v0.5.x，且不得降低 U-24 产品脊柱、Tutor、Practice、Learning
  Space、升级安全或渠道裁剪的完成标准。
