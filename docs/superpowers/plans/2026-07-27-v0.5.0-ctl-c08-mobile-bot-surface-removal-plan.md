## 0. 为什么砍

owner 判断（2026-07-27）：**这套 Bot 配置已经做出来了，但前端重构后它的作用变得尴尬。**

v0.4 及以前的产品是纯 Chat / CLI agent——"从手机给 agent 发消息"在那个形态下成立。
v0.5.0 的产品是 Study / Studio 双域学习工作台：学习发生在课程本、材料面板、练习和复习里，
这些都不是能从微信对话框驱动的东西。让学生在设置里配一个「消息网关」，等于要求他理解一个
和他的学习任务无关的 ingress 概念。

**命名同时修正：**这套东西的真名是**移动端 Bot**（微信 Bot / QQ Bot / 钉钉 Bot），
不是"消息网关"。大学生知道什么是 Bot，不知道什么是 gateway。此名用于保留分支和
将来复活时的产品命名；本刀不做重命名实现——砍掉的东西不需要改名。

**未来可能性（保留理由）：**手机 Bot 将来可能用于支持某些操作（例如在外面用手机拍一页
书扔进课程本、或收一条复习提醒并直接作答）。届时从 `preserve/mobile-bot-gateway`
重新引入，且必须按 Study 的导入/复习路径重新设计，不是复活 ingress 形态。

## Outcome

物理移除**移动端 Bot 与邮件渠道的产品面**：Web 设置/页面/路由/onboarding 探测、
Rust supervisor 与 QR/env 命令、desktop Python 策略产出、bundle 里的 Bot SDK 依赖、
autostart 产出。学生和桌面产品里不再存在 Bot。

**本刀不动 `hermes_core/gateway/`。** 该目录 39 文件 / 35032 行，150 个测试文件引用它，
且十余个非 gateway 模块反向 import 它（`agent/prompt_builder.py`、`tools/approval.py`
的 `gateway.session_context`；`cron/jobs.py` 的 `gateway.delivery_contract`；
`toolsets.py` 的 `kabuqina-gateway` toolset；`run_agent.py`、`kabuqina_cli/`、
`acp_adapter/`）。Study 用的正是这套 agent runtime，因此核心库解耦是独立一刀
（见 §Deferred）。

本刀 non-destructive：已存在的凭据、profile 目录、session、job 与 home target
保持可读或可显式清除，沿用 CTL-C07 的兼容口径。

## Deferred

**明确不进 v0.5.0**（owner 2026-07-27）：

- **`hermes_core/gateway/` 本体删除与 agent runtime 解耦。** C 轨刚做完一部分解耦，
  剩下的不简单——`session_context`、`delivery_contract`、`kabuqina-gateway` toolset
  三处是真正的耦合点，动它们要动 Study 依赖的 agent runtime。**不排进 v0.5.0**，
  另立版本另出 plan。本刀之后主干上留着的是"产品不发但库还在"的状态，这是
  owner 认可的中间态，不作为死代码处理。
- **移动端 Bot 的将来形态设计。** 若复活，按 Study 导入/复习路径重做，不复活 ingress。

**待重判（本版内需给答案，但不属本刀）：**

- `sea` profile 的最终去留（见连带影响 2）。

v0.5.0 的核心是**新前端 + 支撑它的后台**，不是渠道裁剪的收尾。本刀只做到"学生看不到、
桌面不启动、bundle 不带"，到此为止。
