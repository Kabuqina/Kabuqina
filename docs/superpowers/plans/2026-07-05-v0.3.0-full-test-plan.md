# v0.3.0 Full Test Plan — Restructuring + Harness + STUDY

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** run the complete automated verification for the v0.3.0 freeze —
graph-engine restructuring (soak support), learning-conduct harness changes
(H1/H5/H6), and the full STUDY track (M1-M3 data foundation, kq-kp capture,
ACADEMY→REPORT reorg) — and produce a triaged test report. All-green here is
the precondition for the owner's bundle + manual round.

**Scope of "all green":** zero failures that are not on the known
environmental allowlist (§Known environmental failures). Pre-existing
environment failures are recorded, not fixed.

**Tech Stack:** system Python 3.x + pytest (NOT run_tests.sh — Windows dev
convention), Node 20 (`node:test` via transpileModule), Vite/tsc, cargo.

---

## Guardrails

- **This is a verification plan, not a fix plan.** If a test fails and it is
  NOT on the environmental allowlist: capture the full traceback in the
  report, classify it (regression from v0.3.0 scope vs latent), and STOP for
  review before changing any source. Only trivially-obvious test-side fixes
  (e.g. a stale string assertion missed by the reorg) may be applied directly;
  commit them separately with the failing/passing evidence in the message.
- Do not modify goldens, waive gates, or mark tests skipped to get to green.
- Do not build the MSI/NSIS bundle — that is the owner's manual round
  (docs/release-smoke-test.md, docs/qa-checklist.md).
- Use `-o "addopts=" -p no:cacheprovider` on every pytest invocation
  (repo convention).
- Run tracks in the order below (core failures make downstream noise);
  within a track, keep going after a failure to collect the full picture.

## Known environmental failures (allowlist — record, do not fix)

From the Windows dev baseline:

- `tests/cron`: 7 pre-existing failures — chmod 0600/0700 no-ops on Windows,
  `~`-expansion paths.
- GBK-locale text assertions and prompt_toolkit interactive tests where they
  appear in the full discover runs.
- symlink/chmod-dependent cases in packaging/util tests.
- Deprecation/UserWarning noise (asyncio policy, langchain pydantic-v1) is
  expected and not a failure.

Anything not matching these patterns is treated as real until triaged.
