## 0. 结论与开工边界

平板端可以在 v0.5.0 阶段并行开始，但必须分成两种状态：

1. **并行预开发**：v0.5.0 Gate 0 后开始。只做 Capacitor 客户端、触控 UI、真实相机/相册、
   本地模拟数据、离线缓存 spike、合同适配和华为平板 APK 验证。
2. **正式开发**：v0.5.0 发布后开始。届时才允许做 `hermes_core` → `kabuqina_core`
   重命名/瘦身、生产多租户后端、真实账号、计费、推送、内容审核与上架联调。

这覆盖并修正旧 v0.6.0 规划中“v0.5.0 发布前任何任务都不得开工”的绝对表述，但不改变两条硬约束：

- 不在 v0.5.0 开发期重命名或大规模改造 `hermes_core`；
- 不以尚未定型的产品名、版本、模型供应商和数据流提交正式备案/商店材料。

### 允许并行

- 新私有仓的目录骨架、构建与测试基础设施；
- Capacitor + React Android 客户端；
- 从 v0.5.0 冻结合同生成的 TypeScript 类型与 fixtures；
- `StudyRepository`、`CapturePort`、`OfflineStore` 等客户端抽象；
- 三面 Study UI：摊开的本子、卡片盒、扉页与材料；
- 华为平板真机上的拍照、上传、旋转、裁剪、压缩、权限和生命周期验证；
- fake vision 驱动的转写确认、下一步提示、讲评、错题确认和重做；
- Android WebView、KaTeX、横竖屏、触控与性能 spike；
- 云端 API、租户、认证、计量、同步的设计和一次性原型，不接生产数据。

### 禁止并行

- `hermes_core` 全量重命名、瘦身或迁仓；
- 为平板需求改变 v0.5.0 core 热路径；
- 将当前 Windows Python 服务伪装成生产多租户后端；
- 生产数据库迁移、真实用户体系和生产推理网关；
- 正式 IAP、商店推送、支付回执和额度扣减；
- 绑定未确定供应商的生产视觉 API；
- 以预开发 APK 对外宣称正式 Android 兼容或可上线。

## 1. 预开发目标

本阶段要回答五个问题：

1. **APK 能否在现有华为平板上稳定安装、启动和升级？**
2. **Capacitor WebView 能否可靠承载公式密集的 Study 内容？**
3. **真实相机 → 裁剪 → 压缩 → 模拟转写的交互是否顺手？**
4. **“纸负责动手，平板负责引导”在真实设备上是否成立？**
5. **平板客户端能否只依赖稳定合同，避免与 v0.5.0 的 Tauri/Python 实现耦合？**

预开发的最终产物不是一个空壳，而是一套可以装到华为平板上体验的 **Study 闭环演示 APK**：

```text
开本 → 看一个知识核与下一步 → 拍纸上作业/上传图片
    → 裁剪确认 → 模拟结构化转写 → 下一步提示/讲评
    → 学生确认错题 → 卡片盒 → 重做一次
```

识别和讲评内容在本阶段可由 versioned fake fixtures 提供，但相机、图片处理、状态恢复、触控、
离线缓存和 APK 生命周期必须使用真实设备能力。

## 2. 与 v0.5.0 的合同关系

平板端只消费 v0.5.0 的**产品合同**，不复用其桌面实现。

| 可复用 | 不可复用 |
|---|---|
| `CaptureSessionV1` / `CaptureTransformV1` | Tauri commands 和 Rust supervisor |
| `StudyTranscriptionV1` | Windows Credential Manager / DPAPI |
| Assistance / Review / Wrongbook 合同 | loopback HMAC secret bridge |
| 三面 IA 与旧路由语义 | Windows 本地绝对路径和 app-data 布局 |
| Markdown / KaTeX 渲染组件 | 桌面 Python child 与本机 `learning.db` 假设 |
| fake vision fixtures 与错误码 | Windows 摄像头枚举和系统文件选择器实现 |

### 合同同步规则

- v0.5.0 仓库仍是 Study v1 合同的事实来源；
- Gate 0 产出一份不可变的 `study-contract-v1` 快照：JSON Schema/OpenAPI、TypeScript 类型、
  Python 类型和 high/low/malformed/mismatch fixtures；
- 平板私有仓把该快照放在 `packages/contracts/`，记录来源 commit，不直接依赖 v0.5.0 工作分支；
- 合同变化必须更新版本和 change log，不允许两个仓库各自新增同名字段；
- 每次 APK 构建记录合同版本；fixture parity test 防止前后端解释漂移；
- v1 冻结后只允许向后兼容新增，可空字段不得临时改变既有字段语义。

### 与 v0.5.0 Gate 对齐

| v0.5.0 Gate | 平板端解锁项 |
|---|---|
| Gate 0：合同、camera spike、fake vision、IA 路由完成 | 创建客户端、接 fixtures、做三面 UI 和 APK-A |
| Gate 1：上传/拍照统一为 normalized capture | 对齐图片变换元数据，完成 APK-B |
| Gate 2：结构化转写四分支通过 | 固化转写确认/失败恢复状态机 |
| Gate 3：外部错题 E2E 通过 | 完成 mock Study 闭环 APK-C，并评审云 API |
| v0.5.0 Release E2E + 发布 | 正式启动 core 与生产后端工作 |

```text
kabuqina-pad/
  apps/
    tablet/                 # Capacitor + React 客户端
  packages/
```

## 4. 华为平板设备基线

华为平板是第一台 Android 实机，但首先要确认它实际支持 APK。部分较新的纯鸿蒙设备可能不具备
Android APK 兼容层，因此设备能力不能凭品牌推断。

### D0 设备登记

首次安装前记录：

- 具体型号与芯片架构；
- EMUI / HarmonyOS 名称、完整版本号和 Android API level（若可见）；
- 是否允许“安装未知应用”；
- 是否能启用开发者选项和 USB 调试；
- 系统 WebView 名称与版本；
- 屏幕分辨率、逻辑像素、刷新率、内存；
- 横屏/竖屏、前后摄像头、相册选择器是否可用；
- 是否缺少 GMS。预开发 APK **不得依赖 GMS 才能启动或完成 Study 主回路**。

### D0 判定

- 能手动安装并启动最小 Capacitor debug APK：进入后续阶段；
- 能安装但 WebView/相机异常：记录为兼容问题，在 P2 解决或明确最低系统版本；
- 系统不支持 APK：该设备不能作为 Android 基线，需要补一台兼容 Android 的设备；不因此改用
  HarmonyOS NEXT 原生路线，后者需另行立项。

### 安装包规则

- 预开发使用 debug APK 或内部测试签名 APK，不使用正式商店签名；
- 签名文件和密码不得进入 git；
- `versionName` 使用 `0.6.0-predev.N`，`versionCode` 单调递增，保证可测试覆盖安装；
- 每个 APK 附构建清单：commit、合同版本、构建时间、支持 ABI、已知问题；
- 至少保留“干净安装”和“覆盖升级”两条测试路径；卸载会清数据，测试日志须明确说明；
- 测试照片只使用不含真实姓名、学校、考号等敏感信息的样本。

## 5. 工作包与退出条件

### P0 — 启动闸门与合同快照（1–2 人日）

| ID | 任务 | 退出条件 |
|---|---|---|
| P0.1 | 确认 v0.5.0 Gate 0 已完成 | 四类 fixtures 和统一错误码可被平板消费 |
| P0.2 | 冻结 `study-contract-v1` 快照 | schema、TS 类型、fixtures、来源 commit 齐全 |
| P0.3 | 建立跨仓变更规则 | owner、版本策略、变更记录模板明确 |
| P0.4 | 建立预开发 stop rules | 禁止事项进入仓库 README/ADR |

**Gate P0：** 没有合同快照时，可以画静态页面，但不得实现会持久化的业务状态。

### P1 — Capacitor 骨架与第一只 APK（2–3 人日）

- 初始化 React + TypeScript + Capacitor Android；
- 设置横屏优先但允许竖屏恢复，不强锁方向；
- 建立开发/测试配置，不放 provider key；
- 建立本地 fixture repository 和诊断页；
- 生成 `APK-A`，完成华为平板干净安装、冷启动、覆盖升级、卸载重装。

**Gate P1 / APK-A：** 华为平板可以进入三个 Study 面，显示构建与合同版本，旋转和返回键不崩溃。

### P2 — 三面 Study 与公式渲染（4–6 人日）

- 落地 `notebook` / `cards` / `bookend`；
- 本子面只突出一个知识核和一个下一步；
- 接入 Markdown、GFM、KaTeX，建立真实模型公式回归语料；
- 用窄布局作为主布局，命中区不小于 44×44 px，不依赖 hover/右键；
- 验证长推导、矩阵、分段函数、重积分、中文与公式混排；
- 验证系统字号、深色/浅色、软键盘、横竖屏切换和 Android 返回手势。

**Gate P2：** 华为平板连续浏览 20 条公式密集内容无明显错版；三个面在横竖屏都无关键按钮遮挡。

### P3 — 真实拍照与上传图片（3–5 人日）

- “拍一张”只保留 **拍照 / 上传图片** 两个选项；
- 拍照走 Capacitor camera adapter，上传走系统相册/文件选择器；
- 支持权限首次授权、拒绝、永久拒绝后的恢复说明；
- 支持旋转、手动裁剪、最长边约 1280px 压缩；灰度只能作为可回退选项；
- EXIF 方向统一，预览与最终上传方向一致；
- 临时图片在取消、失败和超时后回收；
- 后台/前台切换、锁屏恢复、低内存恢复不产生重复 `capture_id`。

**Gate P3 / APK-B：** 两条真实摄入路径都在华为平板生成相同的 `CaptureSessionV1` 后续状态，
并能送入 fake vision；关闭网络不影响拍照、裁剪和待提交状态。

### P4 — 模拟识别、讲评与错题闭环（4–6 人日）

- 对接 high / low / malformed / mismatch 四类 `StudyTranscriptionV1` fixtures；
- 不可读时提供“重拍 / 换图 / 我来确认”，不得静默补写；
- 串题时禁止直接生成当前题提示；
- 默认只给一个下一步方向；完整答案必须由学生显式请求；
- 讲评固定为“确实做错 / 其实做对 / 看不清，重拍”；
- `capture_id` 重放保持幂等，确认错误后生成一条本地演示错题；
- 卡片盒能显示并重做该错题；正确/不可读/取消不创建 active entry。

**Gate P4 / APK-C：** 在华为平板上不打字完成一次完整演示回路，并可重复演示四类异常状态。

### P5 — 离线缓存与恢复 spike（3–4 人日）

- 缓存到期卡片、错题、知识点和必要的显示资源；
- 区分 `remote truth`、`local cache`、`pending mutation`，禁止把缓存当服务端真值；
- 设计 mutation outbox，恢复联网后可重试且不重复创建错题；
- 用户退出登录/清除学习数据时删除本地缓存和受管图片；
- 记录 IndexedDB 与原生 SQLite 两种方案的性能、迁移和加密边界，预开发只选择其一作为候选，
  最终安全方案在正式架构评审后锁定。

**Gate P5：** 飞行模式下可打开缓存卡片并完成一次本地重做；重新联网后模拟同步保持幂等。

### P6 — 设备体验与产品假设验证（3–5 人日）

至少进行 5 次完整实机走查，覆盖：

- 平板平放、支架横放、手持竖屏三种姿势；
- 从纸上做题到举起平板拍摄的实际动作成本；
- 拍书页、拍单题、多行推导、带划改和彩色批注四类照片；
- 拍照权限拒绝、存储不足、应用切后台、网络中断；
- 公式长页面滚动、连续打开卡片、返回手势和软键盘；
- 是否出现“宁愿直接在平板写”的明确诉求。

每次走查记录完成时长、误触、重拍次数、方向错误、裁剪耗时、公式错版和主观负担。

**Gate P6：** 对“纸负责动手，平板负责引导”给出继续/调整/复议结论。若多数真实走查都要求
GoodNotes 式整页书写，停止继续堆叠 Capacitor UI，回到 v0.6.0 技术栈复议。

### P7 — v0.5.0 发布后的正式交接（2–3 人日）

- 将 fixtures 替换为 hosted API adapter，但保留 fixture adapter 用于测试和演示；
- 用 v0.5.0 发布 tag 生成最终 Study v1 合同基线；
- 评审认证、租户、同步、推理计量和图片上传的云端协议；
- 正式启动 core 重命名/瘦身和后端 M0–M3；
- 建立第二台 Android 设备，优先补目标首发商店对应的小米平板；
- iPad 工作流在 Android 预开发结论稳定后进入同一客户端，不阻塞本计划完成。

## 6. APK 交付梯度

| APK | 内容 | 是否需要后端 | 主要验证 |
|---|---|---:|---|
| APK-A | Capacitor 壳、三面导航、合同/构建信息 | 否 | 安装、启动、升级、WebView、旋转 |
| APK-B | APK-A + 真实拍照/上传/裁剪/压缩 | 否 | 华为相机与图片生命周期 |
| APK-C | APK-B + fake 转写/提示/讲评/错题/卡片重做 | 否 | 完整 Study 体验和产品假设 |
| APK-D | APK-C + 非生产 hosted dev adapter | 是，v0.5 Gate 3 后 | 网络错误、鉴权占位、合同联调 |

APK-C 是并行预开发的主要交付物。APK-D 只允许连接隔离的开发环境，不使用生产用户、生产 key、
真实计费或正式商店身份。

## 7. 测试矩阵

### 安装与系统

- 干净安装、覆盖升级、卸载重装；
- 冷启动、热启动、进程被系统回收后恢复；
- Android 返回键/返回手势、旋转、分屏（若系统支持）；
- 无 GMS 时主流程仍可用；
- 不申请通讯录、定位、麦克风等与本阶段无关的权限。

### 相机与图片

- 首次允许、拒绝、永久拒绝权限；
- 后摄像头拍纸张、相册上传、文件选择器上传；
- 竖拍/横拍、EXIF 旋转、大图、低光、阴影、彩色笔迹；
- 取消裁剪、重复提交、后台恢复、离线待提交；
- 图片尺寸与内存峰值不过度增长，临时文件可回收。

### Study 合同

- high / low / malformed / mismatch 四分支；
- `capture_id` 幂等；
- 默认下一步提示与显式完整答案分离；
- 三态讲评确认；
- 错题只在确认后进入 cards；
- 缓存清除、退出登录和模拟同步不会留下孤儿图片。

### 触控与内容

- 所有主动作单手可达、命中区 ≥ 44×44 px；
- 无 hover-only 和右键唯一路径；
- 长公式、矩阵、`aligned`、`cases` 和中文混排；
- 系统字体放大后内容仍可操作；
- 横屏为主要走查场景，竖屏不崩坏。

## 8. 排期与并行方式

假设有 1 名前端/移动端开发者，并由 v0.5.0 合同 owner 提供少量评审：

| v0.5.0 时间 | 平板预开发 | 交付 |
|---|---|---|
| Gate 0 当周 | P0 + P1 | 合同快照、APK-A、设备登记 |
| Gate 1 附近 | P2 + P3 | 公式/触控基线、APK-B |
| Gate 2–3 | P4 + P5 | mock Study 闭环、APK-C |
| v0.5 集成回归期 | P6，只修平板独立问题 | 实机报告、技术栈继续/复议结论 |
| v0.5 发布后 | P7 | hosted adapter 与正式 M0–M3 交接 |

独立移动端开发者预计 **3–5 个日历周、15–25 人日**完成 APK-C 与实机报告。

## 9. 分支、责任与冲突控制

- 平板端放在独立私有仓；v0.5.0 仓只提交合同来源，不提交 Gradle/Capacitor 产物；
- 指定一名 contract owner，负责批准跨仓合同变化；
- 平板开发不得直接修改 `hermes_core/`、`python/`、`tauri/`；需要变化时在 v0.5.0 计划中登记；
- 禁止复制 Python 数据库和桌面媒体路径到移动端；
- 所有平台能力从 port/adapter 进入，React 组件不直接散落 Capacitor 调用；
- APK 与测试日志按构建编号对应，避免“装的是哪一版”无法追溯；
- 不提交 APK、Gradle 缓存、相机样本、签名文件和任何 secret 到 git。

---

## 10. Stop rules

出现以下情况立即暂停对应工作，不用临时 hack 掩盖：

1. v0.5.0 Gate 0 合同尚未冻结，平板与桌面开始出现同名不同义字段；
2. 华为设备实际不支持 APK，或其系统 WebView 低于可接受基线；
3. APK 只有依赖 GMS 才能进入主流程；
4. 图片权限、临时文件或缓存无法做到可解释、可清除；
5. 为推进平板端而要求在 v0.5.0 发布前重命名/瘦身 core；
6. fake adapter 被写死进 UI，未来无法替换 hosted adapter；
7. 真实走查否定“纸上做题 + 平板引导”的关键假设；
8. 同一开发者的并行投入使 v0.5.0 Gate 延迟。

---

## 11. 预开发 Done

满足以下条件，才算平板并行预开发完成：

- 华为平板完成设备登记，确认 APK 支持边界；
- APK-A/B/C 均可追溯构建，至少完成一次干净安装和一次覆盖升级；
- 三个 Study 面在横竖屏均可用，公式密集内容通过实机走查；
- 拍照与上传图片进入同一裁剪/压缩/状态管线；
- high/low/malformed/mismatch 四类 fake 识别都能正确恢复或 fail closed；
- 默认只给下一步，完整答案必须显式请求；
- 一道纸上错题无需打字进入卡片盒并完成一次重做；
- 离线缓存与待同步 mutation 的候选方案有实测证据；
- 主回路不依赖 GMS，不包含 provider key、生产账号或生产数据；
- 没有修改或复制 v0.5.0 的平台实现，没有提前执行 core 重命名；
- 输出一份实机报告，对 Capacitor、华为兼容性和产品假设给出继续/复议结论；
- v0.5.0 发布后接入 hosted backend 的接口缺口已形成明确清单。

完成这些条件后，v0.6.0 可以从“验证能不能做”进入“建设生产托管产品”，而不是在正式立项后
才第一次发现 APK、相机、WebView 或交互方向存在根本问题。
