## 0. 一句话

0.5.0 的 Study 现在是**围绕"材料已经在 app 里"设计的**；真实场景是**书和草稿纸在桌上、平板在旁边**。
本次修订把 Study 从「五页学习管理台」收成**桌上三件物件 + 两个常驻动作**，
并把产品的取舍标准换成一条：**纸做不到的事我们做，纸更强的事我们不抢**。

---

## 1. 为什么现在要改

### 1.1 现有设计隐含的场景假设

五页模型（扉页 / 计划 / 学习 / 练习 / 评估）是自洽的，但它建立在一串假设上：

| 现有设计的动作 | 隐含假设 | 平板 + 纸场景下是否成立 |
|---|---|---|
| 先导入材料 → 对齐 → 生成目录 | 学生手上的教材是**可导入的电子文件** | ❌ 教材多半是纸质书，导入不了 |
| 右侧书堆 + 阅读器展开正文 | 学生在**屏幕上读材料** | ❌ 书就摊在桌上，屏幕再放一遍是浪费 |
| 练习页输入框「写下你的答案」 | 学生在**屏幕上作答** | ❌ 推导演算在草稿纸上，且考场也是手写 |
| 代码练习面（浏览器跑 Python） | 学生在**平板上写代码** | ❌ 0.6.0 已明确代码学习不在范围内 |
| 五个分页各自的草稿审核区 | 学生愿意**做系统的记账工作** | ❌ 学习中途被拉去处理队列 |

不是这些功能做错了，是**它们回答的是"如何管理学习资产"，而学生坐在桌前问的是"这一步该干嘛"**。

### 1.2 0.6.0 的立场必须提前生效

0.6.0 已锁定「纸负责动手，平板负责引导」。若 0.5.0 继续按"材料在 app 里、答案打在屏幕上"往前建，
0.6.0 就不是延续而是**返工**：IA、五页 prompt 合同、练习作答通道、错题摄入路径全要重写。
把这次修订放在 0.5.0，是为了让 0.6.0 只做"换端 + 托管"，不做"换产品"。

## 2. 唯一判据：纸做不到的事

> 每个 Study 功能只问一句：**它在补纸的短板，还是在和纸抢它更强的活？**

**纸做不到的七件事（这就是我们的产品）**

| 短板 | 我们的能力 | 现状 |
|---|---|---|
| 讲不清的时候没人讲 | 小步讲解、追问、按理解程度自适应 | 已有（Tutor） |
| 做完了没人批 | 判分、批改、指出错在哪一步 | 部分（app 内测验有，纸上作业没有） |
| 错题散在各本子上，翻不动 | 错题本、按知识点归类、可重做 | 部分（只覆盖 app 内答题） |
| 忘了没人提醒 | SM-2 间隔重复 | 已有 |
| 不知道自己哪里弱 | 薄弱点（来自真实答题证据） | 已有 |
| 「这个定理书上哪讲过」找不到 | 材料检索与引用定位 | 已有（但埋在阅读器里） |
| 不知道下一步学什么 | 知识核序列、继续书签 | 已有 |

**纸更强的三件事（停止竞争）**

| 纸更强 | 现有设计在抢 | 处置 |
|---|---|---|
| 读长文 | 阅读器 + 右侧书堆常驻 | 降级为**按需取证**，不是阅读场所 |
| 写推导演算 | 练习页文本输入、代码练习面 | 主通道改为**纸上做 → 拍回来**；打字降为兜底 |
| 长文录入 | 扉页三个多行文本框 | 改为**对话生成 + 学生确认**，表单降为编辑态 |

## 3. 新的信息架构

### 3.1 五个分页 → 桌上三件物件

五页标签是贴在书桌上的**第二套分类法**。书桌本身已经有一套更好的词汇——而且它已经实现了
（`DeskNotebook` / `DeskCardReview` / `DeskBookend`）。收回到物件上：

```text
桌上（每天都碰）
  ├─ 摊开的本子   ← 这一步：讲解 + 到纸上做 + 对照反馈   （合并 学习 + 练习）
  └─ 卡片盒       ← 复习：到期卡片 + 错题重做            （合并 练习的卡片 + 评估的错题本）

书立上（开本时碰一次，之后很少）
  └─ 扉页与材料   ← 这门课学什么、材料是什么、目录长什么样（合并 扉页 + 计划 + 导入 + 对齐）

常驻两个动作（任何位置，拇指可达）
  ├─ 问小娜       ← 讲解、追问、卡壳求助
  └─ 拍一张       ← 拍纸上的题 / 拍自己写的步骤 / 拍写完的作业
```

**为什么合并学习与练习**：五页规格 §2.3 自己写着"学习和练习是同一对象的两种模式，共享同一游标"。
一个对象的两种模式分成两个路由，是把内部结构泄漏成导航。合并后模式切换仍在，只是从换页变成原地切换。

**为什么砍掉评估页**：它装三样东西——错题本（有价值 → 进卡片盒）、最近评估（就是产品明确不要的
"学生报告"）、学习日志（系统流水，不是学生要看的东西 → 移到设置 → 学习数据）。

### 3.2 新增：卡壳求助（本次修订的重点功能）

纸上学习最高频、也最没被服务的时刻是**笔停在半路**。现在的产品要求学生放下笔、打字描述题目——
这道门槛高到大部分时候他会直接翻答案。平板原生的做法：

```text
拍下卡住的那一步
  → 小娜只讲下一步该往哪想，不给完整答案
  → 学生回到纸上继续
  → 还卡 → 再问 → 再走一步
```

- **不违反铁律 1（永不扣留）**：学生明说"直接给答案"就完整给，给完再标出这题建立在哪些知识点上、
  跳过了什么值得回头补。默认只给下一步，是因为他此刻**在做题中途**，不是在要答案。
- **不违反铁律 2（学习者动手）**：动手全程在纸上，屏幕只出提示。
- 这是把 0.6.0 的「拍照桥梁」用在**做题过程中**，而不只是做完之后。

### 3.3 逐项处置表

| 现有面 / 组件 | 处置 | 理由 |
|---|---|---|
| `StudyLifecycleNav` 五标签 | **改三标签**（本子 / 卡片盒 / 扉页） | 见 §3.1 |
| `LearnPage` + `PracticePage` | **合并为「摊开的本子」单面**，模式原地切换 | 同一知识核的两种模式 |
| `EvaluatePage` 错题本 | **移入卡片盒**，与到期卡片并列 | 错题重做就是复习 |
| `EvaluatePage` 最近评估 | **降级**：不再是独立版块，薄弱点作为卡片盒的排序依据出现 | 产品不要学生报告 |
| `EvaluatePage` 学习日志 | **移出产品面**，进设置 → 学习数据 | 系统流水，非学习动作 |
| `FlyleafPage` 三个多行输入 | **主路径改对话生成 + 落墨确认**，表单保留为编辑态 | 平板上打长文是劝退动作 |
| `PlanPage` 三级目录 | **保留但改用途**：定位（我在书的哪一段）而非阅读目录 | 目录服务于范围，不服务于翻阅 |
| `StudyMaterialReader` + 右侧书堆 | **降级为按需取证浮层**：小娜引用某处时打开该片段，用完关闭 | 学生手上有书 |
| `ImportMaterials` | **保留，但不再是唯一入口**；与「拍一张」并列 | 纸质教材导不进来 |
| `MaterialAlignmentReview` | 保留（多份电子材料仍需分本） | 有电子讲义/真题的学生真实需要 |
| `DraftInboxButton` 草稿箱 | **取消为独立目的地**；审批移到使用当下（"开始练这组"＝采用） | 不让学生替系统记账 |
| 开本时的批量草稿（计划 / 知识库） | **保留批量审核**，只在导入/开本那一刻 | 大批量生成确实需要一次过目 |
| `CodePracticeSurface` | **产品面下线**（后端保留为休眠资产） | 0.6.0 无代码学习；平板上写代码最差 |
| `DerivationPracticeSurface` | **保留**，但作答主通道改为拍照，打字兜底；口述作为第三通道但依赖语音能力包 | 考场是手写 |
| `DeskWorkFolder`（制作工作夹） | **删除** | Studio 已砍，架构 §3.2 早已要求移除 |
| `ScratchNotebook` 杂记本 | 保留，改定位为**随手记（拍/说都能进）** | 锁定决策 2026-07-28，不动其存在 |
| `DeskCup` 小娜杯 / `DeskBookend` 书立 | 保留 | 物性词汇表真值 |

### 3.4 不变的东西（本次修订不碰）

1. AI 生成内容先草稿、学生确认才生效——**信任合同不变**，只改它出现的时机与位置。
2. 阅读 / 浏览不构成学习证据。
3. 不展示覆盖率、连续天数、徽章、固定能力标签。
4. 材料必须标来源（`imported` / `builtin`），小娜不凭空造材料。
5. 恢复优先于猜测：目标失效降级到正确课程，不跳别处。
6. 内置课程只做样板，不做内容供给。

## 4. 触屏化：0.5.0 在 Windows 上就要做到

平板对齐不只是 IA，还有手能不能用。0.5.0 是 Windows 窗口版，但按触屏规格建，0.6.0 才不用重来。

| 项 | 要求 |
|---|---|
| 命中区 | 主要可点对象 ≥ 44×44 px；相邻可点对象间距 ≥ 8px |
| 主动作位置 | 主动作**下沿锚定**（拇指可达），不放右上角 |
| hover | 不得有 hover-only 的信息或功能；tooltip 只做补充 |
| 右键 | 不得有右键唯一路径 |
| 布局基准 | 窄布局（当前 `max-width: 720px` 断点）视为**主布局**，宽屏是它的展开，不是反过来 |
| 滚动 | 正文承担纵向滚动；关键动作与关闭入口始终在可达区，不得沉到窗口底部之外 |
| 输入 | 任何要求长文输入的地方，必须同时有非打字通道（拍 / 选为必须；说为可选，见 §5.1） |

## 5. 与 0.6.0 的接缝

本次修订**提前建好、0.6.0 直接接上**的三处：

| 0.5.0 建的 | 0.6.0 接上的 |
|---|---|
| 图片摄入通道（选图 / 粘贴截图 / 拖入），走既有 `ocr_image`（EasyOCR）+ docling 公式识别 | 换成 Capacitor 相机；识别链路从本机能力包改为服务端常驻 |
| 错题本的**外部摄入路径**（不只 app 内答题投影） | 拍纸质错题直接入队，无需再造摄入模型 |
| 三物件 IA + 触屏规格 | 平板端 fresh client 照此实现，不重设计 |

### 5.1 能力包依赖：这是选项 A 的真实成本（核查后补记）

照片这条路在桌面端**全部压在按需下载的能力包上**，不是开箱即用：

| 能力 | 现状 | 对纸质教材学生的含义 |
|---|---|---|
| 图片文字识别 | `hermes_core/tools/ocr_tools.py::ocr_image_tool`，EasyOCR 离线，**载入包**（`easyocr-add-to-load-packages-next-version`） | 首次拍题前要先下模型 |
| 图片公式识别 | docling CodeFormula，**载入包**，且精读档位是本机 CPU 推理、**慢**（`docling-read-modes-and-perf`） | 数学题识别可能要等 |
| 口述转写 | `hermes_core/tools/voice_mode.py`（本机 faster-whisper 可选），但现有形态是 voice-mode 的录音/播放流程，**不是学习作答通道** | 「说」不是顺手就有，要单独建 |

**这条影响选项 A 的判断**：新 IA 的卡片盒对纸质教材学生能不能立起来，取决于第一次拍照前
那次模型下载能不能做得无感。若做不到，选项 A 的实际体验会退化成选项 C。
建议把这次下载并入既有的**载入包串行自愈编排**（`load-package-serial-orchestrator`），
在「开本」那一刻触发，而不是在他第一次卡壳、举着草稿纸的时候。

**0.5.0 明确不做**：自动批改整页手写作业（多行推导的识别与判分质量风险高，且依赖服务端算力，留 0.6.0）。
