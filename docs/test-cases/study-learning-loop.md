# STUDY 学习闭环测试说明

## 覆盖范围

本测试覆盖个性化学习产品中的动态闭环能力：

- 学习画像随学习过程更新
- 学习路径根据进度和评估结果动态调整
- 资源生成结果可进入后续推荐与评估
- 智能辅导记录可作为下一轮补强依据
- 学习效果评估可反向更新画像、路径和资源推送策略

当前实现采用本机持久化的“学习闭环上下文”，由用户把关键生成结果摘要写回 STUDY 面板字段，再驱动下一次生成。

## 自动化测试

在 `web/` 目录执行：

```powershell
npm.cmd run test:study-store
npm.cmd run test:chat-ux
npm.cmd run build
```

通过标准：

- `test:study-store` 通过，确认闭环字段可以规范化、保存、读取、清空和格式化。
- `test:chat-ux` 通过，确认：
  - STUDY 面板暴露当前阶段、资源记录、辅导记录、评估结论、下一轮调整字段。
  - 学习路径提示词会读取学习闭环上下文、最近评估结论和下一轮调整建议。
  - 学习路径、资源包、辅导、评估提示词都会输出“建议写回学习上下文的字段摘要”。
- `build` 通过，确认前端构建无错误。

## 手工闭环测试

### 1. 初始化学习上下文

在 STUDY 面板填写并保存：

```text
课程/专业方向：机器学习基础，计算机专业大二
学习目标：4 周内掌握监督学习并完成 sklearn 分类实验
画像摘要：Python 基础可用，线性代数一般，偏好代码示例
短板/易错点：precision、recall、F1 混淆
偏好/时间：每天 1 小时，喜欢图示和实操项目
当前阶段：第 1 周，监督学习和模型评估入门
```

点击“保存上下文”。

### 2. 生成路径

点击“生成学习路径”。

预期结果：

- 回复使用已保存的课程、目标、短板和当前阶段。
- 输出动态调整建议。
- 最后包含“建议写回学习上下文的字段摘要”。

将回复中的阶段摘要复制回“当前阶段”或“下一轮调整”字段。

### 3. 生成资源并写回

点击“生成资源包”。

预期结果：

- 回复生成至少 5 类资源。
- 输出建议写回字段，例如资源记录、当前阶段、下一轮调整。

将资源摘要写入：

```text
资源记录：已生成逻辑回归讲解、分层练习、sklearn 二分类实验
```

### 4. 记录辅导问题

点击“智能辅导答疑”，输入：

```text
我还是分不清 precision、recall 和 F1，尤其不知道什么时候优先看 recall。
```

预期结果：

- 回复基于已保存的短板和资源记录。
- 给出图解/导图大纲和练习巩固。
- 最后给出建议写回字段摘要。

将未解决点写入：

```text
辅导记录：precision/recall/F1 已讲解，仍需用混淆矩阵和阈值调节实验巩固
```

### 5. 评估并调整

填写练习/反馈：

```text
基础题 8/10，进阶题 5/8，应用题 1/2。代码实验能跑通，但阈值变化对 precision/recall 的影响仍不稳定。
```

点击“学习效果评估”。

预期结果：

- 至少覆盖 6 个评估维度。
- 根据练习/反馈、辅导记录和资源记录给出证据来源。
- 输出画像更新、路径调整、资源推送策略和下次复测方案。
- 最后给出建议写回学习上下文的字段摘要。

将评估摘要写入：

```text
评估结论：基础概念基本达标，模型评估指标和应用题偏弱
下一轮调整：追加混淆矩阵题、阈值调节实验和 F1/recall 对比案例
```

### 6. 再次生成路径验证闭环

再次点击“生成学习路径”。

预期结果：

- 新路径应优先响应“评估结论”和“下一轮调整”。
- 不应重复安排已经完成且已达标的基础任务。
- 应追加针对模型评估指标和应用题的补强任务。

## 边界测试

- 缺少评估结论时：系统应基于已有练习/反馈设计复测任务，而不是假设已掌握。
- 缺少资源记录时：资源推送策略应先补资源，不应声称已使用某资源。
- 下一轮调整为空时：学习路径应根据评估结果生成调整建议。
- 用户写入相互矛盾的信息时：输出应标注冲突并要求确认。
- 用户只填写“当前阶段”但无课程目标时：应先追问目标和课程范围。

## 当前限制

- 闭环写回目前由用户手动完成，系统不会自动解析模型回复并写入字段。
- 学习闭环数据保存在本机 `localStorage`，不是跨设备同步数据。
- 评估结论依赖用户提供的练习、反馈和资源使用情况；没有数据时只能生成复测方案。
