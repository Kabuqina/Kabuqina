# 生成式AI备案 & 算法备案 操作手册（双备案流程）

> 配套：`docs/superpowers/plans/2026-08-14-v0.6.0-compliance-launch-plan.md` §6　·　更新：2026-08-14
> 口径提醒：**属地差异大**（北京/上海/广东严，其他省份相对宽松），以下为通行流程，材料以属地网信办最新要求为准。

## 1. 两个备案是什么关系

| | **算法备案** | **生成式AI服务备案**（大模型上线备案 / 登记） |
|---|---|---|
| 备的是什么 | **算法**（深度合成—文本生成类） | **服务**（我们面向用户的 app 产品） |
| 法律依据 | 《深度合成规定》《算法推荐规定》《生成式AI办法》§17 | 《生成式AI办法》§17 |
| 办理系统 | **beian.cac.gov.cn**（在线系统） | **属地网信办**（区→市→省→中央，线下材料+现场测试） |
| 编号 | 网信算备 XXXXXXXXXXX 号 | 网信办公示的备案/登记编号 |
| 核心材料 | 算法安全自评估报告、算法信息表（机理/场景/数据） | 上线备案表、安全评估报告、关键词库、测试题集、测试账号、等保报告 |
| 实务周期 | 1–4 个月（含修改） | **备案 6–8 个月 / 登记 3–4 个月** |
| 商店要求 | 编号或「审批中」截图（小米/华为硬条件） | 备案/登记证明（AI 应用上架核验） |

**关系**：两个独立事项、两个系统、两个编号，材料有部分共用（安全评估报告、关键词库），
**没有强制的先后顺序**——实务建议两条线同时走：算法备案尽早提交（商店接受审批中截图），
生成式AI备案的**面谈最先约**（周期最长，是上架关键路径）。

## 2. 算法备案流程（beian.cac.gov.cn）

| 步骤 | 内容 | 要点 |
|---|---|---|
| 0 主体 | 营业执照、法人证件、对公账户 | 与 APP 备案同一主体 |
| 1 注册 | 企业账号 + 实名认证（法人人脸 / 对公打款验证） | 1–2 周 |
| 2 定条目 | 深度合成 → **文本生成类**（智能对话/学习辅导）1 条 | 后续加语音/图像生成再逐类增加 |
| 3 填报 | 算法名称、类型、应用场景、机理说明、数据说明 | 名称与产品对应（如「卡布奇娜学习辅导文本生成算法」）；**机理写：第三方已备案大模型 API + 自研提示词/学习管线**，附对方备案编号 |
| 4 自评估 | 算法安全自评估报告（网信办模板） | 风险识别、防护措施（过滤/拒答/人工审核）、数据安全 |
| 5 提交 | 属地网信办初审 → 中央网信办复核 | 官方时限 10 个工作日受理后，实务 1–4 个月（常见修改返工） |
| 6 公示 | 编号公示于 beian.cac.gov.cn | **截图存档**——商店可先用「审批中」截图 |

后续：**换模型供应商、算法场景重大变化 → 10 个工作日内变更备案**。

## 3. 生成式AI服务备案流程

### Phase 0：预约属地网信办面谈（第一周）

**广东口径（有利）**：自研/深度微调 → 大模型备案（国家网信办）；**调用第三方 API 的轻量应用 → 大模型登记（省级网信部门受理）**。我们的形态（DeepSeek API + 应用层开发）大概率走登记，面谈确认。

| **广东省网信办**（正式备案归口，省级初审） | 备案咨询电话 **020-87100795**（来电需报备案主体基本信息）；地址：广州市越秀区东风中路 305 号 | 约**现场预测试（面谈）**、领备案材料 |

**现场预测试（面谈）准备**：
- 参加人员 **2–3 人**：产品经理 + 合规人员 + 算法/技术人员
- 演示材料（简单 PPT + 产品演示）：公司情况、模型基本情况（**第三方 API 调用，非自训练**）、语料来源（无）、安全机制（输入输出过滤 / 敏感问题拒答 / 人工审核 / 内容标识）
- **预测试通过后网信办才发放备案材料**（申请表等），再进入正式材料准备

- 面谈准备：产品端到端演示（注册 → 对话 → 拍照批改）、模型来源说明（DeepSeek 合作协议+备案号）、安全机制说明（过滤/拒答/人工审核/内容标识）、产品定位（学习工具，非培训）；
- **产出：网信办判定走「备案」还是「登记」路径 + 发放《上线备案表》模板**。这一步决定后续全部工作量与排期。

### Phase 1：材料包（面谈后并行准备，约 2–3 个月）
| # | 材料 | 硬指标 / 要点 |
|---|---|---|
| 1 | **上线备案表** | 官方模板，盖章 + 法定代表人签字 |
| 2 | **安全评估报告（30–100 页）** | 可自评或委托测评机构；**敏感问题拒答率 ≥95%、人工审核率 ≥10%**——需实测数据支撑 |
| 3 | **拦截关键词库** | ≥1 万词（北京口径 20–50 万），覆盖 17 类风险，附每月更新机制说明；可采购或自建 |
| 4 | **测试题集** | 生成内容题 ≥2000、拒答题 ≥500、非拒答题 ≥500，覆盖 31 类风险场景 |
| 5 | **模型服务协议** | = 用户协议 + 隐私政策，含禁止事项、投诉机制（**7 个工作日反馈**） |
| 6 | 第三方模型材料 | 与模型厂商（DeepSeek 等）的**合作协议 + 对方算法备案编号**（我们是 API 调用方，无需语料/训练材料） |
| 7 | **等保测评报告** | 二级起步、三级常见；需先定级再测评（2–3 个月，与材料联动） |
| 8 | **测试账号** | 三套：普通 / 附加安全审核 / **无限制（最高权限）**——需要后端已就位 |

### Phase 2：提交 → 逐级审核
```
区级承办 → 市级初审 → 省级复审（专家评审会，多对一答辩）→ 中央网信办终审（六部委征求意见）
```
- **4–6 轮反馈修改常见**，每轮 1–2 周；
- 全程：备案 6–8 个月，登记 3–4 个月。

### Phase 3：公示与常态
- 备案号公示 → 写入 App 与商店材料（与 APP 备案号并存）；
- 之后**每月配合常态化安全测试**；服务重大变更走变更备案。

## 4. 并行时间线（与 0.6.0 开发线对齐）

| 节点 | 动作 |
|---|---|
| **W1（立项首周）** | 预约网信办面谈；算法备案系统注册；找 DeepSeek 要协议+备案证明；测评机构/代办询价 |
| W2–4 | 面谈演示 → 定备案/登记路径 → 领表；**算法备案提交** |
| M2–3 | 安全评估报告撰写；等保定级+测评启动；关键词库+测试题集完成；用户协议/隐私政策定稿 |
| M3–4 | 生成式AI备案材料提交（需后端就位供测试账号） |
| M4–9 | 逐级审核 + 修改返工 |
| M9+ | 公示；上架材料齐备（与 M7 gate 衔接） |

## 6. 常见驳回点（写材料时对照）

- 安全评估报告**缺实测数据**（拒答率/人工审核率指标不达标）
- 关键词库数量不足 / 17 类覆盖不全
- 测试题集不达标（数量或场景覆盖）
- 隐私政策**缺投诉机制**（未写明 7 个工作日反馈）
- 模型来源说明不清（协议、对方备案编号缺失）
- 人工审核兜底机制描述空洞（≥10% 审核率需可验证）

## 7. 其他注意

- **备案名称 = 产品名**，与商店上架名、APP 备案名保持一致（三处联动，改名成本高）；
- 备案用测试环境即可、不必正式上线，但**测试账号需要后端可用**（0.6.0 M1–M2 之后）；
- 两个备案的材料可互相引用：安全评估报告、关键词库、用户协议三件套一起写，避免两份口径不一；
- 全部材料盖章纸质+电子双份，建独立目录归档（备案过程中反复补正是常态）。
