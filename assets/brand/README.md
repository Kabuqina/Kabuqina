Since 2026-07-11 (decision A-R1b, see DECISIONS.md) the Kabuqina artwork
pipeline is split in two:

| Where | What | Access |
| ----- | ---- | ------ |
| **`Kabuqina/kabuqina-mascot`** (private repo) | Authoritative masters + generator scripts (`masters/`) and the ready-to-inject real asset tree (`overlay/`) | Owner only |
| **This repository** | Neutral greyscale **placeholder** assets under the same filenames, so any clone builds and runs unbranded | Public |

The real artwork that shipped before this split remains in git history and in
the dual-marked inline files below; it is proprietary wherever it appears
(NOTICE's `LicenseRef-Kabuqina-Brand` coverage follows the artwork as a work,
not a directory). New brand artwork — including all v0.5 desk-scene assets —
is authored **only** in the private repository.

## Placeholder assets (this repo)

Generated by [placeholder/generate_placeholder.py](./placeholder/generate_placeholder.py)
(Apache-2.0, deliberately generic geometry/palette — a plain grey mug and an
"N" tile). It writes every brand filename the app consumes:

- `web/public/kabuqina_mascot.svg` + `kabuqina_mascot_{64,128,256,512}.png`
- `web/public/kabuqina_na_{16,32,48,128,256}.png` + `kabuqina_na.ico`
- `web/public/kabuqina_coaster_{hero,pill}.svg`,
  `kabuqina_{hero,pill}_scene.svg`, `kabuqina_boot.svg`,
  `kabuqina_social_preview.svg`
- `tauri/icons/_icon-1024.png` (source for `cargo tauri icon`)

Every placeholder SVG carries a `<title>Placeholder …` sentinel; build
tooling uses it to tell placeholder from branded trees. To regenerate:

```powershell
py assets/brand/placeholder/generate_placeholder.py
cd tauri; cargo tauri icon icons/_icon-1024.png
Copy-Item -Force ..\web\public\kabuqina_na_32.png .\icons\tray.png
```

## Official branded build (owner)

Real assets are injected into the working tree only, never committed:

```powershell
$env:KABUQINA_BRAND_DIR = "D:\project\kabuqina-mascot"   # private checkout
.\scripts\apply-brand-overlay.ps1 -Apply                  # placeholder -> real
cd web; npm run build; cd ..\tauri; cargo tauri build; cd ..
.\scripts\package-portable-windows.ps1 -ExpectBranded     # sentinel-checked
.\scripts\apply-brand-overlay.ps1 -Restore                # back to placeholders
```

`apply-brand-overlay.ps1 -Check` fails whenever `web/public` or
`tauri/icons` differ from HEAD — run it before committing if unsure.
A default (no `-ExpectBranded`) packaging run refuses a branded tree, so the
two modes cannot be mixed up silently.

## Inline copies in code (dual-marked)

The pre-split mascot artwork also exists as **inline vector/CSS renderings
inside source files**. Those files carry the dual SPDX expression
`Apache-2.0 AND LicenseRef-Kabuqina-Brand`: the component CODE is
Apache-2.0, the embedded ARTWORK (geometry, palette, composition) is
proprietary under [LICENSE](./LICENSE). Current set:

| File | Embedded artwork |
| ---- | ---------------- |
| `web/src/components/brand/CompanionCupSvg.tsx` | Cup vector |
| `web/src/components/brand/KabuqinaCoasterSvg.tsx` | Coaster vector |
| `web/src/components/brand/KabuqinaSceneSvg.tsx` | Scene composite |
| `web/src/components/brand/kabuqinaBrandTokens.ts` | Palette + geometry tokens |
| `web/src/components/CompanionCup.tsx` | CSS-rendered cup |
| `web/src/components/CompanionPillScene.tsx` | Pill scene composition |
| `web/src/index.css` (`.kq-companion-cup*` block) | CSS mascot rules (banner comment marks the block) |

**Rule going forward:** any new file embedding brand artwork MUST carry the
`LicenseRef-Kabuqina-Brand` SPDX marker — but prefer not to embed at all:
new artwork ships as overlay files from the private repo.
